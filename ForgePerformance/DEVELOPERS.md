# ForgePerformance developer notes

ForgePerformance is a standalone load-shedding plugin. It depends only on BepInExPack_GTFO and GTFO_API, not on any Forge package, and exposes no public interface; third parties have no reason to depend on it. Everything it needs is in this package. Players should read `README.md`.

## Build and offline check

```
dotnet build Mods/ForgePerformance/ForgePerformance.csproj -c Release --artifacts-path artifacts/dotnet -p:GTFOBepInExPath=<QA profile>/BepInEx -warnaserror
```

The P4 offline gate runs from the repository root:

```
python -B Mods/verify.py ForgePerformance --game <GTFO directory> --dump <same version dump.cs> --work-dir artifacts/work/p4-perf/verify
```

It runs four groups: configuration and off routing, the written log, native layout, and the shedding binaries. A missing native input keeps an incomplete record and fails the full gate; a skip is never a pass. Run the layout group alone with the `ForgePerformance:LoadShedding native layout` selector. Nothing here starts the game.

At startup the plugin reads the native module fingerprint (`LoadShedding/NativeModuleFingerprint.cs`); all other implementation is in this package. The SHA-256 of `GameAssembly.dll` and of `globalgamemanagers.assets` (the decoration shader check) goes through `LoadShedding/FileHashCache.cs`, which keeps it in `BepInEx/cache/ForgePerformance/file-sha256.txt` keyed by full path, length, last write time and creation time: an unchanged file is not read again, while a missing, unreadable or malformed cache or any other key reads and hashes the file, and the result is compared with the expected hash every launch.

## Settings

Everything is under `[Performance]` in `BepInEx/config/NAinfini.ForgePerformance.cfg` and is read once, when the plugin loads. The source of truth for keys, ranges and descriptions is `LoadShedding/SheddingConfiguration.cs` and `LoadShedding/SheddingSettings.cs`.

All cut switches default to `true` except `MeleePacketReuse`, the enemy-crowd options that change play (`ClientHiddenSyncThrottle`, `UpdateBudgets`, `AvoidanceQuality`, `HitReactKeepsAgent`) and `Probe`. `SummaryLog` defaults to `false`. Numeric defaults:

| Setting | Default |
| --- | ---: |
| `CorpseLifetime` | 0.01 s |
| `RagdollLimit` | 4 |
| `WindLimit` | 1 |
| `ParticleFactor` | 0.01 |
| `ParticleHz` | 1 |
| `ShellLimit` | 6 |
| `DroppedMagazineSeconds` | 3 s |
| `DecalLimit` | 1 |
| `DecalLifetime` | 0.01 s |
| `CullDistance` | 10 m |
| `LightLimit` | 12 |
| `CorpseRecycleSeconds` | 1 s |
| `ClosedDoorDepth` | 2 |
| `ShadowDistanceFactor` | 0.65 |

A cut that is off installs none of its own hooks and does no per-frame work for itself; shared entry points stay only for the cuts still on. With every cut off, the plugin creates no shedding controller or update component. `WindCapacityProtection` and `WindNearest` both off means the three wind hooks are not installed and the wind lifecycle is not subscribed.

`ShadowDistance` and `SoftParticlesOff` differ from the game's own video options: `ShadowDistance` shortens the value the game already set by `ShadowDistanceFactor` (never below 20 m and never farther than the game's value), and `SoftParticlesOff` turns off only soft particle blending. Both are written when a level starts and restored when it ends. `TextureStreamingOff` installs no hook and does no per-frame work: at level start and at build completion it reads `Texture.streamingTextureCount` and turns `QualitySettings.streamingMipmapsActive` off only when that count is 0; it writes the original and written values to a `load_shedding` line at level end.

`ClosedDoorDepthLimit` is applied at the game's one visibility entry, `C_Camera.RunVisibilityOnPreCull` (called from `FPSCamera.OnPreCull`; its `PropagateFrustra` is a breadth-first walk over open `C_Portal`s). A prefix works out which portals this pass must close from the camera's current cull node and writes `C_Portal.<IsOpen>k__BackingField` (offset 0x128, checked against the layout when installed) to 0; a finalizer writes the real value back, including on an exception, so no other reader sees the changed value outside the visibility call. The camera's node with no closed door in the way is layer 0, the first node behind a closed door is layer 1, and every open portal adds a layer; only portals between `ClosedDoorDepth` layers and the next are closed. Door state is not patched: after the level is built, `AIG_CourseNode.s_allNodes` gives every portal's `m_cullPortal` and `m_door`, and the plugin subscribes to the door sync's `LG_Door_Sync.OnDoorStateChange` and the weak door animation's `OnDoorIsClosed`; it unsubscribes at level exit. The set is recomputed only when the camera's cull node or a door state changes (the node and portal graph and every buffer are built once at level build, so a recompute allocates nothing); each frame is two pointer reads, one comparison and one write and restore per closed portal. A door that was damaged or destroyed, a door without a sync component, or one portal shared by two doors stays vanilla. Level exit writes `item=closed-door-depth`: seen (doors managed), changed (visibility passes that closed a portal), layers, doors without a sync component, shared portals, doors released because they were damaged or destroyed, nodes, portals, recomputes, total and maximum portals closed in one pass, and failures.

`RagdollNodeRefresh` reuses the `ES_Dead.SetRagdollEnabled` patch that `RagdollCap` installs (neither is installed when both are off). It refreshes only when the call was a ragdoll before and has stopped after: it calls the game's own `C_MovingCuller.RefreshNode` once, so a body thrown across a room boundary is looked up in the room where it actually lies instead of vanishing with its old room. Level exit writes `load_shedding` `ragdoll-node-refresh` with seen (ragdolls stopped) and changed (refreshed).

## Wind, decoration and culling

The wind capacity protection covers loading, the level and level exit, independently of the visual controller, with the native fixed capacity of 64; `WindNearest` / `WindLimit` control only the optional visual reduction. The native update reads a reusable small set and a finalizer restores the original set reference, instead of removing and adding n-1 originals each call. The original set is always kept; enable/disable events are mirrored into the set as it was before the call, and a world switch never inserts old objects into the new world. Membership is maintained by pointer index with a last-item swap; a registered member that is enabled and disabled repeatedly reuses its Transform wrapper. The first registration of a new Transform creates a wrapper and keeps it until level exit or unload; first fill, set replacement and growth beyond the reserved capacity are cold paths, with an initial 4096 workspace that doubles as needed. The first choice scans everything; after that, including frequent enable/disable, at most 64 candidate positions are read per call, and the small set is not rebuilt while the nearest choice did not change. Distance culling walks only the registered candidates and the already hidden entries per camera; the shadow filter caches positions to remove by the native list's version, count and candidate set, and repeats the scan when any changes, with no cache across nested calls; corpses are queued by expiry and only the earliest is read per frame, still subject to the per-frame checks and the renderer budget.

A camera cache is built only for a call that exceeds capacity, and every use checks the camera, the underlying camera and the Transform for liveness and instance identity. The set's static field, the camera's fields and the native Transform return values are read as pointers; the steady-state identity check does not call the three QA interop getters that create new wrappers. Only the first use or a replacement creates wrappers; a member entry keeps a strong managed reference to the affector and Transform, and the set and camera cache keep their wrappers. An invalid camera refuses the update and is removed from the cache; replacement or pointer reuse rebuilds the selection; level exit and unload clear the cache. After a move, the nearest choice is refreshed by full scan rounds, so with n > 64 it takes ceil(n/64) calls and may show a small visual delay; each camera chooses independently, and equal distances sort by stable identity. Offline checks show 0 B on the prewarmed CLR stand-in path and no wrapper-creation call, and compare the production IL with the QA getters; whether the real IL2CPP hot path is 0 B can only be measured in game, and neither the cold-path cost nor the CPU gain has been measured.

The two IRF switches call a hook once per decoration per frame: a switch that is off installs no hook, and an installed hook reads one static Boolean first. The main camera and frustum are read once per frame, and the decoration's fields are read directly at checked offsets without creating wrappers. `IrfWorldCameraOnly` draws instanced decoration only into `Camera.main`; `IrfOffscreenSkip` skips the per-frame dispatch, count copy and draw of static instanced decoration whose fixed bounds are fully outside the main camera frustum. Dynamic transforms, decoration parented to an enemy, one that has not had its first transform update, or one whose bounds move with the object are never skipped; the frustum test is expanded by 1 m plus 20% of the distance to cover a camera that moves after the decoration's update. Off-screen plants stop swaying and their shadows use the last computed instances. A level exit writes one `load_shedding` line for each of `MeleePacketReuse`, `IrfWorldCameraOnly` and `IrfOffscreenSkip` that is on.

Decoration classification uses native types and a component whitelist; an unknown object stays vanilla. A rotating decoration must have its own draw group holding only its own subtree, no collider, gameplay or unknown script; the distance hide allows only checked game assets, a known additive shader with a single pass and no depth write, and a unique runtime identity; other materials stay vanilla. Animation must have no root motion, events, state scripts or external animation binding. Lights consider only ordinary static ambient decoration spotlights and exclude the flashlight, controllers, objectives and environment-event light references; when a reference cannot be read completely, vanilla stays. Decals check both the hit-effect source and a separate decal component; scan rings, glue, target marks and generic decals are not treated as combat decals.

Level build starts the opening setup when the elevator is waiting to stop (`ReadyToStopElevatorRide`, before landing), one scene-wide search per block in a queue with at most 12 ms per frame (2 ms after entering the level), never finished on the landing frame; blocks not reached yet stay vanilla. New decoration is scanned once in this round; an object that appears later and is not confirmed stays vanilla. Hit decals are registered at the actual play and pool-return entries. These changes affect only this machine's presentation and send no multiplayer state; corpse collision, the native cleanup coroutine and the multiplayer lifecycle are kept.

## Other cuts

`LeakCleanup` destroys or releases what the game forgets after a level: empty text assets, effect point lights, instanced-render buffers, flyer materials, terminal build-done callbacks, queued objective hint messages, and duplicate menu header entries left by a scrolling window resetting its header. Nothing visible changes. Its instanced-render buffers are destroyed only in the level-exit teardown, never for in-level features, including ones on enemies, that share a buffer.

`DecayCleanup` clears a corpse's dissolve particles about five seconds after they finish; the corpse is already invisible and a corpse that is dissolving again is skipped. `DebrisFreeze` freezes breakable debris three to five seconds after it lands (rechecking each second while it still moves, at most three times), turning off collision and making it static until the object breaks again. `GlueSoundRecycle` returns a destroyed foam ball's audio source to the pool; only the audio object is recycled. `StackTraceTrim` stops Unity writing stack traces for ordinary log and warning lines; errors and exceptions keep theirs. `GuiMirrorOff` removes the interface's mirror and reflection effect. `LowQualitySpitter` blurs the infection spitter's texture and removes its ground decal; its texture offset is restored at level exit, and a decal already destroyed is not restored. `CombatDecals` has no `Decal.Shown` hook: the game only hides a decal on pool return, and the pool-return entry already handles it.

`DroppedMagazineCleanup` gives a reload's dropped magazine back to its gun's pool `DroppedMagazineSeconds` after it drops. In the game, `BulletWeapon.InitializeMagDropPool` makes each gun that has a magazine part (`GearPartHolder.m_aMag`; a gun without one, such as the Buckland s870 shotgun, has no pool and never drops) a pool of five magazine copies (`ObjectPooler.InitializePool(copy, 5, dynamic false, allowStealing true)`, `m_magDropPool`); the reload sequence (`ItemEquippable.PerformWeaponAnimationAction`, reached from `PlayerInventoryLocal.TriggerReload` and, for other players, `PlayerInventorySynced.SyncGenericInteract`) calls `BulletWeapon.DropMagazine`, which sets `m_magDropTimer` when the gun has that part and its check `m_clip <= 1` passes (it passes on an ordinary reload: in the game three reloads with 30 to 34 rounds left dropped one magazine each), and `BulletWeapon.FixedUpdate` two physics steps later takes a copy with `ObjectPooler.Pool.Get(Vector3, Quaternion, bool)`. The game never returns a copy: once five lie on the floor the oldest is taken again. That `Get` overload has no other caller in the game, so a postfix on it registers each drop (pool, copy, a generation per copy) in a fixed-size due queue that the 0.25 s extras tick drains; no scene scan and no per-frame work. At the due time a copy that the pool has not handed out again since and that is still in the pool's used list goes back through the game's own `Pool.Return` (off the used list, onto the free list, under the pool container, inactive), so the pool stays whole. The drop is local presentation on every machine; nothing is sent. The hooked entry starts `mov [rsp+8],rbx; mov [rsp+0x10],rbp` (two 5-byte moves), so the 6 bytes the detour writes cover whole register moves only. Level exit writes `load_shedding` `dropped-magazine` with seen (drops), changed (returned to the pool), the configured seconds, copies handed out again before their time and queue overflows.

`SpentFogRepellerCleanup` stops drawing this machine's copy of a thrown fog repeller once its effect has ended. A thrown repeller is a replicated item (`FogRepellerInstance : Item`) whose `Start` calls `FogRepeller_Sphere.StartRepelling`; each machine runs the sphere's state machine (Initialize, Grow, Life, Shrink) on its own copy, and at the end of Shrink `FogRepeller_Sphere.Update` calls `KillRepellerFunction` (returns the fog sphere, unregisters the infection volume, posts the switch-off sound) and `ChangeState(Disabled)`. Nothing restarts a thrown sphere, it has no pickup, and the game never removes the item: the model stays. The plugin patches `FogRepeller_Sphere.ChangeState` (a prefix keeps the old state, the postfix acts only on a change into `Disabled`), keeps only spheres that are the `m_repellerSphere` of a `FogRepellerInstance` (the large carried repeller, `HeavyFogRepellerGlobalState`, uses the same sphere and is left alone), and right then sets `Renderer.forceRenderingOff` on every renderer under the item (inactive children included). Nothing else is touched: the object stays active, its colliders and rigidbody stay as the game left them, the sound player keeps playing the switch-off sound (so there is no wait), the replicator and item stay registered, and each renderer's `enabled` flag keeps the game's value, so a late joiner's spawn, a checkpoint, a host change, `Item.OnDespawn` and level cleanup meet the same object as in the game. `forceRenderingOff` is a draw switch separate from `enabled`; in the game only `RendererCullingExtensions.CullShow` (culling buckets and clusters, with `CullHide`) and a few systems for their own renderers (FPS renderer, indirect batcher, `Decay`, flyer animation) write it, and the item culler is created only by the pickup cores' `Setup` (`ConsumablePickup_Core`, `ResourcePackPickup`, `GenericSmallPickupItem_Core`, `KeyItemPickup_Core`, `CarryItemPickup_Core`), never for a thrown `FogRepellerInstance`. The repeller's light is already off: `KillRepellerFunction` disables `m_light`. Each machine acts on its own copy's end with its own setting; nothing is sent. Used glow sticks need no cut: in `GlowstickInstance.Update` the fade states end in `Done`, where the host already calls the replicator's `Despawn`. The hooked entry starts `mov [rsp+8],rbx; mov [rsp+0x10],rsi` (two 5-byte moves). Level exit writes `load_shedding` `spent-fog-repeller` with seen (thrown repellers that ended), changed (repellers hidden) and `renderers_hidden`.

`MeleePacketReuse` (off by default) makes every first-person melee weapon of this machine share one network hit packet. The packet is addressed by replicator number and position in the replicator, so the plugin does not remove a position: after setup it points the new packet's position at the session's first packet, and the weapon uses that one, so the replicator's length and order stay exactly vanilla and later registrations (revive state, communication menu) keep their positions. The wire numbers are the vanilla ones, so a lobby with players without the option, without the mod or with another version does not go out of range; the gain is a few small objects less per melee setup, the frame-rate gain is unmeasured, and multiplayer is unverified, which is why it is off.

## Logging

The default log writes errors only. With `[Performance] SummaryLog` true, the session start writes one `type=performance_setting` line per effective setting. Level exit and a normal shutdown write one `type=load_shedding` line per cut and per decoration class, separating changed, unchanged, restored, skipped draws, recycled and native-lifecycle takeovers. There is no per-frame logging. `TentacleLimitErrorFold` writes `type=load_shedding_folded_error code=perf.tentacle-limit-reached state=first` when it holds back the first tentacle-limit error of a level and `state=level-total` with the count when the level ends (a normal quit ends the level first; a killed or crashed session keeps the first line).

The real effective range, the picture and multiplayer behaviour have not been verified.

## Enemy crowds

`Crowd/CrowdLoad.cs` keeps a registry of living enemies, filled by a postfix on `EnemyAgent.Setup` (the corpse hook's class, installed when any crowd option or the probe is on) and emptied at `ES_Dead.CommonEnter`, when the enemy is gone, and at level end. A second `Setup` of the same enemy first releases the earlier entry. The plugin's update runs it: `FarAnimatorThrottle` steps throttled animators every frame (`Animator.enabled = false`, then `Animator.Update(missed time)` every `FarAnimatorInterval` frames, staggered; an enemy that leaves `ES_PathMove` or turns on root motion is given back the same frame); everything else runs four times a second. No option touches a living enemy's shadows (players read invisible enemies by them). `FarSkinQuality` sets `SkinQuality.Bone2` and `skinnedMotionVectors = false`. Each change remembers the game's value and puts it back when the option goes off, the enemy dies or the level ends.

The host-only globals are written only when their option, the host or the level changes: `UpdateBudgets` writes `SteppedUpdateGroup.m_maxUpdateCountPerFrame` of the 16 groups of `EnemyUpdateManager.Current` in `EnemyUpdateManager.Setup`'s order (close, near, far of behaviour, detection, network, locomotion and fixed locomotion, then the node group); `AvoidanceQuality` writes `EnemyAI.s_defaultAvoidanceType`, which `EnemyAI.SetNavMeshAgent(true)` applies, and gives the new type to every registered enemy whose agent is on with the old default type (an agent switched on before the change would otherwise keep it until its next switch-on); `PathfindingIterations` writes `NavMesh.pathfindingIterationsPerFrame`. The game's values, read in game: budgets `5,2,1 10,4,1 12,3,1 20,10,5 5,2,1 1`, avoidance 1 (low quality), pathfinding 100; the defaults equal them.

`Crowd/CrowdPatches.cs` holds the Harmony patches the probe times and the two options that act inside a game method: `ClientHiddenSyncThrottle` skips `EnemyTransformSync.Update` for an enemy the crowd tick listed (client, `C_MovingCuller.IsShown` false, farther than `HiddenSyncDistance`) except one frame in `HiddenSyncInterval`, staggered by its pointer; `HitReactKeepsAgent` counts depth inside `ES_Hitreact.Enter` (prefix and finalizer) and, for the `SetNavMeshAgent(false)` it makes, leaves the agent on with `isStopped`, `updatePosition = false` and no avoidance, then clears `isStopped` before the game's own next `SetNavMeshAgent(true)`. A patch is installed only when the probe is on or its option is configured on. None of these methods is patched by another Forge package (ForgeReplay patches `PropagateTargetLimited`, so the probe times `DoHibernateWakeupPropagation` instead; ForgeEngine patches `ES_Hitreact.CanHitreact`, ForgeCore `DoHitReact`).

ForgePerformance loads without ForgeCore, so `Crowd/EntryAdmission.cs` checks the entry of every method this mod patches (the load-shedding, wind and crowd patches and the probe's timed methods) before the detour is written, by ForgeCore's HookPrologue rule: `GameAssembly.dll` is the supported build; every instruction of the file image starting inside the 6 bytes the detour writes (`FF 25 rel32`) is a plain integer instruction the backend relocates, or the tail jump of a thunk followed by its `0xCC` padding (`C_Camera.RunVisibilityOnPreCull`, `Decay.Initialize`); and the entry's live bytes equal the file image, or differ only inside those 6 bytes on a method Harmony already patched (its own detour, as on `EnemyAgent.Setup` and `OnDestroy` when ForgeCore loaded first). The rule is read from the file image, so it also holds for an entry that already carries a detour. After patching it compares the entry with the file image and takes its patches off when more than 6 bytes differ. The shared-body look-up in the running game walks every method of every loaded class once, so only the crowd and probe patches use it (as before); for the load-shedding and wind patches, which default settings install, shared bodies are checked offline by `Tools/Forge/check-patch-bodies.py`, which reads their `[HarmonyPatch]` targets and fails a target on a shared body unless it lists it (`Decay.Initialize`, whose `SkinnedMeshRenderer` and `MeshRenderer` overloads are one body; `DecayCleanup`'s postfix takes a `Decay` either way). A refused or failed target writes `type=perf_native_hook state=refused|failed code=native-hook-prologue-refused target=… reason=…` once. A crowd or probe patch that is refused is left out alone; the load-shedding patches and the three wind patches each stand together, so one refused entry there stops that install with an exception and takes off what was already put on (no cut runs on half its hooks). The probe does not patch `EnemyAllocator.SpawnEnemy` (ForgeEngine's method); a spawn shows as `EnemySpawned` and `OwnSetupPrefix`.

## Probe

`[Performance] Probe` (off) starts `Crowd/Probe.cs`: one `type=perf_probe` line per `ProbeSeconds` window in `BepInEx/PerformanceLogs/ForgePerformance_<utc>.log` (the newest 10 kept) with the label, host, switches, frames, frame time (average, p50, p95, worst, from the plugin's `Update`), main and render thread CPU time per frame (`GetThreadTimes`; the render thread is the one named `UnityGfxDeviceWorker`), gen-0 collections, IL2CPP heap, the registry gauges and per probed point its calls, most calls in one frame, total and worst milliseconds. A label or switch change closes the open window first. The hot path is a timestamp and three array writes; nothing allocates or looks up a name. Points: `EnemyAllocator.OnEnemySpawned`, this mod's own `Setup` prefix, ragdoll start, enemy destroy (counted when `LeakCleanup` is on), `DoHibernateWakeupPropagation`, `AIG_CourseGraph.GetReachableEnemiesInNodes` (with enemies returned), `SetNavMeshAgent` on and off, kept agents, `C_Light.UpdateVisible`, `CL_ShadowGenerator.ProcessUpdates`, `EnemyTransformSync.Update` and its skips, `Dam_SyncedDamageBase.Update`, `ProjectileTargeting.Update` and `ProjectileManager.SpawnProjectileType`; then, to split the script phases, `GameStateManager.Update` and `FixedUpdate` (the enemy update manager runs inside them), the per-enemy `UpdateMember` of the enemy update manager's behaviour, detection, locomotion, fixed locomotion, network and node groups, `ES_PathMove.Update`, `EnemyMaterialFeeder.Update`, `C_MovingCuller.Update`, `TentacleBase.Update` and `LateUpdate`, `MovingEnemyTentacleBase.LateUpdate`, and the `LateUpdate` of `RootMotion.SolverManager` (FinalIK), `PlayerEnemyCollision`, `FPSCamera` (and its `OnPreCull`), `LocalPlayerAgent` (and its `Update`), `GPUCurvyManager`, `CL_ShadowAtlas`, `FrameRateLimiter`, `IndirectBatcherCamera`, `ControlRigLinker`, `AkInitializer` and `MapDetails`, resolved by name in their own assembly. In game the admission refuses `ES_PathMove.FixedUpdate`, `MovingEnemyTentacleBase.Update` and `PlayerLocomotion.LateUpdate` (bodies shared with other methods) and `FirstPersonItemHolder.LateUpdate` (patched by another package), so they are left out. `EnemyUpdateManager`'s own four updates are timed by ForgeDevelopment's performance log and `Mastermind.GameStateUpdate` is ForgeEngine's patch, so the probe leaves them; animator, skinning and the physics step are native phases that only ForgeDevelopment's log splits. Each timed call goes through Harmony's managed trampoline, so a per-enemy point reads a few microseconds per call higher than the game's own cost. Window and mark lines carry `utc` to line them up with ForgeDevelopment's per-second lines. A main CPU near the frame time means the main thread limits the frame; both threads well under it means the frame waits on the GPU or present.

From the ForgeDevelopment console, `call static:ForgePerformance.Crowd.PerformanceControl Set "<option>" true|false` switches an option, `Value "AvoidanceType"|"PathfindingIterationsPerFrame" <n>` sets the value its option applies (at once when the option is on), `Mark "<label>"` starts a label, `Read` answers the switches, gauges and global values, `Limits` answers `Application.runInBackground`, `QualitySettings.vSyncCount`, `Application.targetFrameRate` and whether the game window has focus (every mark line carries them too), and `Foreground` / `Background` ask Windows to give the focus to the game or to the desktop shell and answer whether it did (Windows refuses while another process holds the input). Every window line counts `foreground_frames`, the frames the game window had focus. `tools/crowd-probe.test` drives one session through sleepers, a wake-up, the awake crowd with each option alone, the defaults, everything, a second spawn burst and a shooter barrage; `tools/crowd-ab.test` alternates each option off and on in equal 8-second segments (A/B/A/B…) over a fixed sleeping and then awake crowd; `tools/crowd-focus.test` alternates foreground and background windows over an empty room and an awake crowd. `python Mods/ForgePerformance/tools/analyze_probe.py <log> [--forgedev <ForgeDevelopment log>] --output summary.md` turns the log into a table per label and, for labels named `<item>-A-<n>` / `<item>-B-<n>`, compares segment medians: each B segment against the mean of the A segments on either side, so a steady drift cancels, with ForgeDevelopment's phases for the same seconds.

The native part of the probe is `tools/NativeProbe` (CMake, one DLL, `ForgePerformance.NativeProbe.dll`); it is not in the store package and loads only when it lies beside the plugin and `Probe` is on. It samples the stacks of the main and render threads (`samples.bin`, with `modules.tsv`, `jit.tsv` and `il2cpp-methods.tsv` to name the frames), times GPU work between camera events with timestamp queries (`PerformanceControl.Capture <frames>` writes `gpu-timeline-N.csv`), times shader creation (`shaders.csv`) and the probe log gains one `type=perf_probe_hitch` line per frame of 33 ms or more. `tools/analyze_samples.py` turns the samples into per-label tables of functions and of plugins (`--mods`, `--focus <name>` for callers and callees), `tools/analyze_gpu_timeline.py` gives the median GPU milliseconds per stage, and `tools/analyze_play.py` cuts a PresentMon capture (run with `--qpc_time`) by the `type=performance_state` lines of a `SummaryLog` session or by probe marks. Its Direct3D draw counters read zero in game (the context entries it patches are not the ones the engine calls); draw counts are not available yet. `PerformanceControl.Lag` and `Animators` read back what `FarAnimatorThrottle` does: manual animator updates, how many advanced the state time and how many moved a limb, for all enemies and for those on screen. `PerformanceControl.Physics` reads the physics settings in force, the rigid bodies awake and asleep, the colliders by owner, layer, shape and body kind, the enemies shown, and one enemy's collider and body counts.

Whole-process sampling, without the probe: `tools/garden-survey.test` drops into R8A1 (every main-layer zone is the Gardens sub-complex) and stands 20 seconds in each of its two largest zones; `tools/garden-load.test` stands 60 seconds in zone 7 and then 60 seconds with 48 aggressive Strikers. `tools/record-cpu.ps1 -Out <file.etl>` records WPR's CPU profile (sampling plus context switches) for 60 seconds and needs an elevated shell. `tools/TraceReport` (`dotnet build` it, then `TraceReport <trace.etl> <Il2CppDumper dump.cs> <out.md>`) names GameAssembly frames from dump.cs's method RVAs, labels the rest of GameAssembly as il2cpp runtime, and names UnityPlayer and Windows from Unity's and Microsoft's symbol servers. It writes the top 20 functions, inclusive and exclusive, per thread group (main, `UnityGfxDeviceWorker`, job workers, other). For the main thread it adds three tables: time per player-loop phase, per script entry (the managed method Unity called) and per innermost managed method, plus CLR GC time and the plugin assemblies and methods on the main thread. `--focus <frame text>` (repeatable) prints the callers, callees and outermost plugin method of every matching frame; `--windows <tsv>` (label, UTC start, UTC end per line) splits the main-thread tables by labelled time windows, such as the hitch frames ForgeDevelopment logged. `python Mods/ForgePerformance/tools/presentmon_summary.py <PresentMon CSV> [<from ms> <to ms>]` gives frame time, CPU busy and GPU busy percentiles for a window of a PresentMon 2 capture. ForgeDevelopment's `frame_summary` rows are written after their window; split them by their `window_start`, not by the line's time stamp. RenderDoc cannot capture the modded game: launching through it keeps Doorstop from starting BepInEx.
