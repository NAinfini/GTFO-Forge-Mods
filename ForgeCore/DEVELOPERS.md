# ForgeCore developer notes

Public types are in namespace `ForgeCore`, one static entry per module; everything else is
internal. Calls are main thread unless a member says otherwise.

## Layering: what this package holds and what it does not

ForgeCore holds the base and the vanilla calls: asset-bundle loading, logging, config, object pools, network messages, input leases, local saves, and enemy queries and slowing, damage, explosions, noise, gear swapping and the special-weapon slot, borrowed-gun switching, data blocks and safe landing spots. It only covers how to call; it holds no gameplay numbers and no content. If another mod may need a vanilla call, add it here. It never depends on a higher package.

## Layout

- `Core/` references no game or Unity assembly and is compiled straight into the offline tests: logging, pools, the local store,
  network channels and lobby values (over an internal transport), the special weapon slot rules, the input lease book, the data block ledger, the module patch table and
  `NativeDataBlockTables`, the JSON data block transaction ForgeEngine and the Forge base packages register their content through.
- `Once/` is a second pure assembly (`ForgeCore.Once`) that any package, test or tool may reference or compile in without the game: `OnceReporter`, `PosixPath`, `Fnv` and `StrictJson`.
- `Native/` is the game side: the plugin and its frame driver, the GTFO-API transport, lazy patching, and the modules that call the game.
- `tests/Core/` is the offline check program (`dotnet run --project Mods/ForgeCore/tests/Core/ForgeCoreTests.csproj -c Release`).

## Modules

- **Content folders.** `ContentFolders.Find(folderName, errors)` returns the full paths of every directory named `folderName` (case-insensitive) under BepInEx `Paths.PluginPath`, sorted and distinct. The plugins tree is walked once per process into a name index (`ContentFolderIndex`), so a second mod asking does not scan the disk again; folders that could not be listed are added to `errors` on every call. It does not read MTFO.
- **Seeds, solo drop and fingerprints.** `Level.TryCurrentLevel` returns the active expedition (`RundownManager.GetActiveExpeditionData` and `Global.RundownIdToLoad`) and the three generation seeds: from `Builder.BuildSeed`, `Builder.HostIDSeedRandom.Seed` and `Builder.SessionSeedRandom.Seed` once generation began, before that from `RundownManager.ActiveExpedition.Seeds.BuildSeed` and `GetSeeds`. `SoloDrop.Start(level, seeds)` walks the main menu with the game's own calls (`CM_PageIntro.EXT_PressInject`, `CM_PageStart.EXT_PressStart`, `SNet.SessionHub.CreateHub(Private)`, `SNet.Slots.SetSlotPermission(Forbidden)`, `RundownManager.MasterSelectActiveExpedition`, `RundownManager.TrySetActiveExpedition` with the seeds, `CM_PageLoadout.OnReadyButtonClicked`, `EXT_StartExpedition`; the same flow ForgeEngine's StartupProbe uses), checks the seeds read back from the game before the drop and again against `Builder` when generation starts, and is driven from ForgeCore's frame update. `Level.Fingerprint()` hashes `Builder.CombinedCheckSum` and `ExpeditionInTierData.GetChecksum()` (the game's own) plus lines for zones, areas (geomorph name, size, gates, enemy spawn points, position in centimetres), and for every `LG_SecurityDoor` and `LG_WeakDoor`, `LG_ComputerTerminal`, `LG_ResourceContainer_Storage`, `LG_PowerGenerator_Core` and `ItemInLevel` (game object name and position in centimetres), each list sorted. Sleeping enemies are left out on purpose: the game spawns them after build done (the first frames of the level), and on R1A1 two runs with identical seeds gave the same enemy types and counts at different positions. `Level.Expeditions()` lists the enabled expeditions of the active rundowns with their official labels; `Level.TryFindLevel` resolves a label such as `R1A1`. `SoloDrop.Start(level)` without seeds lets the game draw its own. `DataBlockHashes.ByType` finds every `GameDataBlockBase<T>` subclass in the interop assemblies, reads `GetAllBlocks()` and hashes each block with `ContentHash` over its public properties (the interop wrappers expose values as properties); `ContentHash` does not walk reference types of the Il2Cpp, Unity or System assemblies (it records their type name) and reads value types by their fields only, combined in persistent-ID order.
- **Compact and ChunkLog.** `Compact` writes into a caller-owned `byte[]` at a caller-owned position: `WriteVar`/`ReadVar` (7 bits per byte, low group first, at most 10 bytes; a run past the end or a tenth byte above 1 throws `FormatException`), `WriteVarSigned` (zig-zag), `WriteDelta`/`ReadDelta`, `Quantize` (saturates out of range and on NaN) / `Dequantize`, `WriteQuaternion` (6 bytes: 2 bits for the largest component, 15 bits for each of the other three over ±1/√2, largest component kept positive, so q and −q give the same bytes; every component within 6e-5). `ChunkLog.Create(stream, formatVersion)` writes a 12-byte start (`FCLG`, container version 1, owner format version, little-endian), then per `Append(type, startMs, endMs, data)` a 28-byte header (`CHNK`, type, flags 0 stored / 1 deflate, start, end, raw length, stored length, CRC-32 over the first 24 header bytes and the payload) and the payload; `Finish()` adds the index (24 bytes per chunk) and a 20-byte trailer (`FCIX`, index offset, count, CRC-32). Data is deflated only when that is smaller. `ChunkLog.Open(stream, expectedFormatVersion)` reads the index when the trailer holds, otherwise scans headers in order and stops at the first chunk that is cut off or fails its checksum (it never skips ahead); `ChunkReader.IsComplete` tells which. Another container or format version throws `ChunkLogFormatException` naming both numbers. Every `Append` flushes the stream. One writer thread; a failed write throws and the writer is abandoned.
- **Net.** `Net.Open(modId, capacity)` opens the mod's only channel; there is no protocol number to bump. Message events are named `modId/name`.
  Every registered message adds its name, delivery and field layout (field names and types in declaration order, nested structs expanded,
  fixed buffers with their length, plus the byte size; lobby values are layout `bytes`) to the channel's format fingerprint
  (`NetChannel.Format`, FNV-1a over that text, same on every machine). The handshake event `ForgeCore/handshake/<modId>` carries that
  fingerprint and a hash of `NetChannel.Content`, so different builds meet and both sides refuse (`PeerState.Refused`, `Refused` event,
  one error each). When the formats differ the two sides exchange their per-message list (`ForgeCore/formats/<modId>`) and the error and
  the refusal reason name the messages that differ: missing there, only there, different field layout, different delivery. Registering a
  message after players answered asks them again. Nothing is computed outside registration and the handshake. Players are listed once a
  second and greeted every 2 s until they answer (at most 5 greetings, then one error saying the mod is missing there). Messages
  wait in a queue until the mod calls `Pump()`; messages from refused players are dropped and counted. How a message travels is fixed where it is
  registered: `On` takes a `NetDelivery` (default `Reliable`) and every send of that name follows it, so every player that sends a message
  registers it too (sending an unregistered name throws). `Reliable` uses `SNet_ChannelType.GameOrderCritical` and is never dropped by the queue (it does not
  count toward `capacity`): requests, answers, checkpoints, state replays. `Lossy` uses `SNet_ChannelType.GameNonCritical` (unreliable, may be lost or
  reordered) for frequent presentation messages; at most `capacity` lossy messages wait, the excess is dropped on arrival and `Pump()` reports the count
  with `ErrorOnce`. Handshakes and lobby values are reliable. `Lobby(name)` is a `NetLobbyValue`: each player `Set`s only its own bytes (null for none),
  sent as `[1]+bytes` or `[0]` on the variable-size event `modId/lobby/name` to every other player, again to each player the
  moment their copy answers the handshake (a later joiner, a reconnect, a content change), and dropped for a player who left, was refused
  or belongs to an earlier host or local player; `Changed` fires inside `Pump()`, `VersionOf` lets a reader cache by version.
  World epoch and readiness: `Epoch` is the host's world number (zero: no world). A message that carries one implements `INetEpoch` explicitly over its
  existing field (the wire layout does not change) and is registered with `OnEpoch<T>`, which drops a message of another epoch, or any message while the
  epoch is zero, before the handler runs. `EnableReadiness()` adds the message `ForgeCore/ready` (`Epoch`, `Ready`): the mod sets
  `Live` (the world is up and its definitions are loaded) and `Ready` before each `Pump()` and calls `Announce()` about once a second; the host broadcasts,
  a client tells the host. A client adopts a newer epoch only from the current host (an older one, or one from a world it left with `ResetWorld()`, is refused),
  raises `EpochChanged` and answers with its own state; the host records each compatible member's answer. `HostReady(lifetime)` and `PeerReady(player, lifetime)`
  say whether an answer is fresh (seconds on the clock `Net.Tick` runs on). `TryToHost` sends only while there is a host. Ordnance stamps and drops by epoch
  but keeps its own hello (throw numbering) in its session; Energy Lab uses all of it.
  Replaying level state to a player who joins mid-level stays with each mod (Ordnance keeps it per call, `OrdnanceApi.SendState`).
- **InputLease.** Wraps the four public `InputMapper` delegates while any lease blocks or steers, and puts them back when none
  does; a wrapper left in place because another mod wrapped over it forwards everything. `Down`/`Held`/`Axis` read the game's own
  answer. Released automatically at `LevelAPI.OnLevelCleanup` and at `GameEvents.LocalPlayerDown` (subscribed with the first lease); nothing is read per frame.
- **Enemies.** `Near` uses `Physics.OverlapSphereNonAlloc` on `MASK_ENEMY_DAMAGABLE` and doubles its buffer until the query is not
  full; collider owners are cached by instance ID and dropped by prefixes on `EnemyAgent.Setup` and `EnemyAgent.OnDead` (patched the
  first time `Near` runs) and at level cleanup. `Nearest` is `Near` sorted by distance and cut to a limit. `Alert` maps `AgentMode.Hibernate` to Sleeping, `Agressive` to Hunting, the rest to Awake; a dead enemy, one without an AI and `AgentMode.Off` are `Off`.
  `Live` is the registry of every living enemy in the level: slot index = position in the span, vacant slots are null, a slot keeps its
  enemy while it lives and `Generation(slot)` goes up each time the slot is vacated. The first read patches `EnemyAgent.Setup` (postfix
  registers) and `OnDead`, `OnDeSpawn` and `OnDestroy` (prefixes unregister: an enemy that leaves without a death is dropped when the game
  removes it, not by a scan on read), and registers the `EnemyAgent`s already in the scene once. `Version` changes whenever a slot is taken
  or left; level cleanup empties the registry.
- **GameEvents.** The game's discrete state changes as events, so no mod reads them per frame: `MasterChanged` with `Master` (the host's
  lookup, 0 without a session; read once at `SNet_Events.OnMasterChanged`, `OnResetSessionEvent`, `OnPlayerJoin` and `OnPlayerLeave` and
  raised only when it changed), `LanguageChanged` with `LanguageRevision` (raised after `GameDataTextLocalizationService.SetCurrentLanguage`;
  a reader caching text compares the revision), `LevelEnded` (`LevelAPI.OnLevelCleanup`), `CheckpointReloaded`
  (`EventAPI.OnCheckpointReloaded`) `LocalPlayerDown` (`Dam_PlayerDamageLocal.ReceiveSetDead`), `LobbyChanged` with `InLobby` (GTFO-API `EventAPI.OnGameStateChanged`; the state is read once at
  start and kept from the events) and `ExpeditionSelected` (rundown id, tier, index; after `RundownManager.MasterSelectActiveExpedition` on the host and after `RundownManager.SetActiveExpedition` on a client). The language,
  player-down and expedition patches go on the first time something subscribes or reads the revision. A handler that throws is one `ErrorOnce` line and the others still run.
- **Checkpoint.** The recall barrier. After a checkpoint reload the game puts the backpack, ammunition and players back over several frames, so anything a mod writes earlier is overwritten. `Checkpoint.Recalling` is true while the game is reloading a checkpoint or its capture is recalling replicated state; `Checkpoint.Settled` is true once no reload is in progress and a frame has passed since `CheckpointReloaded`. A mod restoring its own part of the state waits on `Settled` and writes once; a mod that must refuse stale input during a reload reads `Recalling`. Nobody patches `CheckpointManager.OnStateChange` or `SNet_SyncManager.OnRecallDone` for this. Each mod keeps its own state snapshot (what it saves at `CheckpointReached` and puts back at `CheckpointReloaded`): the data and the messages that carry it to the other players differ per mod, so there is no shared snapshot registry. Main thread only.
- **ColliderQuery.** `new ColliderQuery(capacity)` owns one `Il2CppReferenceArray<Collider>`; `Sphere(position, radius, mask, triggers)` runs `Physics.OverlapSphereNonAlloc` into it, returns the count and clears what a longer earlier query left behind. The game cannot tell a buffer filled exactly from one that overflowed, so `Truncated` is true whenever `Count == Capacity`: the colliders are the first ones found and the caller must refuse or query again with a larger capacity (it never reads as complete). `new ColliderQuery(capacity, grow: true)` does that repeat itself: a full buffer is replaced by one twice as large and the query repeated until the result is below the capacity, so the result is always complete and `Truncated` is never true (the capacity stays grown; use it where the count is unbounded and a refusal is not an option). `Clear()` releases the last result. `Count` and the indexer are valid until the next `Sphere` on the same instance; keep one instance per call site so results survive other queries. Layers (`LayerManager.MASK_*`) and `QueryTriggerInteraction` are the caller's; dedupe, ordering and receiver selection stay with the caller. Energy Lab uses it for its contact, flame, gravity, arc and explosion queries. For living enemies use `Enemies.Near`.
- **Slow.** `Enemies.Slow(agent, factor, owner)` returns a `SlowLease` (dispose to end) and scales `EnemyAgent.Anim.speed` (the game moves enemies by animator root motion; the foam state stops them the same way). The bookkeeping is `SlowBook` (pure): the enemy's own speed is kept, leases on one enemy take the slowest factor and never compound, and when the speed read is not the one applied the game changed it and that value becomes the own speed (`lease.Refresh()` re-applies after that). The last lease ending, or `EnemyAgent.Setup` / `OnDead` (the same prefixes as the registry), puts the own speed back unless the game has set another meanwhile. Every write is read back; a mismatch is an `ErrorOnce` line and `ReadBack` is false. An enemy without a live animator gets an inactive lease and an error line. Callers skip enemies the game holds itself (foam) before asking. `Enemies.SlowZone(centre, radius, factor, seconds, owner)` is that call made for every enemy inside a sphere and returns a `SlowZoneLease` (`Dispose` ends it; it also ends at `Time.time + seconds` and at level cleanup). It is a list of zones, each with one `Slow` lease per enemy inside, run by `CoreDriver.Update` through `Enemies.TickZones(Time.time)` at most every 0.1 s: a pass takes `Near(centre, radius)`, skips an enemy without a live animator and one the game holds in foam (`Locomotion.CurrentStateEnum == ES_StateEnum.StuckInGlue`, the foam owns its speed until it wears off; the enemy is slowed on the first pass after it is let go), takes a lease for a new enemy, refreshes one it holds, takes a fresh lease for one the game ended (died, reused: `Setup` and `OnDead` already put its speed back) and ends the lease of an enemy that is no longer inside. `Slowed` is the number of different enemies slowed with a write that read back over the zone's life and `Mismatches` the writes that did not read back (the lease's `ReadBack`, one `ErrorOnce` line per kind), so a caller can log what really happened. A radius or time of 0 or less, or a negative factor, is refused with `ArgumentOutOfRangeException`. Zones are per peer: call it on every peer that should see the enemies slowed.
- **Level.** `CourseNodeAt(position, sample, out node, out dimension, preferredDimension)` asks `AIG_CourseNode.TryGetCourseNode` for the
  preferred dimension, then for the level's other dimensions in index order, and takes the first live (not collected) node; false with dimension -1 when none.
  Only dimensions the built level has are asked: they are read once from `Builder.CurrentFloor.m_dimensions` at build done and cleared at cleanup (the game logs an error with a stack trace for each index it lacks).
  Zones as level events name them: `HasDimension(dimension)` (that same list), `TryZone(dimension, layer, localIndex, out zone)`
  (`Builder.CurrentFloor.TryGetZoneByLocalIndex`), `AreaCount(zone)` and `TryAreaCentre(zone, index, out centre)` (the area's course node position, in
  the zone's own `m_areas` order). Main thread, after the level is built.
  `TryActiveExpedition(out rundownId, out tier, out index)` reads the active expedition (`Global.RundownIdToLoad`, `RundownManager.GetActiveExpeditionData`); false when the game cannot say.
  `FindStandSpot(origin, yaw, clearance, preferBehind, out spot, out tried)` tries `StandSpots.Count` (7) places in a fixed order (straight behind, the back diagonals, the sides, further behind, the front; mirrored when `preferBehind` is false), each `clearance` times its factor away: a place passes when `NavMesh.SamplePosition` (0.6 m) finds ground within 1.2 m of the origin's height, the floor ray (`MASK_WORLD`) finds the floor, a 0.3 m capsule from 0.45 to 1.45 m touches no world geometry and no world geometry lies on the line from 1 m above the origin to 1 m above the place. When none passes the result is false, `spot` is the origin and `tried` is the count. The order is pure (`StandSpots.Offset`); nothing is allocated.
  `TryRoute(from, to, maxLength, corners, out count)` snaps both ends onto the navigation mesh (`NavMesh.SamplePosition`, 2 m, every area), asks `NavMesh.CalculatePath` (the surface the enemies walk on, closed doors included) and accepts only `PathComplete`; it writes every corner after the start into `corners` (a `Span<Vector3>`) and their number to `count`, and refuses, with a count of 0, a path longer than `maxLength` (summed over the corner segments), one with more corners than `corners` holds (never cut short) and one that fills the game's 64-corner buffer (it may be truncated). `HasSight(floorPoint, aim)` is false when `Physics.Linecast` against `LayerManager.MASK_WORLD` (triggers ignored) meets the level between a point 2 m above `floorPoint` (a ray 0.1 m above the floor finds a lower ceiling; the line then starts 0.15 m under it, never below 0.2 m above the floor) and `aim`. `Blocked(from, to)` is that linecast between the two floor points lifted 1 m. The path object and corner buffer are reused: nothing is allocated per call.
- **Il2CppArrays.** `ToManaged` / `ToGame` copy the array memory (after the four-pointer header) in one go; `Upload` writes RGBA32 pixels with
  `Texture2D.LoadRawTextureData` (the caller applies the texture).
- **PlayerHits.** The one patch on the game's player hit path. `Redirect(owner, (receiver, damage, source) => damage)` changes the damage of a hit before anything reads it (0 = none; redirects run in registration order); `GateInfection(owner, (receiver, data) => allow)` skips an infection write; `Observe` / `ObserveInfection` register the one reader of hits and infection writes (`IPlayerHitObserver.Before/After/Faulted` with a `HitState` value carried between them, `IInfectionObserver.Before/After`); a second owner is refused, null removes a registration. A callback that throws is one `ErrorOnce` line and the game body still runs. ForgePlayer reads, Frames redirects and gates.
- **EnemySpawn.** `Request(id, node, mode, position, rotation)` is `EnemyAllocator.SpawnEnemy(id, node, mode, position, rotation, null, -1)` (native ABI: a null group is accepted and the pose is copied unchanged; the game builds, sets up and replicates the enemy and starts it in `mode`); it returns null when `EnemyAllocator.Current` is missing or collected, and what the game returns otherwise (null when it refuses). The registry in `Enemies` picks the spawn up through the game's own spawn hook.
- **NavMarkers.** The game's own world markers (`GuiManager.NavMarkerLayer`): `Available`, `Layer`, `Place(options, trackingObject, title)` (`PlaceCustomMarker`; null when the layer is missing or the game refuses) and `Remove(marker)` (`RemoveMarker`; safe when the marker or layer is gone). Style, colour and text are set on the returned `NavMarker`. ForgeUI's `UIKit.AddNavMarker` and ForgeMap's HUD marker both call it; no other package calls `PlaceCustomMarker` or `RemoveMarker`.
- **PlayerNoise.** The game gives a player no noise radius: an enemy hears a player's Walk, Run, Jump or LoudLanding inside its own movementDetectionDistance (EnemyDetectionDataBlock) and a Sneak inside a fixed 1.9 m, as Agent.NoiseType says (EnemyDetection.DetectOnNoiseDistance_Conditional_AnimatedWindow reads it, evidence in Mods/ForgeEnemy/evidence/enemy-behavior-hooks.json). PlayerNoise.Scale(player, multiplier, owner) returns a PlayerNoiseLease (dispose to end; leases end with the level) after which enemies hear that player as if all those distances were multiplier times longer; a shot, a melee hit or a decoy is not movement noise and is not scaled. Call it on the host, where enemies detect. Several leases on one player never compound: the largest wins. Mechanism: a postfix on EnemyDetection.UpdateDirectionDistanceToTarget_Hibernate (where the game measures the distance; no by-ref parameter) divides the target's m_distance by the player's factor, so the game's noise check and a mod reading m_distance after it (ForgeEnemy's wake rules) see the scaled value and compose with the multiplier; the distance is measured again before every check, so nothing is put back. The noise check itself is never patched: its out float parameter made Il2CppInterop's trampoline throw on every call, and ForgeCore refuses to patch any game method with a by-ref primitive parameter (TrampolineSafety, checked at startup). The factor is one array element read by player global ID (NoiseScaleBook, no lookup, string or allocation per call), the hook returns at once while no lease exists, and without ForgeEnemy installed nothing changes. A target farther than the enemy's gunfire distance is skipped by the game before this method, so a scaled noise cannot reach past it. One consequence of dividing the distance: the game's inside-1 m instant wake becomes 1 x multiplier m.
- **Combat.** `Explode` is `DamageUtil.DoExplosionDamage` (all explosion targets) or `DoExplosionDamage_Capsule` (a target mask, a
  damage type and a source ID). `Fire` is `Dam_SyncedDamageBase.FireDamage` and reads `Health` before and after. `Bullet` is
  `BulletWeapon.BulletHit(hit, true, 0, 0, true)`. `Noise` is `NoiseManager.MakeNoise` with the parameters of the game's loud events (a
  mine's explosion, a sentry's shot): no noise maker, radius 0 to the given one, y scale 1, `InstaDetect`, spreading into neighbouring
  areas, no first-node raycast; the parameterless `NM_NoiseData` constructor is used because the generated nine-argument one reads
  `this.Pointer` before boxing. The requests to one receiver all return a `DamageSettlement` (the receiver's `Health` read before and after, on this peer: the settlement on the receiver's authority, the host for enemies; elsewhere the game forwards the request and the receiver's own peer settles it later). `Push(receiver, strength, source, position, direction)` is `Dam_SyncedDamageBase.PushDamage`: `Dam_EnemyDamageBase.ReceivePushDamage` takes no health (it does nothing for an immortal enemy or one whose `EnemyBalancingData.CanBePushed` is false, otherwise it registers the source agent, tells the enemy's abilities it was hit and starts a hitreact on the enemy's locomotion along the direction: Heavy when `strength` is above 0, Micro when the enemy is glued past its tolerance), so a settlement of 0 means only that no health was lost; whether the hitreact moved the enemy is not read. `Melee(receiver, damage, source, position, direction, staggerMultiplier)` is `Dam_EnemyDamageBase.MeleeDamage` with the stagger multiplier and the other four multipliers 1, no directional bonus, `DamageNoiseLevel.Normal` and gear category 0. `ExplosionDamage(receiver, damage, position, force)` is `Dam_SyncedDamageBase.ExplosionDamage(damage, position, force)` for one receiver (no falloff, no blockers, no other target; `Explode` is the radius query). `BulletDamage(receiver, damage, source, position, direction, normal)` is the receiver's five-argument `BulletDamage` (no limb, weak spot or falloff; `Bullet` resolves a whole hit). `Force(receiver, origin, magnitude)` is `Dam_EnemyDamageBase.SendExplosionForce`, which the game replicates and applies to the body; it takes no health and the game keeps no value to read back, so it returns nothing and throws the game's own exception when the request is refused. `Combat.Killed` (`Action<EnemyAgent, Agent?>`) is raised on the host after `Dam_EnemyDamageBase.ReceiveBulletDamage` took a living enemy to dead (a prefix at the highest priority notes `SNet.IsMaster` and `Owner.Alive`, a postfix at the lowest reports `!Owner.Alive` with the packet's `source`); melee, explosion and fire kills are other receivers and are not reported; a handler that throws is one `ErrorOnce` line and the others still run; the first subscription puts the patch on.
  `Combat.Shot` is one shot from a point at a target, settled as a stock bullet; keep one instance per call site (it owns its `WeaponHitData` and a 64-entry ray buffer; nothing is allocated per shot). `Trace(weapon, profile[, origin, direction])` aims along the look camera and traces again from the gun's visible muzzle (the first-person item camera has its own field of view, so the muzzle is put at the same screen point in world space and pulled in front of any level surface between the camera and it) so cover blocks both the effect and the damage; `Trace(owner, profile, start, direction)` is the same ray for a shooter whose camera is not this peer's. Rays are cast against `LayerManager.MASK_BULLETWEAPON_RAY` with the global trigger setting, nearest hit only, stepping over the shooter's own colliders (at most 32; a ray that crosses more throws and submits nothing). `VisibleTarget` accepts a ray only when it first lands on the same receiver as the wanted collider; `RayTarget` finds the first surface of a receiver's actor along a radial path (for an area query that selects actors, not limbs; a collider that contains the origin is found by a ray from outside back through its exit surface, distance 0); `ContactTarget` turns a sweep or overlap contact into a parallel physics ray through the contact point, keeping the sweep's distance for the game's falloff; `ResolveHit` takes such a hit as the shot; `Apply()` submits it through `Combat.Bullet` (`BulletHit(hit, true, 0, 0, true)`, gear category 0), nothing when the collider is the shooter's own, and `Submit` is virtual so a caller can mark its own submission. `BulletProfile(Damage, Stagger, Precision, Range)` is what the shot hands the game; the damage falloff is flat to `Range`.
  `Combat.GunLowered(owner)` is true while the local player's gun is in the game's relaxed (idle-lowered) pose, and `Combat.RaiseGun(owner)` restarts the game's idle-lowering timer so a fire input brings a relaxed gun back up; `Trace(weapon, ...)` starts a shot or effect from `GunPose.RaisedMuzzle` (the raised hip muzzle in front of the look camera) while the gun is lowered, so nothing begins at the hip. `GunPose.ToYawFrame` / `FromYawFrame` keep a reported point in the shooter's yaw frame so a remote peer's effect turns with the shooter.
- **Gear.** `Prepare` and `PrepareSentry` (over `GearEffectAssets`, the one gun-assembly asset entry) bring in the muzzle flash block's first- and third-person
  prefabs (loading their shard once) and the tracer while `BulletWeapon.s_tracerPool` is null. `EquipLocal` calls
  `PlayerBackpackManager.EquipLocalGear` only when that answers Ready. `WriteLocalAmmo` writes the reserve and magazine, then
  `UpdateAllAmmoUI` and `ForceLocalAmmoStorageUpdate`. `Gear.SpecialSlot` is the local player's one special weapon slot arbiter
  (`Core/SpecialSlot.cs`): `Take` stacks leases, only the newest changes the slot (older ones are `Suspended` and `Park` their gun),
  `Remember`/`OwnLeaves`/`OwnReturned` keep the player's own weapon and its stock, and while it is away special ammunition pickups
  go into its kept pool (`RedirectsRefill`). The slot is captured at `EventAPI.OnCheckpointReached` and recalled at
  `OnCheckpointReloaded` (subscribed when ForgeCore loads, so dependent mods read the recalled slot) and cleared at level cleanup.
- **GameAssets.** Only what GTFO-API's `AssetAPI` lacks; whether an asset is loaded is `AssetAPI.ContainsAsset`. The game's own `GetLoadedAsset` throws `KeyNotFoundException` for a missing key, so `Get<T>(path)` asks `AssetAPI.ContainsAsset` first and answers null for a path that is not loaded or whose object was collected. `ReadShard(shard)` returns a `GameShardState` (manifest present, count present, count, and the identity of the two tables and the manifest, so two readings tell a stable registration from a replaced one). `LoadShard` is the game's loader (true: a scene load started; false: the manifest was registered, the game incremented the count itself and queued the callback), `IncreaseShardDependency` and `UnloadShard` are its counted pin and release. A native load of an unregistered key resets its count to 1, so a caller joins a load in flight (count positive, no manifest) instead of restarting it. Which caller owns which pin, and when it may release it, is the caller's own proof and stays with the caller. `GearEffectAssets`, ForgeMap, ForgeEnemy, ForgeWeapon, ForgeVisual and ForgeEngine's `NativeModelRuntime` read through here.
  `LoanedGun` is what every lender does the same way: `TryLocalSpecial` reads the slot, `Settled` says the slot's gun is assembled (loaded,
  a live weapon with its archetype, gear known), `OwnLeaves` keeps the own weapon's live magazine and reserve in the slot, `Require`/`Equip`
  throw unless the gun's assets are ready (then `Equip` calls `EquipLocalGear`), and `EquipOwn` asks for the kept own weapon. The game spawns the incoming gun's parts one per frame with the hand empty meanwhile, so
  call `FinishParts(item)` every frame of a swap (an orderly leave that can wait skips it): once the new instance stands in the slot,
  its own part spawner (captured from `GearPartSpawner.SpawnAllParts`) runs its remaining steps at once (`GearAssembly.Finish`) and the
  swap ends (`EndSwap`). Which gun,
  its stock and when it goes back stay with the lender.
  Handling (`Native/GearHandling.cs`): `Gear.LeaseReload(owner, (weapon, duration) => factor)` multiplies the game's own reload duration
  (`BulletWeapon.get_ReloadTime`, patched once on the first lease; leases of different owners multiply, null removes yours); no data
  block is written. `Gear.ScaledRecoil(block, m)` returns a copy of a recoil block with power, crosshair pop, position impulse and shift,
  rotation impulse and concussion intensity scaled by `m` (the axis ranges stay); the source is untouched.
- **DataBlocks.** `Add` checks the ledger and the game's table, calls `GameDataBlockBase<T>.AddBlock` and reads the block back by ID
- **DataBlocks.** `Clone(donor, name, id)` is a shallow copy of a donor block under a new name and ID, enabled (nested data stays shared with the donor); register it with `Add`. `Add` checks the ledger and the game's table, calls `GameDataBlockBase<T>.AddBlock` and reads the block back by ID
  and name. `NativeDataBlockTables.Register` adds blocks written as the game's JSON in one startup transaction (every row checked
  before the first table changes, a failed publication removed again); `HasUnknownState` is true for the rest of the process once a
  rollback failed.
- **GameHooks.** The game methods more than one package reads are patched here once (`Native/GameHooks.cs`), never by the packages: each member is a `Bracket<TCall>` over one game method (`Native/Bracket.cs`). `Before` sees the call ahead of every other patch (prefix `Priority.First`), `After(call, ran)` after all of them (postfix `Priority.Last`; `ran` is false when another prefix skipped the body, the old `__runOriginal`), `Around` keeps the subscriber's own state between the two (a value, per call; `faulted` runs instead of `after` when the body threw, the exception stays the game's to throw). `RayBracket` (`MuzzleRay`, `AlignedRay`) hands the hit data and the result by reference; the muzzle overload does not read the muzzle position (a native read), the subscriber does when it needs it. The first subscription patches the method (`Patches.Ensure`, module `GameHooks.<Name>` in `Modules`); a subscriber that throws is one `ErrorOnce` line and the others still run. Subscribe once, at plugin load; there is no unsubscribe. A package that needs a new shared game method adds a member here (and its `Modules` row) instead of patching it; `validate-dependencies` refuses the same game method patched by two packages.
- **Items.** `Items.Spawn` is the game's `ItemReplicationManager.SpawnItem` and reads the spawned replicator back from
  `m_internalSpawnCallbackReturnReplicator`. A pickup made in play keeps the game's own allocation: its state replicator takes the next
  self managed key (`SNet_Replication.AllocateKey`, counter starting at 500) and the game logs "Its not allowed to create self amanged
  replicators during play"; every player runs the same spawn path, so they allocate alike. ForgeCore does not hand it a key of the
  dynamic range (32767 up): `SNet_Replication.ReconstructIds`, which runs after a checkpoint reload, counts keys by the replicator's
  type, so a self managed replicator in the dynamic range is not counted, the dynamic counter falls back below it, and the next dynamic
  allocation takes its key (the game logs "Replication Key collision!") and the pickup's state, its amount included, goes to the wrong
  replicator. The pickup's culler gets no cull bucket (the game's culling job, `C_Culler..ctor`, reads the level's zone objects above the
  pickup and throws without them), so the game logs "tried to MoveToNode() but CullBucket was null" once per pickup and the pickup is not
  culled. `Items.Spawned` is raised after every other patch of `OnItemSpawn` (`Native/ItemSpawnHook.cs`).
- **Frame.** `Frame.OnUpdate(modId, callback)`, `OnLateUpdate` and `OnQuit` add a callback to a `FrameBook` (Core) that ForgeCore's one driver runs: `Update` after the network tick, `LateUpdate` (after the game's animation), and `OnDestroy` at shutdown, each in registration order. A callback that throws is one `ErrorOnce` line under that mod's ID and kind (`update`, `late update`, `quit`); the other callbacks and the next frame run as usual. A callback registered during a frame first runs on the next one. No mod adds its own `MonoBehaviour`: state lives in plain static classes and the callback is a static method (the delegate is made once, so a frame allocates nothing). There is no per-callback timing.
- **Patches.Lazy.** `Patches.Lazy(modId, install)` returns a `LazyPatches` for hooks that serve one rarely used feature (an energy gun in hand, a suit worn). The first `Ensure()` runs `install` once with a `Harmony` for `modId`; later calls return at once, also after a failure. A throwing `install` is one `ErrorOnce` line and the feature stays unpatched. Patches stay on, for the reason under Patches below.
- **StrictJson.** Pure (`Once/`). Every method takes the object's own path prefix (empty at the root, `"Shield."` inside `Shield`) and names the field as prefix + name in a `StrictJsonException`. `OnlyKnown(value, prefix, known, alsoAllowed, owner)` refuses a non-object, a member in neither list (the message lists `known`) and a member written twice. `Number` and `Integer` (`min`..`max`, bounds included; a whole number for `Integer`), `Bool`, `Enum<T>` (exact member name, no number), `Reference` (a persistentID or a block name) and `Object` read one member; a missing member returns the fallback, or is "required" when there is none; a wrong type or a value outside its range is refused, never clamped. `Canonical` writes members sorted by name with every number in one spelling (coefficient and exponent, no rounding) and strings escaped by the default serializer, so equal content is equal text; ForgeOrdnance hashes it into its definition set hash.
- **Fnv.** `Hash32` and `Hash64` over UTF-8 text or bytes; `Mix32` and `Mix64` feed one byte for callers that hash a record. The algorithm is part of wire formats and saved keys (`Net` fingerprints, ForgeOrdnance payload and look keys, ForgeAudio network names, EnergyLab gear IDs, the Frames spec key), so its output never changes; the tests lock the published vectors.
- **Assets.Keep.** `Assets.Keep(asset)` sets `HideFlags.DontUnloadUnusedAsset` on an object a mod holds only in managed code (a texture, mesh, material, pooled root or a loaded bundle asset) and returns it; the game's unused-asset sweep at scene changes cannot see such references. `Assets.Load`, `LoadBytes` and `Get` already keep what they return.
- **Log, Settings, Pool, Store, Assets** as listed in `README.md`. Logging writes errors only: `Error` and `ErrorOnce` (an exact message is written the first time it occurs and never again; a different message from the same place is written too) reach the mod's BepInEx log source, and nothing else is written (`Log.Num(value)` and `Log.Pos(x, y, z)` / `Log.Pos(Vector3)` format a number with at most two decimals and a position with two, always with a dot). A failed feature, or data or configuration that leaves something unusable, is an error; progress, state changes and recoverable conditions are not logged. There is no debug mode or log switch and no `Info` or `Warning`. An error that carries an exception writes the whole exception (`error.ToString()`), not its `Message`. A state a player or the game can legitimately be in (a player without the mod, an enemy that has just left) is not logged.

- **Puppets.** `Puppets.Enemy(enemy, owner)` holds an enemy as a puppet (`EnemyPuppet`): `AI.Mode = Off`, `AI.SetNavMeshAgent(false)`, the `NavMeshAgent` component and `Anim.applyRootMotion` off, `Dam_EnemyDamageBase.IsImortal` on (the damage limbs stay, it can still be aimed at), `ForceNoAnimationCulling` on, and `Locomotion.ChangeState(StandStill)` so the animator leaves the hibernation pose. `Drive(position, rotation, velocity, seconds)` (call it in `Frame.OnLateUpdate`) sets the transform and writes the game's own animator inputs `EnemyLocomotion.s_hashMoveOnGround`, `s_hashForward`, `s_hashRight` (the world velocity in the enemy's frame, `PuppetMotion.Local`; smoothed with the locomotion's `MoveAnimDampTime`). Every `Drive` checks that the AI mode, nav mesh, root motion and immortality are still as set; if the game changed one, it is set again, `Retaken` goes up and one `puppet-retaken` error line is written. `Rate` sets the animator speed (0 freezes), `Die()` ends the immortality and calls `InstantDead(true)` (the game's death animation or ragdoll), `Dispose()` restores AI mode, immortality, root motion, culling flag, nav mesh and animator speed. `Puppets.Player(agent, owner)` holds a non-local `PlayerAgent` (a bot): the first one calls `PlayerManager.DisableBotAI()` (the game's own switch, for the rest of the level), `Drive` calls the synced-player locomotion (`SyncedSetPosition`, `SyncedSetRotation`, `UpdateFullBodyAnimValue`, `SetCrouch`), `Wield(slot)` is `Sync.WantsToWieldSlot(slot, true)`. `SoloDrop.Start(level, seeds, bots)` opens `bots` (0 to 3) of the other slots to bots (`SlotPermission.Bot`) instead of closing them; the game fills them itself.
- **WorldStates.** `Door` (security and weak doors, `eDoorStatus`), `Generator`, `Item` and `Puzzle` call the game's own state handlers (`OnSyncDoorStatusChange`, `OnSyncDoorStateChange`, `OnStateChange`) with a state built from the status. `instant: true` passes the handler's drop-in / recall flag, which is how the game gives a late joiner the state without animation, sound or effect; `false` is a live change. Nothing is replicated and no game rule runs.

## Patches

`Enemies` patches `EnemyAgent.Setup` (prefix and postfix) and `EnemyAgent.OnDead`, `OnDeSpawn` and `OnDestroy` (prefixes) on its first use; `Gear.LeaseReload` patches `BulletWeapon.get_ReloadTime` (postfix) on its first lease; `PlayerHits` patches `Dam_PlayerDamageBase.OnIncomingDamage` (a first-priority prefix for redirects; a last-priority prefix, postfix and finalizer for the observer) and `ModifyInfection` (a first-priority prefix, a last-priority postfix) on its first registration; `Gear.SpecialSlot` patches
`PlayerAmmoStorage.PickupAmmo` (prefix and postfix) and `PlayerAmmoStorage.NeedWeaponAmmo` (postfix) on its first use. PlayerNoise patches EnemyDetection.UpdateDirectionDistanceToTarget_Hibernate (postfix) on its first Scale. `GameEvents` patches
`GameDataTextLocalizationService.SetCurrentLanguage` and `Dam_PlayerDamageLocal.ReceiveSetDead` (postfixes) when the language or the
player-down event is first needed. `Items` patches `ItemReplicationManager.OnItemSpawn` (prefix and postfix), `ItemInLevel.OnDespawn` (postfix),
`SNet_Replication.AllocateKey(SNet_ReplicatorType, ushort)` (prefix) and `SNet_Replication.DeallocateReplicator` (postfix) when ForgeCore loads, not on first use, because a client must
take the host's keys without ever spawning anything; all four return at once outside one pickup spawn in play. Nothing else is patched. At startup ForgeCore checks that every patched method exists; a missing one logs
an error and the module's calls throw. A patch, once on, stays on: under Il2CppInterop an unpatch rebuilds the detour as a pass-through to
a new trampoline and keeps the old delegate, so it saves nothing per call and leaks one generated method each time.

## Quick start

Depend on `NAinfini-ForgeCore-0.1.0` in `manifest.json`, reference `ForgeCore.dll`, and add `[BepInDependency("NAinfini.ForgeCore")]`.
Every call takes your plugin GUID as the mod ID.

```csharp
using ForgeCore;

[BepInPlugin(Id, "My Mod", "1.0.0")]
[BepInDependency("NAinfini.ForgeCore")]
internal sealed class Plugin : BasePlugin
{
    internal const string Id = "me.mymod";
    private static NetChannel _net = null!;

    public override void Load()
    {
        _net = Net.Open(Id);                            // a player whose messages differ is refused on both sides, with a log line naming them
        _net.On<Ping>("ping", (sender, ping) => Handle(sender, ping.Value));
    }

    // From your own Update: run the received handlers, then send.
    internal static void Tick() { _net.Pump(); _net.Broadcast("ping", new Ping { Value = 1 }); }
}

[StructLayout(LayoutKind.Sequential, Pack = 1)] internal struct Ping { public int Value; }
```
