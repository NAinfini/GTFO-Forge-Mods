# ForgeCore developer notes

The plan is `Docs/forge-core/PLAN.md`. ForgeCore is one assembly, `ForgeCore.dll`, one BepInEx plugin `NAinfini.ForgeCore` and one Thunderstore package `NAinfini-ForgeCore`, in four parts: the core (namespace `ForgeCore`, this first half), UI (`ForgeUI`), Audio (`ForgeAudio`) and Visual (`ForgeVisual`). One static entry per module; everything else is internal. Calls are main thread unless a member says otherwise. Within 1.x, public members are only added, never removed or changed. Internal classes, log wording and packaging are not part of the public API.

## Layering: what this package holds and what it does not

ForgeCore depends only on BepInExPack_GTFO and the game; ForgeEngine and the standalone mods depend on it. The core holds the base and the vanilla calls: asset-bundle loading, logging, config, object pools, network messages, input leases, local saves, and enemy queries and slowing, damage, explosions, noise, gear swapping and the special-weapon slot, borrowed-gun switching, data blocks and safe landing spots. The UI, Audio and Visual parts hold the on-screen, sound and world-drawing mechanisms (their own sections below). It only covers how to call; it holds no gameplay numbers and no content. If another mod may need a vanilla call or one of these mechanisms, add it here. It never depends on a higher package.

## Layout

- `Core/` references no game or Unity assembly and is compiled straight into the offline tests: logging, pools, the local store,
  network channels and lobby values (over an internal transport), the special weapon slot rules, the input lease book, the data block ledger, the module patch table and
  `NativeDataBlockTables`, the JSON data block transaction ForgeEngine and the Forge base packages register their content through.
- `Once/` is pure code (`ForgeCore.Once.csproj`) that any package, test or tool may reference or compile in without the game: `OnceReporter`, `PosixPath`, `Fnv`, `Hash`, `StrictJson` and `Png`. It is compiled into `ForgeCore.dll`; no separate `ForgeCore.Once.dll` ships.
- `Native/` is the game side: the plugin and its frame driver, the GTFO-API transport, lazy patching, and the modules that call the game. `Net/` is the network layer.
- `UI/`, `Audio/` and `Visual/` hold the three parts, each with its own `Core/` (no Unity reference) and `Native/` (the game side); their folders are listed in their sections.
- `Assets/` holds the media: `fonts/`, `Shaders/` (the shader bundles, embedded in the DLL), `Sights/` and `Vfx/`. `lang/` holds the UI part's own texts, one `<language>.forge` per language.
- `web-manifest.forge` is the website's library manifest, one file with four parts (`core`, `ui`, `audio`, `visual`).
- `tests/Core/` is the offline check program (`dotnet run --project Mods/ForgeCore/tests/Core/ForgeCoreTests.csproj -c Release`).

## Build and package

Run from the repository root. Replace `<profile>` with a GTFO r2modman profile.

```
dotnet build Mods/ForgeCore/ForgeCore.csproj -c Release --artifacts-path artifacts/dotnet --disable-build-servers -m:1 -p:GTFOBepInExPath=<profile>/BepInEx
dotnet run --project Mods/ForgeCore/tests/Core/ForgeCoreTests.csproj -c Release
dotnet run --project Mods/ForgeCore/Audio/tests/Core/ForgeAudioCore.csproj -c Release
python Mods/ForgeCore/Audio/tools/test_tools.py
python Mods/ForgeCore/tools/package_release.py --artifacts-path artifacts/dotnet
```

When a game profile is configured, the audio tests also check every installed `audio` folder. Without one those checks report "not run". The package script (the shared `Mods/Build/package_common.py`) checks the Thunderstore metadata, that the project and manifest versions agree and the 256 x 256 icon, and writes a deterministic zip: `ForgeCore.dll`, `NVorbis.dll` with its licence and notice, `lang/*`, `fonts/` (the font bundle and both licences; it refuses to build without them), `forge-visual-fx.bundle`, `fx-slots.forge` and `fx-licences.forge`, with `manifest.json`, `icon.png`, `README.md`, `DEVELOPERS.md`, `CHANGELOG.md`, `LICENSE`, `NOTICE` and `web-manifest.forge`. It does not publish. The fonts come from the UI part's font build and the effect bundle from `Tools/Vfx` (both local media).

## Modules

- **Content folders.** `ContentFolders.Find(folderName, errors)` returns the full paths of every directory named `folderName` (case-insensitive) under BepInEx `Paths.PluginPath`, sorted and distinct. The plugins tree is walked once per process into a name index (`ContentFolderIndex`), so a second mod asking does not scan the disk again; folders that could not be listed are added to `errors` on every call. It does not read MTFO.
- **Landing warm-ups.** Inside ForgeCore one internal queue holds the warm-ups that have to wait for the game's picture (a shader drawn once off screen, a large texture made). Once the elevator has stopped (`StopElevatorRide`) or the level runs, one step runs on each frame in the order added, so the warm-ups of the UI and Visual parts never share a frame. A step that throws is reported once and the rest still run.
- **Seeds, solo drop and fingerprints.** `Level.TryCurrentLevel` returns the active expedition (`RundownManager.GetActiveExpeditionData` and `Global.RundownIdToLoad`) and the three generation seeds: from `Builder.BuildSeed`, `Builder.HostIDSeedRandom.Seed` and `Builder.SessionSeedRandom.Seed` once generation began, before that from `RundownManager.ActiveExpedition.Seeds.BuildSeed` and `GetSeeds`. `SoloDrop.Start(level, seeds)` walks the main menu with the game's own calls (`CM_PageIntro.EXT_PressInject`, `CM_PageStart.EXT_PressStart`, from any other menu page first `MainMenuGuiLayer.ChangePage(CMP_RUNDOWN_NEW)`, `SNet.SessionHub.CreateHub(Private)`, `SNet.Slots.SetSlotPermission(Forbidden)`, or `Bot` for the bots asked for, `RundownManager.MasterSelectActiveExpedition`, `RundownManager.TrySetActiveExpedition` with the seeds, `CM_PageLoadout.OnReadyButtonClicked`, `EXT_StartExpedition`), checks the seeds read back from the game before the drop and again against `Builder` when generation starts, and is driven from ForgeCore's frame update. `Level.FingerprintSteps(done)` is the same fingerprint as an enumeration of one native scan per step (about 80 ms each on a large level), for a caller that runs one `MoveNext` per frame; `Level.Fingerprint()` runs it to the end at once. It hashes `Builder.CombinedCheckSum` and `ExpeditionInTierData.GetChecksum()` (the game's own) plus lines for zones, areas (geomorph name, size, gates, enemy spawn points, position in centimetres), and for every `LG_SecurityDoor` and `LG_WeakDoor`, `LG_ComputerTerminal`, `LG_ResourceContainer_Storage`, `LG_PowerGenerator_Core` and `ItemInLevel` (game object name and position in centimetres), each list sorted. Sleeping enemies are left out on purpose: the game spawns them after build done (the first frames of the level), and on R1A1 two runs with identical seeds gave the same enemy types and counts at different positions. `Level.Expeditions()` lists the enabled expeditions of the active rundowns with their official labels; `Level.TryFindLevel` resolves a label such as `R1A1`. `SoloDrop.Start(level)` without seeds lets the game draw its own. `SoloDrop` asks for the drop only when `PlayerManager.IsBotActionAllowed` holds and every lobby bot has its agent (the game's drop gate refuses silently otherwise, and cannot itself be asked: its yes already starts generation); 30 s of waiting, or 5 s in the lobby after asking, ends in `Failed` with the lobby in the log.
- **PlayerStats and CarrySlot.** `PlayerStats.Walk / CarryUnslowed / Jump / NoStamina / NoFlinch` change the local player's walk velocity, carry slowdown, jump, stamina cost and hit flinch; each hook goes on with its first subscriber and every subscriber is asked. `CarrySlot` moves the object of the in-level carry slot between the local player's hands and back: `Track` every frame, `Toggle` on the key, `GiveBack` and `Settle` when the permission ends, `DropIfFallen` while it may be on the back (the game drops only one in hand), `ShowOnBack` for other players, `SetPickupHold` at spawn. The package lifts `GameHooks.WieldedSlotBlocked` and `LocalItemHeld` for its carrier. The object stays in the slot, so the game's leaving capture and checkpoint capture read it unchanged.
- **Compact and ChunkLog.** `Compact` writes into a caller-owned `byte[]` at a caller-owned position: `WriteVar`/`ReadVar` (7 bits per byte, low group first, at most 10 bytes; a run past the end or a tenth byte above 1 throws `FormatException`), `WriteVarSigned` (zig-zag), `WriteDelta`/`ReadDelta`, `Quantize` (saturates out of range and on NaN) / `Dequantize`, `WriteQuaternion` (6 bytes: 2 bits for the largest component, 15 bits for each of the other three over ±1/√2, largest component kept positive, so q and −q give the same bytes; every component within 6e-5). `ChunkLog.Create(stream, formatVersion)` writes a 12-byte start (`FCLG`, container version 2, owner format version, little-endian), then per `Append(type, startMs, endMs, data)` a 28-byte header (`CHNK`, type, flags 0 stored / 1 Brotli, start, end, raw length, stored length, CRC-32 over the first 24 header bytes and the payload) and the payload; `Finish()` adds the index (24 bytes per chunk) and a 20-byte trailer (`FCIX`, index offset, count, CRC-32). Data is Brotli-compressed (quality 5, window 2^22) only when that is smaller. `ChunkLog.Open(stream, expectedFormatVersion)` reads the index when the trailer holds, otherwise scans headers in order and stops at the first chunk that is cut off or fails its checksum (it never skips ahead); `ChunkReader.IsComplete` tells which. Another container or format version throws `ChunkLogFormatException` naming both numbers. Every `Append` flushes the stream. One writer thread; a failed write throws and the writer is abandoned.
- **Net.** (`Net/`) ForgeCore is the only caller of GTFO-API's NetworkAPI (`Tools/Forge/core-owned-entries.json`). Every package sends through its
  channel; there are no raw events. Handlers run on the main thread as the game delivers each message (no queue, no `Pump()`), so they
  keep their order against the game's own messages; a handler's exception is logged, not thrown into the game's callback.
  `Net.Open(modId)` opens the mod's only channel. Message events are named `modId/name`; every message is a GTFO-API free-sized event
  sent to one player at a time (`Native/GtfoTransport.cs` says why not the player-list overload).
  **One handshake.** `Forge/hello` is one message per pair of players for the whole process: handshake version, answer flag, the highest
  world number the sender has seen, then one cell per open channel (mod ID, format fingerprint, content hash, held flag). Each channel
  reads only its own cell; a mismatch refuses that mod alone (`PeerState.Refused`, `Refused` event, one error naming the mod), and only
  then do the two sides exchange that mod's per-message list (`Forge/formats`) so the error names the messages that differ. A mod the
  other player does not list, and a player who answers no greeting (3 greetings, 10 s apart: ForgeCore missing or a build with another
  handshake), raise `PeerSilent`; another handshake version is refused with `net-hello-version` and an error telling both sides to run
  the same ForgeCore. The fingerprint (`NetChannel.Format`) is FNV-1a over every registered message's name, delivery, kind and field
  layout; a hand-coded byte body gives an integer version instead, so raise it when the bytes' meaning changes. `Content`,
  `HoldContent()`, `ContentDetail`, `ContentDetailOf`, `FormatDiffers` work per mod as before. Nothing of a mod is sent to, or taken
  from, a player whose verdict for that mod is not `Compatible` (`net-peer-refused`, `net-peer-unverified`); `PeerSynced` fires when a
  verdict becomes compatible, after ForgeCore sent that player the mod's rows, tables, readiness and checkpoint copies; `AnyPeer` is
  true while at least one player's verdict is compatible, for a mod that builds messages ahead of sending them.
  **One member list** (the session hub's members plus the players `AddPlayerToSession` / `RemovePlayerFromSession` named), read when the
  game says the session changed and before any received message is judged.
  **One epoch**, `Net.World` = (`Number`, `Checkpoint`, `Reason`), minted by the host in one place and announced by one message
  (`Forge/world`, sent before every greeting too). The number goes up when a session begins, a level starts building
  (`LevelAPI.OnBuildStart`), a level is cleaned up and the host changes; it is always above every number any member has seen. The
  checkpoint generation goes up on a checkpoint reload. A client moves at the same game event without waiting (so its own handlers
  already stamp the new world), the host's announcement confirms it, and a client whose guess is not confirmed within 2 s asks the host.
  `Net.WorldChanged` fires after ForgeCore dropped what belonged to the earlier world; on a host change `Session.IsHost` and
  `GameEvents.Master` already name the new host there, and `GameEvents.MasterChanged` follows. Number 0: no world.
  **Seven ways to send**, each with its epoch rule fixed in ForgeCore:
  1. `channel.Event<T>(name, handler)` -> `NetEvent<T>` (`ToHost`, `To`, `Broadcast`): reliable fixed-size message, stamped number +
     checkpoint; one from another world or generation is dropped (`net-stale-world`).
  2. `channel.Event<T>(name, handler, NetDelivery.Lossy)`: unreliable, same stamp plus a per-sender sequence; one older than the last
     received is dropped (`net-out-of-order`).
  3. `channel.Request(name, version, serve)` -> `NetRequest`: `Ask` / `AskHost` give exactly one `NetAnswer` (`Answered`, `AlreadyRan`,
     `TimedOut`, `Left`, `WorldChanged`); the receiver's ledger (per sender: settled floor and started numbers) runs each request
     exactly once (`net-request-duplicate`, `net-request-stale`). A request to the host that left is asked of the new host under the
     same number; `CaptureLedger` / `RestoreLedger` carry the ledger in the mod's own mirror of host state.
  4. `channel.Table<TKey, TRow>(name)` -> `NetTable`: only the host writes (`Set`, `Remove`, `Clear`); one message a frame with the changed rows;
     the whole table to a player who joins and to everyone after a checkpoint reload or host change; emptied by a new number, kept by
     the new host on a host change; `Changed` fires on every player, the host included; a hole asks for the table again (`net-table-gap`).
     `channel.Table<TKey>(name, version, maxBytes)` -> `NetByteTable` is the same table with rows of bytes of any length (a state per
     object, a document kept in parts: a part whose bytes did not change is not sent again); `NetTable` is that table with rows of
     one struct's size.
  5. Each player's own row: `channel.Lobby(name)` (bytes, session-long), `channel.Manifest(name)` (content list matched entry by entry),
     `channel.PlayerState<T>(name)` (value plus "seconds ago", number + checkpoint), `channel.Ready` / `HostReady` / `PeerReady` (number
     only). A world-stamped row from a world this player has not reached waits for it; a host change keeps the local row and sends it again.
  6. `channel.CheckpointCopy(name, version)` -> `NetCheckpointCopy`: the host `Publish`es what a reload restores, every player holds
     `Value`; number only, so it outlives reloads and host changes (the new host sends it again) and goes with the level.
  7. `channel.Bytes(name, version, handler)` -> `NetBytes`: a byte body to one player or all. Reliable bodies above 1 KiB are split by
     ForgeCore (`net-chunk-orphan` for a part without a beginning) and leave after the frame's other messages, within a send budget
     of 960 KiB of reliable traffic a second whatever the frame rate (at most 32 KiB in one frame); rows, tables, requests and copies
     ride the same path. At most 4 MiB waits: a body beyond that is dropped and counted (`net-bulk-void`, as one whose player or world
     went first). A dropped table change, value or checkpoint copy is sent again (the whole table, the value, the copy) once the queue
     is half empty; a dropped request or answer ends the request as timed out; a dropped `Bytes` body is lost. A lossy body must fit one packet.
  Every drop is counted (`Net.Drop(code)`, `Net.Dropped(code)`) and written once per mod and code as a `net.drop` line in ForgeCore's
  log; the other codes are `net-body-oversized`, `net-body-malformed`, `net-formats-unreadable`, `net-lobby-malformed`,
  `net-state-size`, `net-state-invalid`, `net-manifest-malformed`, `net-not-host`, `net-answer-unknown`. `Net.Traffic` is what every
  package sent since the process started (packets and bytes without GTFO-API's event header, and the lossy share).
  `FromHost(sender)` and `IsPlayer(lookup)` are the sender checks a handler makes itself; the network does not authenticate senders.
- **InputLease.** A blocked action passes while `FocusStateManager.CurrentState` is `MainMenu`, `Map` or `GlobalPopupMessage`, because the menu cursor (`CM_PageBase.UpdateCursorPosition`) reads the look axes. Wraps the four public `InputMapper` delegates while any lease blocks or steers, and puts them back when none
  does; a wrapper left in place because another mod wrapped over it forwards everything. `Down`/`Held`/`Axis` read the game's own
  answer. Released automatically at `LevelAPI.OnLevelCleanup` and at `GameEvents.LocalPlayerDown` (subscribed with the first lease); nothing is read per frame.
- **Enemies.** `AimPoint(enemy)` is where a shot or blast looks at an enemy (its aim target, else a metre above its feet) and `NearVisible(position, radius)` is `Near` kept to the enemies whose aim point the position can see (`Level.HasSight`, no wall between). `Near` uses `Physics.OverlapSphereNonAlloc` on `MASK_ENEMY_DAMAGABLE` and doubles its buffer until the query is not
  full; collider owners are cached by instance ID and dropped by prefixes on `EnemyAgent.Setup` and `EnemyAgent.OnDead` (patched the
  first time `Near` runs) and at level cleanup. `Nearest` is `Near` sorted by distance and cut to a limit. `Limbs(position, radius, triggers)` is the same query one level down: every enemy limb collider in range whose enemy lives, as `EnemyLimb(Collider, Enemy)` (an enemy once per limb inside, the trigger setting the caller's), for a caller that picks a limb itself (an arc that aims at the nearest limb); same layer, same owner cache, never truncated, no allocation once grown. `Alert` maps `AgentMode.Hibernate` to Sleeping, `Agressive` to Hunting, the rest to Awake; a dead enemy, one without an AI and `AgentMode.Off` are `Off`.
  `Live` is the registry of every living enemy in the level: slot index = position in the span, vacant slots are null, a slot keeps its
  enemy while it lives and `Generation(slot)` goes up each time the slot is vacated. The first read patches `EnemyAgent.Setup` (postfix
  registers) and `OnDead`, `OnDeSpawn` and `OnDestroy` (prefixes unregister: an enemy that leaves without a death is dropped when the game
  removes it, not by a scan on read), and registers the `EnemyAgent`s already in the scene once. `Version` changes whenever a slot is taken
  or left; level cleanup empties the registry.
- **FactoryEvents.** `FactoryEvents.OnBuildStart(handler)`, `OnBuildDone(handler)` and `OnBatchDone(handler)` (`Native/FactoryEvents.cs`) are `LG_Factory`'s own `OnFactoryBuildStart`, `OnFactoryBuildDone` and `OnFactoryBatchDone` delegates for any number of subscribers: the one native delegate goes on with the first subscriber and hands the call on at the same moment, in subscription order, and each subscription returns an `IDisposable`. They are not GTFO-API's `LevelAPI.OnFactoryStart` / `OnFactoryDone`, which are postfixes of `LG_Factory.OnStart` and `FactoryDone`; a subscriber that needs either moment picks it. Packages do not add to the three delegates themselves (`core-owned-entries.json`).
- **GameEvents.** `StateChanged` is raised after the game changed state, from GTFO-API's `EventAPI.OnGameStateChanged` (a postfix of `GameStateManager.DoChangeState`), for a cache a scene owns. The game's discrete state changes as events, so no mod reads them per frame: `MasterChanged` with `Master` (the host's
  lookup, 0 without a session; read once at `SNet_Events.OnMasterChanged`, `OnResetSessionEvent`, `OnPlayerJoin` and `OnPlayerLeave` and
  raised only when it changed), `LanguageChanged` with `LanguageRevision` (raised after `GameDataTextLocalizationService.SetCurrentLanguage`;
  a reader caching text compares the revision), `LevelEnded` (`LevelAPI.OnLevelCleanup`), `CheckpointReloaded`
  (`EventAPI.OnCheckpointReloaded`) `LocalPlayerDown` (`Dam_PlayerDamageLocal.ReceiveSetDead`), `LobbyChanged` with `InLobby` (GTFO-API `EventAPI.OnGameStateChanged`; the state is read once at
  start and kept from the events) and `ExpeditionSelected` (rundown id, tier, index; after `RundownManager.MasterSelectActiveExpedition` on the host and after `RundownManager.SetActiveExpedition` on a client). The language,
  player-down and expedition patches go on the first time something subscribes or reads the revision. A handler that throws is one `ErrorOnce` line and the others still run.
- **Players.** `Players.Motion(agent)` and `MotionChanged` read the players' locomotion states; `Players.Face(agent, point)` turns the local player's view level toward a point (a teammate, for a two-player action) and does nothing for a remote agent.
- **Checkpoint.** The recall barrier. After a checkpoint reload the game puts the backpack, ammunition and players back over several frames, so anything a mod writes earlier is overwritten. `Checkpoint.Recalling` is true while the game is reloading a checkpoint or its capture is recalling replicated state; `Checkpoint.Settled` is true once no reload is in progress and a frame has passed since `CheckpointReloaded`. A mod restoring its own part of the state waits on `Settled` and writes once; a mod that must refuse stale input during a reload reads `Recalling`. Nobody patches `CheckpointManager.OnStateChange` or `SNet_SyncManager.OnRecallDone` for this. Each mod keeps its own state snapshot (what it saves at `CheckpointReached` and puts back at `CheckpointReloaded`): the data and the messages that carry it to the other players differ per mod, so there is no shared snapshot registry. Main thread only.
- **ColliderQuery.** `new ColliderQuery(capacity)` owns one `Il2CppReferenceArray<Collider>`; `Sphere(position, radius, mask, triggers)` runs `Physics.OverlapSphereNonAlloc` into it, returns the count and clears what a longer earlier query left behind. The game cannot tell a buffer filled exactly from one that overflowed, so `Truncated` is true whenever `Count == Capacity`: the colliders are the first ones found and the caller must refuse or query again with a larger capacity (it never reads as complete). `new ColliderQuery(capacity, grow: true)` does that repeat itself: a full buffer is replaced by one twice as large and the query repeated until the result is below the capacity, so the result is always complete and `Truncated` is never true (the capacity stays grown; use it where the count is unbounded and a refusal is not an option). `Clear()` releases the last result. `Count` and the indexer are valid until the next `Sphere` on the same instance; keep one instance per call site so results survive other queries. Layers (`LayerManager.MASK_*`) and `QueryTriggerInteraction` are the caller's; dedupe, ordering and receiver selection stay with the caller. Energy Lab uses it for its contact, flame, gravity, arc and explosion queries. For living enemies use `Enemies.Near`.
- **StaticColliders.** `Node(parent, name, layer, position, rotation, scale)` makes a GameObject on a TagManager layer (`Layer(name)` throws `static-collider-layer-missing` for an unknown name); give it one collider with `Box`, `Sphere`, `Capsule` or `MeshCollider` (all non-trigger). The navigation build takes active, non-trigger box and mesh colliders on `Navigable(layer)` layers (`LayerManager.MASK_UNITY_NAVMESH_GENERATION`) as walkable sources, so nodes parented into a level before its navigation build carry voxel nodes (read back in game; the player build has no static flag to set). `Mesh(name, positions, indices)` builds a collision mesh (UInt32 indices above 65535 vertices; throws `static-collider-mesh-invalid` for incomplete or out-of-range geometry); `ColliderMesh(node, name, vertices)` returns the mesh of a vanilla MeshCollider only when name and vertex count match (a Unity built-in mesh is not handed back by name in the player build, so callers carry it as geometry).
- **Slow.** `Enemies.Slow(agent, factor, owner)` returns a `SlowLease` (dispose to end) and scales `EnemyAgent.Anim.speed` (the game moves enemies by animator root motion; the foam state stops them the same way). The bookkeeping is internal and pure (`Core/SlowBook.cs`): the enemy's own speed is kept, leases on one enemy take the slowest factor and never compound, and when the speed read is not the one applied the game changed it and that value becomes the own speed (`lease.Refresh()` re-applies after that). The last lease ending, or `EnemyAgent.Setup` / `OnDead` (the same prefixes as the registry), puts the own speed back unless the game has set another meanwhile. Every write is read back; a mismatch is an `ErrorOnce` line and `ReadBack` is false. An enemy without a live animator gets an inactive lease and an error line. Callers skip enemies the game holds itself (foam) before asking. `Enemies.SlowZone(centre, radius, factor, seconds, owner[, admit])` is that call made for every enemy inside a sphere (and passing `admit`, for example not behind a wall) and returns a `SlowZoneLease` (`Dispose` ends it; it also ends at `Time.time + seconds` and at level cleanup). It is a list of zones, each with one `Slow` lease per enemy inside, run by `CoreDriver.Update` through `Enemies.TickZones(Time.time)` at most every 0.1 s: a pass takes `Near(centre, radius)`, skips an enemy without a live animator and one the game holds in foam (`Locomotion.CurrentStateEnum == ES_StateEnum.StuckInGlue`, the foam owns its speed until it wears off; the enemy is slowed on the first pass after it is let go), takes a lease for a new enemy, refreshes one it holds, takes a fresh lease for one the game ended (died, reused: `Setup` and `OnDead` already put its speed back) and ends the lease of an enemy that is no longer inside. `Slowed` is the number of different enemies slowed with a write that read back over the zone's life and `Mismatches` the writes that did not read back (the lease's `ReadBack`, one `ErrorOnce` line per kind), so a caller can log what really happened. A radius or time of 0 or less, or a negative factor, is refused with `ArgumentOutOfRangeException`. Zones are per peer: call it on every peer that should see the enemies slowed.
- **Level.** `CourseNodeAt(position, sample, out node, out dimension, preferredDimension)` asks `AIG_CourseNode.TryGetCourseNode` for the
  preferred dimension, then for the level's other dimensions in index order, and takes the first live (not collected) node; false with dimension -1 when none.
  Only dimensions the built level has are asked: they are read once from `Builder.CurrentFloor.m_dimensions` at build done and cleared at cleanup (the game logs an error with a stack trace for each index it lacks).
  Zones as level events name them: `HasDimension(dimension)` (that same list), `TryZone(dimension, layer, localIndex, out zone)`
  (`Builder.CurrentFloor.TryGetZoneByLocalIndex`), `AreaCount(zone)` and `TryAreaCentre(zone, index, out centre)` (the area's course node position, in
  the zone's own `m_areas` order). Main thread, after the level is built.
  `TryActiveExpedition(out rundownId, out tier, out index)` reads the active expedition (`Global.RundownIdToLoad`, `RundownManager.GetActiveExpeditionData`); false when the game cannot say.
  `FindStandSpot(origin, yaw, clearance, preferBehind, out spot, out tried)` tries 7 places in a fixed order (straight behind, the back diagonals, the sides, further behind, the front; mirrored when `preferBehind` is false), each `clearance` times its factor away: a place passes when `NavMesh.SamplePosition` (0.6 m) finds ground within 1.2 m of the origin's height, the floor ray (`MASK_WORLD`) finds the floor, a 0.3 m capsule from 0.45 to 1.45 m touches no world geometry and no world geometry lies on the line from 1 m above the origin to 1 m above the place. When none passes the result is false, `spot` is the origin and `tried` is the count. The order is pure (internal, `Core/StandSpots.cs`); nothing is allocated.
  `TrySnap(position, reach, out snapped)` is the nearest walkable ground on the navigation mesh within `reach` (`NavMesh.SamplePosition`, every area; false and the position itself when there is none).   dynamic range (32767 up): `SNet_Replication.ReconstructIds`, which runs after a checkpoint reload, counts keys by the replicator's
  type, so a self managed replicator in the dynamic range is not counted, the dynamic counter falls back below it, and the next dynamic
  allocation takes its key (the game logs "Replication Key collision!") and the pickup's state, its amount included, goes to the wrong
  replicator. The pickup's culler gets no cull bucket (the game's culling job, `C_Culler..ctor`, reads the level's zone objects above the
  pickup and throws without them), so the game logs "tried to MoveToNode() but CullBucket was null" once per pickup and the pickup is not
  culled. `Items.Spawned` is raised after every other patch of `OnItemSpawn` (`Native/ItemSpawnHook.cs`).
- **Frame.** `Frame.OnUpdate(modId, callback)`, `OnLateUpdate` and `OnQuit` add a callback to a `FrameBook` (Core) that ForgeCore's one driver runs: `Update` after the network tick, `LateUpdate` (after the game's animation), and `OnDestroy` at shutdown, each in registration order. A callback that throws is one `ErrorOnce` line under that mod's ID and kind (`update`, `late update`, `quit`); the other callbacks and the next frame run as usual. A callback registered during a frame first runs on the next one. No mod adds its own `MonoBehaviour`: state lives in plain static classes and the callback is a static method (the delegate is made once, so a frame allocates nothing). There is no per-callback timing.
- **Patches.Lazy.** `Patches.Lazy(modId, install)` returns a `LazyPatches` for hooks that serve one rarely used feature (an energy gun in hand, a suit worn). The first `Ensure()` runs `install` once with a `Harmony` for `modId`; later calls return at once, also after a failure. A throwing `install` is one `ErrorOnce` line and the feature stays unpatched. Patches stay on, for the reason under Patches below.
- **StrictJson.** Pure (`Once/`). Every method takes the object's own path prefix (empty at the root, `"Shield."` inside `Shield`) and names the field as prefix + name in a `StrictJsonException`. `OnlyKnown(value, prefix, known, alsoAllowed, owner)` refuses a non-object, a member in neither list (the message lists `known`) and a member written twice. `Number` and `Integer` (`min`..`max`, bounds included; a whole number for `Integer`), `Bool`, `Enum<T>` (exact member name, no number), `Reference` (a persistentID or a block name) and `Object` read one member; a missing member returns the fallback, or is "required" when there is none; a wrong type or a value outside its range is refused, never clamped. `Canonical` writes members sorted by name with every number in one spelling (coefficient and exponent, no rounding) and strings escaped by the default serializer, so equal content is equal text; ForgeOrdnance hashes it into its definition set hash.
- **Fnv.** `Hash32` and `Hash64` over UTF-8 text or bytes; `Mix32` and `Mix64` feed one byte for callers that hash a record; `Mix32(h, uint | int | ulong)` and `Mix64(h, ulong | long)` feed an integer as its little-endian bytes and `MixUtf8(h, text)` feeds the UTF-8 bytes of a string without allocating (equal to `Hash32` / `Hash64` of the text from the offset basis, a lone surrogate being U+FFFD). The algorithm is part of wire formats and saved keys (`Net` fingerprints, ForgeOrdnance payload and look keys, ForgeAudio network names, EnergyLab gear IDs, the Frames spec key), so its output never changes; the tests lock the published vectors.
- **Session.** `Session.IsHost` is the game's `SNet.IsMaster` read from two numbers ForgeCore keeps current (`GameEvents.Master`, `Session.LocalLookup`, both set from the game's `OnMasterChanged`, session-reset and join/leave events and from `SNet_SyncManager.OnFoundMaster`, `GameHooks.MasterFound`, which is the only one after a lone host's session found its host), so asking costs no game call; at a host migration it flips together with `GameEvents.MasterChanged`, and a `MasterChanged` handler already reads the new value. `HostLookup` and `LocalLookup` give the two lookups; everything is 0 / false with no session. Packages use it instead of reading `SNet.IsMaster`; `SoloDrop` still reads the game's own value because it runs while the session is being created.
- **Players (roster and warp).** `Players.WorldCamera()` is the camera the picture comes from (the game's current camera while active, so a dead player watching a teammate or a scripted shot is followed; else the local first-person camera; else `Camera.main`): effects, sound and HUD placement read the view from it, never from the local player's body. `Players.Local` / `LocalAlive` are the local agent (null when empty, collected, or dead for `LocalAlive`). `Players.Each(visit)` and `Players.Each(state, visit)` walk the level's live player agents as `PlayerInfo { Agent, Lookup, Slot, IsLocal, IsBot, Name }` (`Name` is read from the game only when asked for); with a static lambda nothing is allocated. `Players.Joined` / `Left` raise a `SessionPlayer { Lookup, IsBot, IsLocal }` when the session lists or drops a player (its agent may not exist yet). `Players.Warp(agent, dimension, position, forward, mode)` calls the game's own entry and reads the position back: `WarpMode.Synced` is the host's `RequestWarpToSync` (replicated, any live agent in one of its `m_warpableStates`), `WarpMode.Local` is `TeleportTo` for this machine's own agent (not replicated, same dimension, camera turned to `forward`). A wrong side, a dead or unwarpable agent, a dimension mismatch or no agent is refused by name before the game is called (`WarpRefusal`, rules in the internal `Core/WarpGate.cs`); `WarpResult.Landed` is true only when the agent reads within `WarpTolerance` (0.5 m) of the request, so an accepted warp that did not land is reported as such. The caller brings a landing from `PlayerAgent.SampleWarpPosition`.
- **Store.WriteText.** `Store.WriteText(path, text)` writes any text file atomically (UTF-8 without a byte order mark, a temporary file beside it, then a replace; the folder is created; an `IOException` family exception is the caller's to handle). `Store.Write<T>` uses it.
- **Active expedition.** `Level.TryActiveExpedition` gives the numbers; `Level.ActiveKey` the game's key string (a new string per read, so compare the numbers first and read the key when they change). A package that needs to know when the choice changes subscribes to `GameEvents.ExpeditionSelected` instead of polling.
- **Png.** Pure (`Once/`). `Png.TrySize(bytes, out width, out height)` reads the PNG signature and the IHDR size and is false for anything else; `Png.TryJpegSize` reads a JPEG's first frame header the same way. Check it before handing bytes to a decoder, which allocates whatever the header claims; ForgeVisual's `ImageTextures` and ForgeMap's image admission do.
- **Assets.Keep.** `Assets.Keep(asset)` sets `HideFlags.DontUnloadUnusedAsset` on an object a mod holds only in managed code (a texture, mesh, material, pooled root or a loaded bundle asset) and returns it; the game's unused-asset sweep at scene changes cannot see such references. `Assets.Load`, `LoadBytes` and `Get` already keep what they return. `Assets.LoadAsync(modId, path, expectedDigest)` loads a bundle over several frames, after the bundles it depends on: it checks `Assets.Digest(path)` first, and you poll `BundleLoad.IsDone` then read `Bundle` (null, one error logged, when it or a dependency failed). The bundle is not shared or kept; the caller owns it, takes assets with `BundleLoad.LoadAssetAsync` (from the bundle, or the dependency that holds the name) and ends it with `BundleLoad.Unload`. Dependencies follow Unity's standard layout: `Assets.Dependencies(path)` reads the manifest bundle that `BuildPipeline.BuildAssetBundles` writes into its output folder under the folder's name, shipped beside the bundles the same way (no manifest, or one that does not list the bundle: none). A dependency is loaded once for every bundle that needs it and unloaded with the last. `Assets.Digest(path)` is the SHA-256 of the file, or for a bundle with dependencies, over its own and each dependency's SHA-256.
- **Log, Settings, Pool, Store, Assets** as listed in `README.md`. Logging writes errors only: `Error` and `ErrorOnce` (an exact message is written the first time it occurs and never again; a different message from the same place is written too) reach the mod's BepInEx log source, and nothing else is written (`Log.Num(value)` and `Log.Pos(x, y, z)` / `Log.Pos(Vector3)` format a number with at most two decimals and a position with two, always with a dot). A failed feature, or data or configuration that leaves something unusable, is an error; progress, state changes and recoverable conditions are not logged. There is no debug mode or log switch and no `Info` or `Warning`. An error that carries an exception writes the whole exception (`error.ToString()`), not its `Message`. A state a player or the game can legitimately be in (a player without the mod, an enemy that has just left) is not logged.

- **Puppets.** `Puppets.Playback` says the level only shows a recording; the package that plays it (ForgeReplay) sets it from the moment the recording's level is asked for until the playback ends. ForgeEngine adopts no plan in such a level (no trigger has a subscriber, nothing is dispatched, no zone is judged) and reads the plans again for the next level; a plan reload is refused there. `Puppets.IsPuppet(EnemyAgent)` and `IsPuppet(PlayerAgent)` say whether the agent is held now (one set lookup, none while nothing is held); ForgeEnemy's scream that clears immortality skips a puppet, its ability-use action refuses a puppet and refuses everything in a playback level, and ForgeMap judges no trigger zone and runs no object or device action there. `EnemyPuppet.Stance(state, variant)` follows the game's locomotion state read each frame: sleep is the game's hibernation state; waking, a ladder and a leap are the animator's states played directly, because `ES_HibernateWakeUp` would wake the sleepers around it. An action's state that returns to walking by its own timer ends the action there. An action's length runs on `Time.time`, so a time scale of 0 holds it; `Settle()` ends it at once (a jump in time). The wake-up pose's `HibernateWakeUp` sets the AI to aggressive; that is put back without counting it. `Stance(state, variant, turn)` plays the recorded wake-up animation (the turning set when `turn`); a pose set while the animator is held (rate 0) is advanced once so it shows. Asleep, the puppet stays in the game's hibernation state: when the game leaves it, `Drive` puts it back and counts it in `Retaken`. `Heartbeat(strength, sensed)` is the sleeper's own `ES_Hibernate.DoHeartbeat` (glow and sound) and `Detecting(on)` its `DoStartDetection` / `DoEndDetection` (the sensing glow), on change only and only while asleep. `Drive` also moves the agent's position and its `C_MovingCuller` (`UpdatePosition`) when it moved more than 1 cm, so its shadow, lights and culling follow the puppet. While an enemy is held, the launches its attack states make on the host (`EAB_ProjectileShooter.FireBurst`, `EAB_MovingEnemeyTentacle.Attack`, `EAB_MovingEnemyTentacleMultiple.Attack`) are skipped (module `Puppets.AttackHold`); the attack's voice and timers still run. `PlayerPuppet` puts a downed player back into `PLOC_Downed` when the game left it (at most twice a second, counted in `Reentered`, not logged). `CameraLease.Look` looks the view's room up itself: `Dimension.TryGetCourseNodeFromPos` at the view, then at the floor under it (a 40 m ray on `LayerManager.MASK_WORLD`), then at the given point, else the last room; again when the view or the point moved 1 m and every 0.25 s; `SetCurrentNode` and the agent's `m_position` and `lastCrossCheckPos` every frame. Not `UpdatePosition` and `RefreshNode`: the first does nothing while the agent has no room and checks portal crossings from its last place, so a view that jumped got a room along that line or kept a far one. `PlayerPuppet.MeleeSwing(charged)` and `MeleeCharge()` are the remote-player entry `MeleeWeaponThirdPerson.ReceiveClassItemSync` (its animation and swing sound). `PlayerPuppet.Say` is `PlayerVoice.SayLine`; `WorldStates.ZoneLights(modes, instant)` is `EnvironmentStateManager.UpdateAllLightModes`. `PlayerPuppet.State` also takes `OnTerminal`, `GrabbedByTank` and `ClimbLadder` (`PlayerSync.IncomingClimbLadder` with the nearest player ladder). `Puppets.Enemy(enemy, owner)` holds an enemy as a puppet (`EnemyPuppet`): `AI.Mode = Off`, `AI.SetNavMeshAgent(false)`, the `NavMeshAgent` component and `Anim.applyRootMotion` off, `Dam_EnemyDamageBase.IsImortal` on (the damage limbs stay, it can still be aimed at), `ForceNoAnimationCulling` on, and `Locomotion.ChangeState(StandStill)` so the animator leaves the hibernation pose. `Attack`, `Hitreact` and `Scream` put the enemy in the game's own state for that action and set `Acting`; the puppet re-asserts its control right after entering the state (root motion stays on while the action plays) and again when the action ends and the enemy is sent back to walking, so these state changes are not counted as the game taking the enemy back. `Drive(position, rotation, velocity, seconds)` (call it in `Frame.OnLateUpdate`) sets the transform and writes the game's own animator inputs `EnemyLocomotion.s_hashMoveOnGround`, `s_hashForward`, `s_hashRight` (the world velocity in the enemy's frame, `PuppetMotion.Local`; smoothed with the locomotion's `MoveAnimDampTime`). Every `Drive` checks that the AI mode, nav mesh, root motion and immortality are still as set; if the game changed one, it is set again, `Retaken` goes up (counted, not logged: it is expected). `DestroyLimb(limbId, instant)` calls the limb's own `Dam_EnemyDamageLimb.DestroyLimb` (what `Dam_EnemyDamageBase.ReceiveDestroyLimb` does on a client: the destruction shows, no damage is settled); `instant` leaves the custom limb's `m_effectOnDestroy` out for that call. `Feelers(spread, remove)` shows a scout's feelers: out is the scout state's own `ES_ScoutDetection.SpawnAntennaDetection` (the game's head height, random seed and spread) with an empty target list (`SetTargets`), so the tendrils find nobody and come back by themselves; back is `SetState(PullingBack, false)` as the state's exit does; `remove` despawns them (a jump). `Rate` sets the animator speed (0 freezes and switches the animator off, keeping its state, so nothing moves it while paused), `Die()` ends the immortality and calls `InstantDead(true)` (the game's death animation or ragdoll), `Dispose()` restores AI mode, immortality, root motion, culling flag, nav mesh and animator speed. `Puppets.Player(agent, owner)` holds a non-local `PlayerAgent` (a bot). A single-player expedition (`ExpeditionInTierData.IsSinglePlayer`, which `PlayerManager` spawns no bots for) with bots asked for fails before the lobby opens.

Nothing is replicated and no game rule runs. `ClearFog()` shows the game's no-density fog block (`NoFogId`, the elevator ride's) on this machine only; `LevelFog()` puts the level's own back. Level machines: Bulkhead, Hsu, Portal, GeneratorCluster, FogTurbine and ScanMove run the machine's OnStateChange with its replicated state as the old one and the named fields changed (the matching *Status / *Step / *State readers give the state it holds now); HolopathReveal reveals a holopath (Reveal, or fully drawn at once with instant); Spitter runs the bodies of the spitter's explode and glue packets.

### Recording (observation port: `Core/Observers.cs`, `Native/Recording.cs`)

The Visual and Audio parts report every effect, line, held effect, beam, trail, decal, model and sound they put in the world to `Recording`, at the point every call of their kind passes; the reporting members are internal to ForgeCore. Any number of observers hear them: `Recording.Observe(IShownObserver)` returns an `IDisposable` that removes it; observers are called in the order added, on the main thread, inside the library call, and must not throw (one that does is logged once and stays) and should not allocate.

- While nobody observes a report site costs one field read; the library builds no struct, looks nothing up, allocates nothing.
- Names are integers, taken once when a library makes its handle and never changing in the process; 0 is no name. `RecordingNames.Name(id)` gives the text of a number and `RecordingNames.Count` how many there are; an observer turns them into its own table (an array, not a dictionary).
- An observer reads the fields of `ShownEffect` (kind, name, hold key, at, to, size, colour, head, seconds, fade, look object), `ShownSound` (name, place, at, picked variant and pitch, gain, self, loop number), `ShownModel` (spawned, hidden, shown) and `ShownPose` (start or stop, anchor, track, clip name number, seconds in, loop, weight, fade in and out, per-joint mask weights valid during the call); only ForgeCore builds them. `Recording.Anchor(Transform)` says what a transform hangs on (player agent, enemy agent or world, and the node when it is not the root).
- Poses: the Visual part's `JointPlayer` reports every clip that has a name (`JointClip.Read(file, name)`) on a body bound with `Models.BindJoints(player or enemy)`; a clip without a name, a first-person arms clip, a body that hangs on no player or enemy and a body posed some other way are not reported. Only the name, the start and the play options travel, so the observer needs no bones and a replay finds the clip by `JointClip.Find(name)`. A pose copied from the game's body every frame (`PoseCopy`) is derived from what the replay already animates and is not reported.
- Notes: `Recording.Note(modId, kind, payload = "", mark = false)` writes a note of a mod's own into the recording being made, so a mod needs no reference to the recorder (ForgeReplay stores it as event 101 and offers it back as `ReplayEvents.OnNote`, on the replay timeline when `mark` is set, and in the exported statistics `notes`). `modId` and `kind` are required; a recorder cuts them to 200 and the payload to 1024 UTF-8 bytes. `Recording.ObserveNotes(Action<RecordingNote>)` is the recorder's side and returns an `IDisposable`; a listener that throws is logged once and stays. Every machine records what its own mods note, host and client alike; nothing happens while no recorder listens.
- Inside ForgeCore one many-observer list (copy-on-change array) carries these reports; a further report of this kind uses it instead of a single callback field.

## Quick start

This is the one way to depend on any part of the library, UI, Audio and Visual included. Add `NAinfini-ForgeCore-1.0.0` to the `dependencies` of your `manifest.json` and `[BepInDependency("NAinfini.ForgeCore")]` to your plugin. Reference the DLL (do not copy it into your package) and the game assemblies your code uses:

```xml
<ItemGroup>
  <Reference Include="$(GTFOBepInExPath)/plugins/NAinfini-ForgeCore/ForgeCore.dll" Private="false" />
  <Reference Include="$(GTFOBepInExPath)/core/BepInEx.Core.dll" Private="false" />
  <Reference Include="$(GTFOBepInExPath)/core/BepInEx.Unity.IL2CPP.dll" Private="false" />
  <Reference Include="$(GTFOBepInExPath)/core/Il2CppInterop.Runtime.dll" Private="false" />
  <Reference Include="$(GTFOBepInExPath)/interop/Il2Cppmscorlib.dll" Private="false" />
  <Reference Include="$(GTFOBepInExPath)/interop/Modules-ASM.dll" Private="false" />
  <Reference Include="$(GTFOBepInExPath)/interop/UnityEngine.CoreModule.dll" Private="false" />
  <Reference Include="$(GTFOBepInExPath)/interop/Unity.TextMeshPro.dll" Private="false" />
  <Reference Include="$(GTFOBepInExPath)/interop/UnityEngine.UI.dll" Private="false" />
</ItemGroup>
```

The last two are needed only by code that touches the UI part's `TextMeshPro` or UI types (for example `HudElement.AddText`); a mod that only registers through its other members compiles without them.

Every call takes your plugin GUID as the mod ID.

```csharp
using ForgeCore;

[BepInPlugin(Id, "My Mod", "1.0.0")]
[BepInDependency("NAinfini.ForgeCore")]
internal sealed class Plugin : BasePlugin
{
    internal const string Id = "me.mymod";
    private static NetChannel _net = null!;
    private static NetEvent<Ping> _ping = null!;

    public override void Load()
    {
        _net = Net.Open(Id);                            // a player whose messages differ is refused on both sides, with a log line naming them
        _ping = _net.Event<Ping>("ping", (sender, ping) => Handle(sender, ping.Value));
    }

    // The handler runs when the message arrives; send from anywhere on the main thread.
    internal static void Tick() => _ping.Broadcast(new Ping { Value = 1 });
}

[StructLayout(LayoutKind.Sequential, Pack = 1)] internal struct Ping { public int Value; }
```

## UI (namespace `ForgeUI`)

### Layering: what this part holds and what it does not

ForgeUI holds on-screen interface mechanisms: lobby buttons and cells, pickers, menu pages, HUD zones, templates, boot sequences, screen-edge overlays, visors, damage indicators, world markers and countdowns, location readouts, hiding and redrawing the vanilla HUD, a screen effect stack, enemy health bars, drawing helpers and translations. It holds no look or wording of its own: appearance, text, colours and icons belong to the mod that adds them and are passed in through the API. A mechanism other mods may use goes here without waiting for a second user.

### Folder layout

| Path | Contents |
|---|---|
| `UI/Core/` | Plain logic with no Unity reference: layout, easing, queues, command codes, screen math. |
| `UI/Native/` | The game side: lobby buttons, pickers, menu bar, HUD, templates, screen layers, language. |
| `lang/` | The kit's own texts, one `<language>.forge` per language. |
| `UI/tools/screen/` | `build_screen_shaders.ps1`: builds the power-on and screen effect shaders into `Assets/Shaders/*.shaderbundle` (embedded in the DLL) with Unity 2019.4.21f1. |
| `UI/tools/fonts/` | `build_fonts.ps1`, `make_symbols.py` and `FontBundleBuild.cs`: make ForgeUI Symbols (the kit's own ∞, U+221E, drawn to Rajdhani's digits; needs fontTools) and build the six font files into `Assets/fonts/ForgeUI-fonts.bundle` (local only) with Unity 2019.4.21f1. |
| `Assets/fonts/OFL-*.forge` | The two fonts' licences, shipped in `fonts/`. |

### Fonts

The font bundle is built once before the first package (take `artifacts/work/unity-lock.txt` first; Unity runs outside the sandbox):

```
pwsh Mods/ForgeCore/UI/tools/fonts/build_fonts.ps1 -Latin <folder with Rajdhani-Medium.ttf, Rajdhani-SemiBold.ttf> -Chinese <folder with GlowSansSC-Condensed-Medium-common.ttf, GlowSansSC-Condensed-Bold-common.ttf>
```

Rajdhani comes from google/fonts (`ofl/rajdhani`), Glow Sans SC Condensed from welai/glow-sans 0.93 (`GlowSansSC-Condensed-*-common`). Unity
only imports them as dynamic fonts; the TextMesh Pro font assets are made in the game by the game's own TextMesh Pro, so no
TextMesh Pro version is baked into the bundle.

### Quick start

With the dependency set up as under Quick start above:

```csharp
using System.Collections.Generic;
using BepInEx;
using BepInEx.Unity.IL2CPP;
using ForgeUI;

[BepInPlugin(Id, "Hello", "1.0.0")]
[BepInDependency("NAinfini.ForgeCore")]
public sealed class HelloPlugin : BasePlugin
{
    public const string Id = "Me.Hello";

    public override void Load()
    {
        var ui = UIKit.Mod(Id);                        // every registration of this mod goes through its handle
        // A lobby button under APPAREL that opens a picker.
        ui.AddLobbyButton("Colour", "COLOUR", bar => UIKit.TogglePicker(bar, Colours.Instance));
        // A top menu bar button with a page.
        ui.AddMenuBarPage("Guide", "HELLO", page => page.AddText("Pick a colour in the lobby."));
        // A line on the in-level HUD, in the region under the weapon list (priority 10, 300 x 30).
        ui.AddHud("Line", new HudSlot(HudRegion.WeaponList, 10, 300, 30), hud => hud.AddText().SetText("COLOUR " + Colours.Instance.Chosen));
        // A banner in the shared queue: it waits behind stronger banners of any mod instead of covering them.
        ui.AddBanner("Banner", priority: 10)?.Show("HELLO");
    }
}

public sealed class Colours : PickerSource
{
    public static readonly Colours Instance = new();
    private static readonly PickerCard[] Cards = { new() { Title = "RED" }, new() { Title = "GREEN" }, new() { Title = "BLUE" } };
    public string Chosen = "NONE";

    public override int SlotCount => 1;
    public override PickerCard SlotCard(int slot, bool chosen) => new() { Subtitle = "COLOUR", Title = Chosen };
    public override IReadOnlyList<PickerCard> Entries(int tab) => Cards;
    public override string? Pick(int slot, int tab, int entry)
    {
        Chosen = entry < 0 ? "NONE" : Cards[entry].Title;
        return null;
    }
}
```

Buttons, pages and HUD lines look like the game's, follow resolution changes, and are rebuilt when the game rebuilds its menus or HUD.

### Joining the shared layout

1. Take your handle once in `Load`: `var ui = UIKit.Mod(YourPlugin.Id);`. Your registrations are named `YourPlugin.Id/name`, so two mods can both have a "Banner".
2. For each HUD element, say where it belongs and how much it matters, not where to draw it: `new HudSlot(region, priority, width, height)`. The kit stacks all mods' elements in each region by priority, keeps them off the game's weapon list and health bar, and folds away the weakest when a region is full. Use `hud.Resize(w, h)` when your content changes.
3. Use the shared pieces instead of your own: `ui.AddBanner(name, priority)` for big centre text, `ui.AddNotices(name)` for corner messages, `ui.AddPowerOn(name, spec)` for a power-on that covers the screen.
4. An element the layout cannot place (its region is full) is folded away without a log line and read from `HudElement.State` (`Collapsed`).

### Rules

- Call everything from the main thread, from your plugin's `Load` or later.
- `UIKit.Mod(modId)` takes your mod ID (letters, digits, `.`, `_`, `-`, no `/`) and returns the same handle every time. An invalid ID throws. Names are unique inside your mod, stable, and have no spaces or `/`. The full ID is `modId/name`, at most 128 characters. An empty, spaced or taken name returns null and logs why.
- Every `Add...` returns a handle. `Remove()` takes it off. An old handle never removes a newer registration with the same ID.
- An exception in your callback is logged with your full ID and never reaches the game or other mods.
- Titles, card texts, notes and tab names show exactly as written (after a key is looked up); `<` is not read as a tag. Picker details (`PickerInfo.Body`), page text and HUD text accept TextMeshPro rich text.
- The library has no audio. Presses on its buttons, slots and cards do not reach the game's own handlers, so the game plays no click. Play your own from `onClick`, `PickerSource.Clicked` or the page's `clicked`.
- The game is patched only for the features you use, the first time you use them (clicks, menu bar, menu pages, picker, settings page, gear names and icons, hiding the game's HUD, weapon list, enemy health bars, local hits, teammate overhead lines (`PatchGroup.Markers`), and each game readout when `UIKit.<readout>` is first read: `Vitals`, `Inventory`, `Objectives`, `Interaction`, `Subtitles`, `Intel`, `Boosters`, `Pickups`). A hook that is on stays on. A readout read for the first time catches up with the game's current state.
- Per-frame work runs as ForgeCore `Frame.OnUpdate` / `Frame.OnLateUpdate` callbacks (the late one after every mod's `Update`); the kit adds no component to the scene.

### Texts in several languages

Put one file per language in `lang/` beside your DLL, each a flat JSON object of key to text, and ship the folder in your package:

```
lang/en.forge   { "button": "COLOUR", "picked": "Picked {0}" }
lang/zh.forge   { "button": "颜色", "picked": "已选 {0}" }
```

`en.json` is required; adding a language is adding a file. Codes are lower case: `en`, `zh`, `zh-hant`, `fr`, `it`, `de`, `es`, `ru`, `pt-br`, `pl`, `ja`, `ko`.

```csharp
var ui = UIKit.Mod(Id);
ui.AddLobbyButton("Colour", UIText.Key("button"), bar => UIKit.TogglePicker(bar, Colours.Instance));
ui.AddMenuBarPage("Guide", UIText.Key("guide.title"), page => page.AddText(UIText.Key("guide.body")));
dash.Label = UIText.Key("dash");                 // HUD pieces resolve keys every time they draw
string line = ui.Text("picked", colourName);      // a string in the current language, for your own text
UIKit.LanguageChanged += Rebuild;                 // rebuild anything you composed from strings yourself
```

- Anything that takes a `UIText` takes a plain string as before (shown as written) or `UIText.Key(key, args)`. Keyed titles, pages, labels, hint lines and command lists switch the moment the language changes; an open menu page is rebuilt in place. Banners and notices resolve when pushed.
- `ui.Text(key)` and `ui.Text(key, args)` read your `lang/`; `UIKit.Texts(folder)` gives the same for another folder (a definition pack's). `TryText` returns false without logging, for optional texts.
- The language is the `Language / Language` setting: `Auto` (the default) follows the game's language, or a code forces one. `UIKit.Language` is the code in use.
- A key missing in the chosen language falls back to `en.json` and logs one error; missing there too, the key itself is shown. With no file for the chosen language, the whole mod shows English and warns once.
- Files are read once, on first use, and checked against `en.json`: duplicate keys, broken files, missing or extra keys and different `{n}` placeholders are logged. After that a lookup is a dictionary read; texts with no arguments allocate nothing.

| Region | Grows from | Up to |

| `CenterBanner` | A little above the middle of the screen; one slot | One element at a time |
| `TopCenter` | The top edge, centred, downwards | A little above the middle |
| `Notices` | The top left, below the game's own messages, downwards | The middle |
| `RightColumn` | The right edge, a quarter screen above the middle, downwards | A little below the middle |
| `BottomLeft` | The bottom left corner, upwards | A little below the middle |
| `BottomRight` | The bottom right corner, upwards | Half way between the middle and the top |
| `TopRight` | The top right corner, right-aligned, downwards | A little above the middle |
| `World` | The middle of the screen; not laid out (markers, hit ticks, damage numbers) | |

Each frame, every region stacks its visible elements from all mods by priority (higher first, ties by full ID) with a 12-unit gap. The game's weapon list and health area are occupied first. An element that would overlap them, or another element, moves past it. An element that would pass the region's limit, or a single-slot region held by a stronger one, is folded away (an expected outcome, not logged). The layout uses the larger of your declared size and what the element draws.

`new HudSlot(region, priority, width, height, space: s)` leaves `s` more units (default 0) between the element and the one it follows in its region, on top of the region's gap (a line takes its members' largest). `new HudSlot(region, priority, width, height, row: n)` with `n` above 0 puts the element on a shared line: the shown elements of one region with the same row stand side by side from the corner outwards (highest priority nearest the corner) on the edge the region grows from, the line takes the height of its tallest member and stacks like one element, and a line that does not fit folds away whole. While a mod hides the game's weapon list and an element marked `Entry.WeaponListStandIn` (the kit's loadout) is shown, `WeaponList` elements stack on past everything in that element's region instead of keeping the empty corner; `Entry.BesideStandIn` says so, and the command list then takes the loadout's row style.

### Wheel

A radial choice in the middle of the screen, opened by one of your key actions. Hold the key: the wheel opens with a pointer in its centre; the slot under the pointer lifts out and lights in the accent colour with a thicker rim, its name shows in the centre, and a row of cells there shows the page; let go to do it.

### Ready-made HUD pieces

Each `ui.Add...` registers a HUD element in its default region and returns a handle (null and a logged reason when the name is taken). The optional `slot` argument takes a `HudSlot` to change region, priority or size. `Visible` and `Remove()` are on every handle.

ui.AddHintLine("Hint").Set(HintPart.Word("Hold"), HintPart.Key("F"), HintPart.Word("to revive"));

### Key actions

Keys your mod reads are registered once at load and read every frame through the handle; the player changes the key and the trigger mode in the game's own settings (Controls), where they are listed under one FORGE heading and your group's heading after the game's keys.

```csharp
// lang/en.forge { "keys.group": "My Mod", "keys.dash": "Dash" }
var dash = ui.AddKeyAction("Dash", "keys.dash", "keys.group", "LeftShift", KeyMode.Press, "on-foot");
if (dash!.Pressed) Dash();                         // per frame: no lookup, no allocation
ui.AddKeyHint("DashHint", dash, UIText.Key("keys.dash"));   // the prompt shows the player's key
```

- **Saved keys.** `BepInEx/config/NAinfini.ForgeUI.keys.cfg`, one line `<mod>/<action> = <key>` per changed key (`None` for unbound) and `<mod>/<action>#mode = <mode>` per changed trigger mode, `<mod>/<action>#hold = <seconds>` per action with its own long-press time, `<mod>/<action>#double = <seconds>` per action with its own double-press time and `<mod>/<action>#game = Both` per action set to fire together with the game, read when ForgeCore loads, written at each change. - **Conflicts.** Two actions on one chord with overlapping contexts whose same press would fire both are shown in the settings (a `Tap` and a `Hold` action share a key without conflict while the tap's time is not longer than the hold's: a long press never fires the tap, and the tap is decided when the key comes up; a `Tap` and a `Double` action share a key too: the tap waits out the longest double-press time of the `Double` actions on its key after the key comes up and a second press within it cancels the tap, so a double press never fires the tap but a short press fires it that much later; a `Hold` and a `Double` action, and two of a kind, conflict); so is a game key equal to the chord's main key (the game key fires whatever modifiers are held), except a game button the action hands back (below). A short R still reloads; a long press never fires the game's action first. Game axes (movement, look) cannot be handed back and stay a conflict. The player can set an action to fire together with the game instead (the row "On a key the game also uses"): nothing is held off, the game reads its key untouched, and the settings show the conflict. - **Settings rows (game facts).** The game builds its settings in `CM_PageSettings.Setup`: each sub-menu is a `CM_ScrollWindow` in `m_allSettingsWindows`; the keyboard and mouse key page (`eSettingsSubMenuId.KeyMap`) lists `CM_SettingsItem` rows, each holding a `CM_SettingKeyBindingField` (`m_data` is the game's `InputMapData`, `device` Keyboard or Mouse; the gamepad page's are Gamepad; `m_valueText`, `m_background` with `m_bgActive` / `m_bgNotActive`, `m_readingActive`; it reads keys itself in `Update` and writes them through `iKeyBindingInputReceiver`). The copies' field methods (`Update`, `OnEnable`, `OnBtnPress`, `OnBtnPressAnywhere`, `OnHoverUpdate`, `OnHoverOut`, `UpdateValueField`, `UpdateText`, `ResetValue`, `SetReadingActive`, `SetupInputItem`) and the rows' `OnEnable` / `UpdateText` are skipped, so the game's reading never touches its own bindings for them; ForgeUI reads the key (it waits for every key to be up, Esc cancels, Backspace or Delete unbinds) and writes the box. `CM_PageSettings.ResetPageSettings(KeyMap)` (the page's reset) also resets every action. ### Screen layers

### Notes

- Everything is parented to the game's own UI objects and copies their layer. The menu camera is disabled and drawn by the game's UI pass, so a check such as "no enabled camera draws layer 5" is expected and does not mean something is invisible.
- Do not move pieces to another layer or parent them outside the game's UI.
- `Auto` reads the game's language from `Localization.Text.TextLocalizationService.CurrentLanguage` (`Modules-ASM`, enum `Localization.Language`: English, French, Italian, German, Spanish, Russian, Portuguese_Brazil, Polish, Japanese, Korean, Chinese_Traditional, Chinese_Simplified), four times a second. A mod's `lang/` is found from its plugin's DLL location in the BepInEx chainloader.

### Drawn ahead of first use

The screen effect stack is warmed with the other screen layers (`ui.WarmNextLayer()`, `HitEdge.Warm()`, `Visor.Warm()`, and on its own on the elevator ride): it loads its shader, builds the hit band and interference textures and draws its pass once off screen in both variants (with and without the screen copy), so turning blur on later compiles nothing.

### Logging

Logging goes through ForgeCore's `ModLog` and only real failures are written: `Plugin.Error` takes a message and uses its text up to the first colon as a short fixed key, so a given failure is written once. Expected limits and refusals (a full HUD region, a full pool, a full confirmation queue) write nothing. The library has no info, warning or timing log calls and no diagnostics setting.

### Player marker

`UIKit.Ping(player, point)` places the game's own player marker (the middle-mouse one, synced by the game), `UIKit.ClearPing(player)` removes it and `UIKit.AimPoint(out point)` reads where the crosshair ray hits; it returns false when it hits nothing. `UIKit.GameScreenOpen` says a map or terminal has the player's attention.

## Audio (namespace `ForgeAudio`)

Drop Ogg files and a `cues.forge` in a folder next to your DLL, load it with one line, and play by cue name. 2D, positioned and following sounds, volume values, voice limits and wall occlusion are handled for you. Every mod using the kit shares one mix: global categories with one voice limit each, ducking across mods, and one master and per-category volume in the game's own audio settings. The kit also plays a sound for every player in the session and picks a volume and pitch per play from a range.

### Layering: what this package holds and what it does not

ForgeAudio holds sound mechanisms: playing plain audio files by cue, 3D positioning, mix categories and global limits, occlusion, long-running sounds, plays every player hears, and replacing or muting vanilla sounds (player body sounds, weapon action sounds). It ships no sounds. Your audio files and `cues.forge` stay in your mod; load them once and decide when to play and what to replace. A reusable mechanism goes here even before a second mod needs it.

    engine.ogg
    cues.forge

  "buses": {

    "blast": { "category": "explosion", "duck": { "categories": ["debris", "ambience"], "db": 6 } },
    "motor": { "category": "vehicle" }

  "cues": {
    "click":     { "bus": "menu", "place": "2d" },
    "explosion": { "bus": "blast", "priority": 200 },
    "engine":    { "bus": "motor", "loop": true }

### Joining the shared mix

1. Load with your plugin ID. Your cues are `Plugin.Id/cue` in every log line, so two mods can both have a `click`.
2. Group your cues into buses and map each bus to one of the global categories (`ui`, `weapon`, `explosion`, `debris`, `ambience`, `voice`, `vehicle`, `device`, `music`). Pick by what the sound is, not by which mod plays it.
3. Your own limits (`maxVoices`, `maxPerEmitter`, `minInterval`, bus `seats`) apply first. The category limit applies on top, over every mod's sounds of that category. When a category is full, the weakest sound of any mod is pushed out for a stronger or nearer newcomer. Otherwise the newcomer is refused. Give important sounds a higher `priority`.
4. Duck categories, not your own buses: `"duck": { "categories": ["debris"], "db": 6 }` lowers every mod's debris while your bus plays.
5. Do not add a volume setting to your mod. Players set the kit's master and category volumes in the game's audio settings (a package adds the rows, see below).

#### Volumes

The kit's volumes (the master and one per category) are `AudioVolumes`: `Master`, `Get(category)` / `Set(category, value)` (0 to 1, the cues.forge category names), `ResetAll()` (everything to full, saved at once) and `Controls` (the master, then the nine categories: `VolumeControl` with `Id`, `TextKey`, `Get`, `Set`; `HeadingKey` names the group; both are keys of the UI part's language files in `lang/`). A change applies to every mod's sounds the same frame and is saved to `BepInEx/config/NAinfini.ForgeAudio.cfg` (`Volume / Master` and one entry per category) half a second later. A category's volume is the game's master x the slider it follows (Music, Dialogue or SFX) x the kit's master x the category's value.

ForgeCore lists the volumes in the game's Settings, Audio page itself, in its `Load` (`SettingsPages.AddAudioSliders` with the section id `ForgeAudio.volumes`); a package does not add them.

### `audio/cues.forge`

The file has two sections: `buses` (groups, each mapped to a global category) and `cues`. Every cue plays on a bus.

```json
{
  "buses": {
    "boom":   { "category": "explosion", "gainDb": -2, "seats": 3, "duck": { "categories": ["debris"], "db": 6 } },
    "debris": { "category": "debris", "seats": 2 },
    "ui":     { "category": "ui" }
  },
  "cues": {
    "big_boom": {
      "bus": "boom", "priority": 230, "maxSeconds": 1.8,
      "space": { "near": 8, "far": 180, "curve": [[0, 1], [40, 0.6], [180, 0]], "doppler": 0.5 },
      "layers": [
        { "clips": ["boom-1.ogg", "boom-2.ogg"], "distance": { "max": 40 }, "pitch": [0.97, 1.03] },
        { "clips": ["sub.ogg"], "offsetMs": 60, "gainDb": -4, "fadeOutMs": 300, "distance": { "max": 40 } },
        { "clips": ["rumble.ogg"], "distance": { "min": 40 }, "lowpassHz": 600 }
      ]
    },
    "click": { "bus": "ui", "place": "2d", "maxSeconds": 0.25 }
  }
}
```

A cue with no `layers` plays its own file `<cue>.ogg`. A file that a layer uses is not a cue of its own. A file no cue names is reported as unavailable. Comments and trailing commas are allowed. Files in subfolders are cues named `sub/name`. Cue names ignore case.

#### Cue settings

| Setting | Default | Meaning |
|---|---|---|
| `layers` | the cue's own file | 1 to 8 layers, below |
| `gain` / `gainDb` | `1` / `0` | Cue volume: 0 to 4 linear, or -60 to 12 dB (not both). `[min, max]` picks a volume per play, evenly in decibels (from silence: linearly) |
| `pitch` | `1` | 0.1 to 3, or `[min, max]` for a random pitch per play |
| `loop` | `false` | Loops seamlessly until stopped. A loop has one layer with only `clips` and `gain` |
| `maxSeconds` | none | The longest the mix plays (0.05 to 60 s). It is cut there and fades out over 12% of the length (40 to 150 ms) |
| `bus` | required | The bus the cue plays on. Its category is the bus's |
| `priority` | `100` | 0 to 255. Higher takes a voice from lower, wins a bus seat and a place in a full category |
| `maxVoices` | `8` | How many of this cue may play at once (1 to 256) |
| `maxPerEmitter` | `maxVoices` | How many may play at once from one emitter |
| `minInterval` | `0` | Seconds. A play sooner than this after the last accepted one returns `Throttled` |
| `environment` | `true` | Wall and door muffling for placed sounds |
| `place` | `"auto"` | `"2d"` (in the listener's head), `"world"` (a fixed point), `"follow"` (follows the object and fades out in 150 ms if it is destroyed), `"auto"` (what the caller passed). Or `{ "self": ..., "other": ... }` for the local player's own sounds and everyone else's |
| `space` | below | Distance and spatialisation |

#### Layers

Each layer is one sound inside the cue. `clips` is a pool of variants: a cue has one variant per clip of its largest pool, one is picked per play, and the other layers cycle through their own pools. A random pick never repeats the cue's previous variant (when it has two or more); `PlayOptions.Variant` plays as given. Per-play randomness lives in the cue: `pitch` and `gain` as `[min, max]`; a layer's own `pitch` range is fixed per variant.

| Layer setting | Default | Meaning |
|---|---|---|
| `clips` | required | 1 to 32 files in the folder |
| `offsetMs` | `0` | Start offset inside the cue |
| `gain` / `gainDb` | `1` / `0` | Layer volume |
| `range` | whole clip | `[startSeconds, endSeconds]` of the clip to use |
| `fadeInMs`, `fadeOutMs` | `0` | Fades of this layer |
| `pitch` | `1` | 0.1 to 3, or `[min, max]`, picked per variant |
| `distance` | everywhere | `{ "min": m, "max": m }`. The layer plays only while the listener is inside, so a far layer can replace the near one |
| `lowpassHz` | none | 50 to 20000. A low-pass on the layer, for a distant version made from the same clip |

Clips can have any sample rate or channel count. The mix uses the first layer's rate and is stereo when any clip is.

#### Space

| `space` setting | Default | Meaning |
|---|---|---|
| `near`, `far` | `2`, `30` | Metres. Full volume within `near`, silent beyond `far` |
| `curve` | `"linear"` | `"linear"`, `"log"` or points `[[metres, gain], ...]` |
| `blend` | `1` | 0 hears the sound flat, 1 fully positioned |
| `spread` | `0` | 0 to 180 degrees. Widens the sound, which reduces panning |
| `doppler` | `0` | 0 to 5. Pitch shift from the relative motion of listener and sound |
| `cull` | `true` | Beyond `far` the sound is silent and takes no voice |

#### Buses

| Bus setting | Default | Meaning |
|---|---|---|
| `category` | required | One of the nine categories |
| `gain` / `gainDb` | `1` / `0` | Scales every cue on the bus |
| `seats` | unlimited | How many of its sounds may play at once from one emitter. `1` makes the bus mutually exclusive. A newcomer takes a free seat, else fades out the weakest holder in 60 ms when it has a higher priority (or equal and not much quieter), else it is refused |
| `duck` | none | `{ "categories": [...], "db": 6 }`. Lowers every mod's sounds of those categories while any sound of this bus plays (40 ms down, 160 ms back). The deepest active duck applies |

#### Categories

One limit per category, shared by all mods: ui 8, weapon 16, explosion 10, debris 12, ambience 8, voice 4, vehicle 48, device 10, music 2. At the limit, the weakest sound is faded out in 60 ms and ends with `PushedOut` when the newcomer outranks it (higher priority, or equal and nearer). Otherwise the newcomer is `BudgetRejected`. `music` follows the game's Music slider, `voice` the Dialogue slider, and every other category the SFX slider. The kit's master and category volumes multiply them.

#### Errors

A misspelled or out-of-range cue setting makes only that cue unavailable, with the reason in the log. An unreadable or missing `cues.forge`, an unknown top-level section, a bus without a known category, or a duck naming an unknown category fails the whole folder. A library holds at most 1024 cues and 1 MiB of settings.

#### Observing plays

`AudioLibrary.Find(identity)` returns the loaded library of a mod ID or null. Every valid play (`Engine.Play`, so `Play`, `AudioCue.Play` and `PlayEverywhere`) is reported to ForgeCore `Recording` as a `ShownSound` with the cue's number (`identity/cue`), place, position, picked variant and pitch, gain and self flag, whether or not this machine can hear it; a loop is reported once it has its handle and carries its own number, and its end is reported too. Without an observer the cost is one field read.
#### `AudioCue`: a cue found once, and plays every player hears

| Member | |
|---|---|
| `Play(options)`, `Play(position, options)`, `Play(follow, options)` | As the library's `Play`, without a name lookup per play |
| `PlayResult PlayEverywhere(Vector3 position, PlayOptions? options = null, bool reliable = false)` | Plays here and for every other player in the session at the same point and dimension, with the same variant, pitch and volume (picked here). The result is this player's own play |
| `PlayResult PlayEverywhere(PlayOptions? options = null, bool reliable = false)` | The same in 2D: each player hears it in their own head |
| `bool IsReady`, `AudioLibrary Library`, `string Name` | |

How it travels: the kit sends one message through its own ForgeCore channel (`Net.Open("NAinfini.ForgeAudio")`); your mod registers nothing. ForgeCore's handshake refuses a player whose copy of the kit has another message layout and drops a play sent before a level change, a checkpoint reload or a host change, and the library and cue travel as hashes of their names, so every player needs the same mod with the same cue. Whoever calls it decides: call it on the host for a sound the host decides (an alarm, a boss phase), or on the player who caused it (a throw). Each player hears it as another player's sound (`IsSelf` is false on the others), the moment the message arrives. A player who joins later does not hear plays from before, so a loop is refused: start loops on each player yourself (`Sustain`). `reliable: true` uses the game's reliable channel, for rare sounds that must not be lost; the default is the unreliable one, for frequent presentation. A play refused here for the call itself (throttled, invalid options, the library not loaded) is not sent; one only this player cannot hear (too far, the category full, no listener yet) is.

```csharp
static AudioCue _siren = null!;
public override void Load()
{
    Sounds = AudioKit.Load(Id);
    _siren = Sounds.Cue("siren");          // found once, kept
}

// On the host, when the alarm starts: every player hears the same siren at the same point.
_siren.PlayEverywhere(panel.position, reliable: true);
```

#### Replacing the game's body sounds

ForgeAudio is the one place a mod replaces the game's own sounds; do not patch the game's sound calls yourself. It covers a player's body (below) and weapon actions (further down). A player's body: the game plays every footstep, jump take-off, landing and end of a fall of a player through `FeedbackPlayer.Play`, and the kit's single hook on its three overloads asks the claim on that body, if any. Bodies nobody claimed play their sounds unchanged, and a lookup costs one pointer probe with no allocation.

| Member | |
|---|---|
| `[Flags] enum BodySound` | `Footstep` (every footstep: movement states and the third-person walk animation), `Movement` (jump take-off, landing, end of a fall) |
| `BodySoundClaim? AudioKit.ClaimBodySounds(string modId, GameObject root, BodySound kinds, IBodySoundHandler handler, int priority = 0)` | Takes over the `kinds` sounds of the body under `root` (usually a `PlayerAgent`'s GameObject) on this client. Every transform under `root` is collected now. Null, logged, for an invalid argument, off the main thread, or when the game's body sounds cannot be told apart by body |
| `bool IBodySoundHandler.Play(BodySound kind, Vector3 position)` | Called from inside the game's play. `position` is the footstep's own; for `Movement` it is `root`'s. Return true to drop the game's sound, false to let it play. If it throws, the game's sound plays and the error is logged once |
| `claim.Dispose()` | Gives the sounds back. Safe to call twice and after the level ended |
| `claim.Refresh()` | Collects `root`'s transforms again after parts were added or moved under it |
| `claim.Active`, `ModId`, `Root`, `Kinds`, `Priority` | `Active` is false once disposed, after level exit, or when the kit unloads |

Of several claims on one body only the highest `priority` is asked (the newer one at equal priority), and only for the kinds it claimed. Every claim ends at level exit. The kit sends nothing over the network: claim the body on every client that should hear the change.

```csharp
// While the suit is worn: the pilot's footsteps become the suit's, the jump and landing sounds are dropped.
sealed class Suit : IBodySoundHandler
{
    BodySoundClaim? _claim;
    public void Board(PlayerAgent pilot) => _claim = AudioKit.ClaimBodySounds(MyPlugin.Id, pilot.gameObject, BodySound.Footstep | BodySound.Movement, this);
    public void Leave() { _claim?.Dispose(); _claim = null; }
    public bool Play(BodySound kind, Vector3 position)
    {
        if (kind == BodySound.Footstep) Sounds.Play("exo.footstep", position);
        return true;
    }
}
```

#### Weapon actions

The kit also raises three actions of a weapon you claim: the start and the end of a reload and a trigger pull on an empty magazine. The game's own weapon sounds come from the weapon's animation and stay; your handler adds the mod's cue. Weapons nobody claimed cost nothing (each hook reads one counter), a claimed weapon costs one pointer probe per action with no allocation.

| Member | |
|---|---|
| `[Flags] enum WeaponAction` | `ReloadStart` (the reload sequence really started), `ReloadDone` (the reload animation finished), `DryFire` (a trigger pull on an empty magazine; automatic, semi-automatic and burst alike) |
| `WeaponActionClaim? AudioKit.ClaimWeaponActions(string modId, Item weapon, WeaponAction kinds, IWeaponActionHandler handler, int priority = 0)` | Hears the `kinds` actions of this weapon instance on this client. | `void IWeaponActionHandler.Play(WeaponAction action)` | Called from inside the game's event, once per action. If it throws, the error is logged once |

| `claim.Active`, `ModId`, `Weapon`, `Kinds`, `Priority` | `Active` is false once disposed, after level exit, or when the kit unloads |

sealed class SuitGunSound : IWeaponActionHandler

```

### How it behaves

- **The kit plays local sounds unless asked.** It does not decide when or for whom a sound plays. `Play` plays on this client only: your mod triggers it on every client that should hear it and passes `IsSelf` for the local player's own sounds. `AudioCue.PlayEverywhere` is the one call that sends: a one-shot every player hears, without a network message of your own.
- **Lifecycle.** Sounds end at level exit and checkpoint reload. Start the loops you still want again afterwards, or use `Sustain`. Saving a checkpoint does not stop sounds. When the output device changes, one-shots end with `DeviceChanged` and loops resume.
- **Loading.** `Load` returns at once. Decoding runs on worker threads. Playing a cue before its files finish returns `Failed` with `NotReady`. Decoded audio is cached (at most 256 MiB compressed, 512 MiB decoded; the decoded PCM waiting to be mixed and every mixed clip count, and a mix is held twice while Unity takes its copy, so a mix that would pass the limit is refused and its cue fails with `AssetLimit`) and identical files are shared between libraries. Each file is limited to 64 MiB compressed and one hour. Ogg Vorbis only: Opus and chained or multiplexed streams are refused.
- **Mixing.** A cue with more than one plain layer (or a `maxSeconds` cap) is mixed once after its files decode (on a worker, one variant of one distance stretch at a time, uploaded one clip per frame; the decoded PCM is freed after the last cue that uses it), so playing it costs one voice. The mixer's rules: the output rate is the first layer's; other rates are resampled; each layer is trimmed, pitched, low-passed, scaled, faded and summed at its offset; the sum is clamped. A random pitch comes from a hash of the cue, variant and layer, so the same variant always sounds the same.
- **Distance stretches.** The `distance` ranges of the layers split the listener distance into stretches. `Play` picks the stretch from the distance at the start of the play. A stretch where no layer plays returns `DistanceCulled`.
- **Voices.** There are 64 real voices and 256 logical states. Speech, warnings (`priority` 200 or more) and ambience loops each reserve eight voices. Higher priority steals from lower. Loops that lose their voice keep their place in the loop and resume.
- **Occlusion.** Walls and closed doors between the camera and the sound lower its volume, down to 0.35. At most four rays are cast per frame, and no voice is tested more often than every 0.2 s. There is no reverb and no low-pass at play time; make a distant version with a layer that has a `distance` range and `lowpassHz`.
- **Dimensions.** A world sound's dimension is the one whose navigation mesh contains the point, or the listener's own for points off every mesh. A following sound without an explicit `Dimension` is placed again when its object jumps more than 10 m at once (a teleport or a dimension warp). The listener is in the local player's dimension while the kit hears through that player's own camera; while spectating it takes the dimension of the player the camera is at.
- **Listener.** The kit reuses any enabled Unity listener. Otherwise it adds its own to the active look camera. It never moves or removes a listener it did not create. After one full pass in the menus the kit stops looking up the camera, the local player and the listener every frame; entering a level (a game state change) wakes it.

### Author tools

`Audio/tools/convert_audio.py` needs Python 3.10+ and FFmpeg with `libvorbis`. `validate` also needs the .NET SDK. The runtime never starts external tools.

```
python Mods/ForgeCore/Audio/tools/convert_audio.py convert my-sounds/ path/to/audio/        # whole folder, keeps the names
python Mods/ForgeCore/Audio/tools/convert_audio.py convert shot.wav path/to/audio/shot.ogg  # one file
python Mods/ForgeCore/Audio/tools/convert_audio.py validate path/to/audio                   # exactly what Load will do
python Mods/ForgeCore/Audio/tools/convert_audio.py render path/to/audio big_boom --out big_boom_far.wav --distance 90 [--variant 1]
```

- `convert` turns every WAV, MP3, FLAC and OGG into `<name>.ogg`, keeps subfolders, skips outputs that already exist, and reports each file that failed. It never normalizes or truncates.
- `validate` runs the runtime's own catalog code and decodes every clip, then prints a JSON summary. It exits non-zero if any cue is unavailable.
- `render` writes the mixed preview of a cue exactly as the game plays it at a listener distance (default 0 m). It exits 3 when the cue is silent at that distance.
- `Audio/tools/cue_render.py` prepares a source segment for a clip: onset alignment, short fades and loudness. Its `exact` rule keeps a segment you chose by ear as cut: no trimming or fades, and a quiet one-shot is lifted toward -14 LUFS (a layer of a layered cue toward -17; at most 12 dB, peaks held at -1 dBFS by a limiter, never lowered; a loop is not lifted). A source's `targetLufs` sets its own target and `false` keeps its level. A clip can never be louder than its file, because the kit scales a clip by the sliders and clamps at full volume; stage files loud enough instead of raising cue `gain` above 1.

Ship recordings you own or have the right to use, as real Ogg Vorbis. Rights remain the author's.

### Logging

Logging goes through ForgeCore's `ModLog` and only real failures are written: every `AudioLog.Report` failure (except a voice restarted after a device change) goes through one dedup layer, `AudioLog.Report(key, ...)` into `ErrorOnce`, so one key is written once. Periodic reports have fixed keys (`clip-destroyed`, `voice-destroyed`, `one-shot-stalled`, `emitter-non-finite`, and `driver-update-<step>` for each of the driver's per-frame steps, which run and fail on their own). There are no information lines, timing, play counters or a Diagnostics setting.

## Visual (namespace `ForgeVisual`)

ForgeVisual draws things in the game world for any mod: model bundles, vanilla objects dressed in your models, rigged models worn by players, glow materials, the game's own effects by name, particle systems you built in Unity, code-configured sprite particles, decals, impact presets, effect lights, outlines round enemies and objects, ground markers, beams and trails, and it shakes the local camera. It only says how to draw; when, where and for whom is yours. Looks (colours, textures, timings, sizes) are always passed in by the mod that owns them.

### Layering: what this package holds and what it does not

ForgeVisual holds the mechanisms for drawing in the world: effect and model bundle registration, playing by name, the vanilla effect catalogue, particle pools, additive and glow shaders, decals, impact presets, effect lights, ground rings, beams, trails, outlines (and outlines seen through walls), camera shake, and loading models or re-skinning vanilla objects. What is drawn on the screen (full-screen layers, hit edges, visor, power-on, and screen effects such as a hit flash, vignette, blur or chromatic aberration) is ForgeUI's. Finished effects, textures, models and colours stay in the mod that adds them, registered as `pack:entry` and played by name. A mechanism other mods may use goes here without waiting for a second user.

### Rules

- **Names.** Everything is `Pack:item`. `Game:` is the vanilla catalog (`Fx.GameNames`), `Forge:` is this library (`Forge:soft-dot`, `Forge:soft-line`); neither can be registered by a mod. The first registration of a name keeps it; a second is refused and logged.
- **Resolve once.** `Fx.Find`, `Models.Get`, `ParticlePool.Get`, `ParticlePool.Channel`, `SpriteSheet.Get` look a name up; call them at load and keep the handle. Nothing in play looks up a name.
- **Failures are explicit.** A missing name, a pack that is not installed, a bundle that does not load or missing shaders return null or `FxResult.Unavailable` and log once with the mod and the name. Nothing falls back to another effect.
- **Nothing allocates per frame.** Playing, emitting, moving markers, beams, trails and domes reuse pooled objects and one property block.
- **Levels.** On every level change, checkpoint reload or return to the lobby the library clears its own pools and instances (sprites, decals, effect lights, running shakes, particle channels, held effects and impact copies, markers, beams, trails, glow spots). Your handles to bundles, models, sheets, channels and `FxHandle`s stay valid; a `GroundMarker`, `Beam`, `Trail` or `Sprite` you held is gone (`Alive` is false).

### Using it

- **Bundles and models.** `Bundles.Register(modId, pack, path)` loads a bundle through ForgeCore (a relative path is next to your DLL). A bundle with an `ordnance-profile` text asset (format 1) has its materials rebuilt with the game's gear shader (`LitMaterial.Create`) on first use; otherwise its prefabs are indexed by name. `Models.Get("Pack:item").Spawn()`; `Models.Dress(vanillaObject, model, options)` puts a model on a vanilla object fitted to its bounds and can hide the vanilla meshes; `Dressed.Undo()` restores it.
- **Gun models.** `GunMount.Create(partHolder, prefab, new GunMountOptions { ... })` is the one way a gun model goes on a game gun, in first and third person. The instance is a child of the gun's `GearPartHolder`, so whatever moves the gun (the game, a weapon inspector) moves the whole model; the game's meshes are hidden and their animators keep running. A reskin of a game gun, a new gun on a game gun and a gun made from scratch are the same path: each has a game gun underneath that fires, hits, damages and replicates, and the model goes on its `GearPartHolder`; replacing and adding differ only in content (which game gun, which model). Where the model goes and where both hands go is `GunHold.Solve` (below); a mod gives no size or hand position (a grip-table row's optional `adjust` is the only hand fine-tune). `Hold` is the answer for this gun (scale, origin, both wrist targets, shown length) and `GunMount.Rules` the rule it used. `Magazine` (origin at its own centre) stays with the gun and takes what the game's magazine node does on its own, so a reload moves it about its own centre and it never parts from the gun. On the first-person layer (`GunMount.FirstPersonLayer`) each renderer takes `LitMaterial.FirstPersonCopy` of its materials, the game's item-camera projection the hands are drawn with; `ApplyView` replaces that for a model with surfaces of its own. The game's hand, bore and sight nodes then point at the model. Each hand has a target node at its `GunHold` wrist target that is carried with the gun and also takes what the game's own hand node does on its own, so reloads and raises still move the hands (the left leaves the gun and comes back); the arms stay the game's LimbIK with the elbow on its bendGoal. The weapon's first-person settings are replaced by a copy with the rule's hold added to the hip and relaxed positions and its hip item field of view taken halfway from the game gun's own toward the rule's (`GunHold.HipItemFov`) (the game's shared block is never written; `Release` puts the original back). The game reads those settings only when its hip state takes the item (`FPIS_Hip.SetupWieldedItem`), so when the copy goes on or comes off while the local gun already sits at the hip the mount has the hip state take the item again; nothing waits for the next swap or reload. The left hand is pulled back along the gun into the arm's reach at the hip (`GunHold.IntoReach`): once the gun has sat at the hip for 1.5 s (longer than the game's raise, aim and relax transitions) the mount reads the upper-arm bone to each target once, pulls the left target back along the bore into the rule's reach (one line `visual-grip-pulled-into-reach` for the model's author), and reports the right hand, the model's anchor, with `visual-grip-out-of-reach` when it is out. A mod gives only the model, its `Front` (`Quaternion.Euler(0, 180, 0)` for an export facing -Z) and its sockets (`Sockets`, `GunSockets.Find` by default; `GunSockets.FromChildren(model, muzzleName)` when parts and sockets share names; `Models.FindSocket` / `RequireSocket` for one). The library calls `Refresh()` when the gun is assembled or wielded (`GameHooks.GearPartsSpawned`, `BulletWeaponWielded`), in that frame, and a mod may call it on a reload or every so often: it takes over replaced nodes and hides meshes the game added. To show no bare game gun, mount in the same two hooks and raise the gun only after; `GunMount.Of(holder)` finds a live mount, the model's magazine follows the game's reload visibility by itself (`GameHooks.MagazineVisibility`; `SetMagazineVisible` sets it by hand), `Bound` / `Released` tell a mod when the nodes point at the model, and `Release()` gives the gun back (the library does it when the gun or model is gone). The library steps every mount; the first-person pose goes in through `GameHooks.FirstPersonHolderLateUpdate` before the holder reads the hand targets. `GunMountOptions.Adopt` mounts an instance another package already spawned instead of a copy (ForgeWeapon's whole-gun model, a Model Library model ForgeEngine placed on the gun): its grip row is looked up by `Name`, and a failed mount or `Release` leaves it inactive for its owner to remove. `GunMountOptions.DrawnBounds` gives the box of meshes drawn without a renderer (batched imported models) in the model's own frame, measured with its renderers; those draws follow the anchor's layer and take `LitMaterial.FirstPerson` (the library's shared `FirstPersonCopy`, the one `GunMount` uses too) on the first-person layer.
  `GunMount.Of(holder)` is also the registry of guns whose look a package took over: no other package re-dresses a gun it names. `GunMount.Mounting` is raised with the holder at the start of `Create`, before the gun's rest poses are sampled and its meshes hidden, so a package that changed the gun's parts, materials or objects (ForgeSkin) gives them back there.
- **Holding a gun.** `GunHold.Solve(input, rules)` is the one rule every gun model is held by, a pure calculation (no Unity) that the website is to use too. A model declares only geometry: its right grip (`RightHand`, a bare point where the right palm touches the pistol grip; a model without the socket is held at its origin, the authoring grip), optionally its own left palm (`LeftHand`, kept where the model has it; when it is missing the mount derives the left hand from the game's hold), `muzzle`, `SightLook`, optional `Magazine`, and its mesh bounds for its length along the bore. The rule (`Visual/Data/gun-hold.json`, embedded; `GunHoldRules.Parse` names what is wrong in a bad one) takes the size and hold the owner approved on the EnergyLab guns and the hand from the game: size 0.85 of the authored size for every model, never squeezed (a shown length along the bore outside the game's own guns, 0.30-1.20 m, pistol to sniper as read in game, logs `visual-gun-size-out-of-range` from the mount, the author's error to fix in the model; `GunHold.LengthInRange`); the right grip point on the game's right hand node along the bore, the bore on the game's bore across, `SightLook` level with the game's sight (else bore on bore, else right wrist on the game's), so aiming puts the sight on screen centre; the right hand keeping the game hand's rotation unless its grip table row turns it (the game's grip pose, fingers included, is made for it; on every vanilla gun the left palm faces the gun from its lower left, 1-59 degrees above level, fingers along the bore, 6-15 cm below the bore: gun-hold.json) with the point of its palm that touches what it holds (`palm`, in the hand node's frame: the palm centre read in game, the same on every vanilla gun, plus 1.5 cm to the skin) on the right grip point, so its wrist follows from the game's own hand; a model without a left socket gets `GunHold.LeftGrip` (the game gun's left palm relative to its right palm, mapped onto the model's right grip along its bore), whose wrist is exactly the game gun's left hand relative to its right, and at the hip `GunHold.IntoReach` pulls the left hand back along the gun until it is inside the arm's reach instead of only logging; a grip table row's `adjust` is the only per-gun hand fine-tune; the hold offset and hip item field of view (halfway between EnergyLab's earlier hold and the game gun's own); and the arm's reach (`GunHold.Reach`: over 0.58 m a hint, over 0.62 m out). Inputs and outputs are in the replaced gun's frame (+Z bore, +Y up), the model turned to face +Z. A point that is not finite, a length that is not positive or a zero rotation throws `ArgumentException`. `Visual/Data/gun-hold.cases.json` holds fixed inputs with their answers; any implementation must reproduce them (0.1 mm, 0.001). A gun's hold is a preset, its grip points and an optional adjustment, in one format: a package lists its models in its own `gun-grips.json` data file (`forge-gun-grips`, schema 2: `models` by prefab name, each with `preset` and the muzzle/sight/shell-eject/flashlight points the model lacks or has in the wrong place (`muzzle`, `sight`, `shellEject`, `flashlight`, in the model's own frame at its own size, metres), and optional `adjust.right` / `adjust.left` with `offset`, where on the hand the point touches, in the hand node's frame, metres, and `angle`, the hand turned about the bore through its grip point, degrees, +X toward +Y) and passes `GunGrips.Read(assembly, resource)` as `GunMountOptions.Grips`. A model's own hand sockets are kept (a missing right grip is its origin; a missing left hand comes from `GunHold.LeftGrip`). The mount moves each listed fact point there before it seats the model, or makes an empty one when the model has none (a drawn part named so is refused), and puts the adjustments into the hold (`GunHoldInput.RightAdjust` / `LeftAdjust`, `GunHandAdjust`). `GunGrips.Parse` refuses another format, a row with no preset, or a row that gives `rightHand` / `leftHand` (hands come from the model's own sockets and the preset's vanilla hold; `adjust` is the fine-tune). `TryGet` gives a row (`GunGripEntry`); the mount refuses a preset the rules do not have. The presets (`GunHoldRules.Presets`, `gun-hold.json` `presets`) are the game's own holds read in game, one per grip animation: `rifle` (gear 12), `rifle-2` (gear 5, EnergyLab's main donor), `pistol` (3), `smg` (4), `shotgun` (13), `sniper` (14), `machinegun-1` (16) and `machinegun-2` (38; gear 43 holds the same), each with both hand nodes, the muzzle and, where read, the sight. In game the hands still take what the actual gun's own hand nodes do on their own (the grip animation the fingers follow, a reload), while the wrist targets are the model's own hand points (or the rule's derived left); without the game (the website, the shared cases) `GunHoldPreset.On(input)` stands the preset in for those nodes, so a new gun picks the preset its donor gear holds by and any implementation computes the same wrists. A hand point stays with the model; a listed fact point goes when its model is rebuilt with it; the preset stays.
- **Hand shapes, part points, followers.** `GunMount.SetHandShapes(holder, left, right)` gives a gun the grip animations of another vanilla gun: only the fingers change, the hands still touch this gun's nodes (first person; third person has empty clips on that layer). `GunPartMount.Create(holder, model, point, name)` is for a model that replaces one part (a barrel): the game's muzzle, sight and left-hand nodes point at the facts in `GunPartPoint` (a `forge-gun-part-points` schema 1 row), the left hand keeps what the game's own hand node does on reload, a point left out changes nothing, `Release()` gives the nodes back. `GunMount.FollowNode(part, node)` keeps a separately placed model piece under a whole-gun model moving with a game node, by the same rule as `Magazine`; a piece moves alone only if it is its own placement, since one placement draws from one anchor. Grip tables take no hand points (a model's own hand sockets are kept, a missing right grip is its origin and a missing left hand is the rule's) but optional `muzzle`, `sight`, `shellEject` and `flashlight` points, and each hand's `adjust` offset and turn.
- **Sights.** ForgeVisual ships three sights a package can put on any gun model (`Visual/Data/sights.json`, `GunSights.Kinds`): `red-dot-1x` (micro tube red dot), `holo-1x` (holographic tunnel hood with a lit ring and dot) and `scope-2x` (compact prism scope, a lit chevron with no crosshair lines). They are self-made hard-surface models (`Assets/Sights/LICENSE.txt`) in the Forge model package format: `Assets/Sights/<id>.model.json` in Git; the mesh `<id>.forgemesh` and the textures `<id>.t<index>.png` (the descriptor's textures in order: a colour atlas with baked occlusion and a surface map) are local media embedded at build from `ForgeModsRoot` (the build stops without them). Each embedded file is checked against the SHA-256 its descriptor names before the sight is built (a file packed under the wrong index is refused, never drawn). They are built once through `ImportedModels`: the gear shader for the body and its emission for the lit marks. A sight has no lens pane: the aperture is open, so the target shows through it untinted and the lit reticle floats in it. Each kind gives its look point (the reticle centre, in its own frame: front +Z, up +Y, origin at the middle of its base, real size) and its magnification. A package lists its models in its own `gun-sights.json` data file (`forge-gun-sights`, schema 1: `models` by prefab name, `sight`, `at` where the middle of the base stands in the model's own frame at its own size, optional `replace` with the model's own sight parts) and passes `GunSights.Read(assembly, resource)` as `GunMountOptions.Sights`; `GunSights.Parse` refuses another format or a sight ForgeVisual does not ship. The mount takes the replaced parts away before anything looks them up, stands the sight on the model (turned by `Front`), moves the model's `SightLook` to the sight's look point (making one when the model has none) and seats the model by it, so aiming lines the camera up through the sight. The held settings copy then aims the world camera at `GunHold.SightLookFov` (the half-angle tangent of `gun-hold.json` `sight.openLookFov`, 45 degrees, the median of the game's own open sights, over the magnification: 23 degrees at 2x); the item camera keeps the game gun's aim. A caller with its own `ApplyView` still gets the library's surfaces on the sight. While the game's gear shader is not loaded the sight cannot be built: the gun keeps its own sight and the cache writes one error line.
- **Imported models.** A player's uploaded `.glb` or a geomorph's own model, converted to the Forge model package, drawn as decoration (no collider). The caller finds the package's files, matches their SHA-256 to the descriptor and hands the bytes over; this library reads no file and computes no hash. `ImportedModelDescriptor.Parse(json, out failure)` reads the descriptor (format 1: the mesh's hash and counts, `submeshes` as index runs with a material each, `materials` with a linear `baseColor` or one base-colour `texture`, `metallic`, `roughness`, `alpha` `opaque`, `mask` or `glass` (a see-through pane: one flat `baseColor` tint whose alpha is its opacity, drawn with `LitMaterial.Glass`, the game's `GTFO/Glass` shader with a faint sheen; no texture, map or emission; the converter maps glTF `BLEND` to it), an optional `metalTexture` (the gear shader's own surface map, linear: metal in red, smoothness in green; the converter folds the glTF factors in, so `metallic` and `roughness` are then 1 and ignored; without it the two numbers make a flat map), an optional `normalTexture` (linear, OpenGL +Y, the glTF scale already applied) and an optional glow (`emissiveColor`, linear, 0 or more: glTF's emission factor times its strength, times an `emissiveTexture` map when given), and `textures` as PNG hashes with their size); `ImportedModelDescriptor.EstimatedBytes` (48 bytes a vertex instead of 32 when a material has a normal map: the loader adds tangents) is what a caller with a per-level budget checks first. The mesh sidecar is `FMSH`, format 1, vertex count, index count (little-endian 32-bit), then per vertex position, normal and UV as 8 floats, then 32-bit indices, all in Unity's space (the converter negates glTF x, flips the winding and moves the UV origin to the bottom left); the reader checks sizes, finite numbers, normals and indices. `new ImportedModels(budgetBytes)` is one level's cache (`keep: true` makes one that outlives levels, as the sights' cache does: everything it builds, textures included, is marked with `ForgeCore.Assets.Keep`, so the game's unused-asset sweep at a scene change cannot unload a part no instance draws at that moment): `Create(descriptor, meshBytes, pngBytes)` returns an `ImportedModelResult` (`Model` or a `Failure` with a stable `ImportedModelCodes` code and a detail, also logged once), builds the same descriptor once (`ImportedModelDescriptor.Key`: every value it holds, so models sharing a mesh with other materials stay apart), refuses a bad one the same way every time, and refuses a model that would pass the budget (`imported-model-over-budget`, not remembered, `ResidentBytes` says what is held). `ImportedModel.Spawn(parent)` makes an object with a mesh filter and a renderer sharing the model's mesh and materials; `Glow` and tints work on copies of those. `Dispose()` destroys every instance, mesh, material and texture the cache made; spawn nothing after it. Materials are `LitMaterial.Create`, the game's gear shader (`Cell/Player/CustomGearShader`, the shader family the game's clustered renderer lights, fogs and shades; a Unity light lights nothing there, so a shader of our own would stand unlit): base colour as a texture (a flat colour becomes a 2x2 one; the converter has multiplied glTF occlusion into it, the shader has no occlusion input), metal in red and smoothness in green of a second map (the package's `metalTexture`, or the flat numbers as a 2x2 one), `LitMaterial.SetRelief` for a normal map and `Glow.Write` for the glow (the shader's toggle, keyword, map and colour, written as given; the loader first scales the package's emission by `LitMaterial.EmissionPerUnit`, 0.01, because the shader's gain washes a multiple of 0.1 or more out to white). The shader culls back faces and has no switch for it, so a double-sided surface arrives with its back faces already in the mesh (the converter writes them). `ImageTextures.TryGet(..., linear: true)` reads a normal map without the sRGB step; one picture read both ways is two textures. A cut-out (`mask`) needs the shader to take `_Cutoff`; if it does not the model is refused with `imported-model-cutout-unsupported`, never drawn solid. The textures are decoded with a mip chain, trilinear and repeating (`new ImageTextures(surface: true)`); `ImageTextures` refuses a PNG whose header (`ForgeCore.Png.TrySize`) is not the expected size before it decodes. Before a level has been built the game has no gear shader and `Create` says `imported-model-shader-unavailable` (not remembered; ask again after the level exists). `Tools/Models/glb_to_forge_model.py` makes a package from a static `.glb` for checks. A skinned model is format 2: the descriptor adds `skin.bones` (each `name`, `parent` index (parents first, -1 for the root) and `rest`, the bone's rest pose in the model's frame as a column-major 4×4 in Unity's axes), and the mesh sidecar is format 2 with, after the indices, four bone indices (16-bit) and four weights (32-bit floats, summing to one) per vertex; `ImportedModel.Skinned` says so, and `Spawn` then builds the bones as child objects named as in the descriptor at their rest pose and draws the mesh with a `SkinnedMeshRenderer` on them (a skinned model is never batched).
- **Meshes from arrays.** `MeshArrays.Build(name, positions, normals, uv, tangents, indices, submeshes = null, computeTangents = true)` is the one place a model file's numbers become a Unity mesh (the imported models above and ForgeSkin's own mesh files go through it): flat xyz / uv / xyzw arrays in Unity's space, normals computed when null, tangents computed from the UVs when null and asked for, index runs per submesh, 32-bit indices past 65535 vertices. The mesh comes back readable; the caller adds what it needs (bones) and calls `UploadMeshData`.
- **Pictures of unknown size.** `ImageTextures.Decode(bytes, out failure, linear, normalMap, mipChain, compress, maxSide = 8192)` decodes one PNG or JPEG (its header read first, `Png.TryJpegSize`) into a texture the caller owns, with no CPU copy left. `normalMap` reads a tangent-space normal map (OpenGL +Y) and stores it the way the game's own normal maps are on its gear shader, DXT5nm (x in alpha, y in green; Unity's two normal unpackings read it alike), the layout `LitMaterial.SetRelief` expects; `ImageTextures.TryGet(..., normalMap: true)` is the same for the cached, size-checked path. `compress` compresses to DXT when both sides are a multiple of 4 (check `texture.format`).
- **Instanced draws.** `InstancedMeshBatches.Register(anchor, draws, layer, instanced)` draws many copies of a mesh below an anchor without a GameObject each: matrices are split into chunks of 1023, each chunk is frustum-culled and submitted once per sub-mesh (`instanced: false` draws every matrix alone, lit and shadowed like a renderer, for shaders without an instancing variant). A draw is `InstancedDraw(mesh, materials, local, shadowOnly)` in the anchor's frame; the groups end with the anchor. The host calls `InstancedMeshBatches.Draw()` once per frame after transforms settle; `ViewReport` receives one line when a gun model's first-person view changes.
- **Thrown parts.** `new Thrown(origin, rotation, velocity, spinAxis, spinDegrees, groundY)` is the path of a part blown off a model (a hatch lid, a panel): a parabola with a constant tumble until it lands. `Pose(seconds, out position, out rotation)` is a pure function of the time since the throw and `FlightSeconds` says when it lies still, so every peer counting from the same moment draws the same pose with no state; the caller reparents the part, hides it when it likes and chooses the speeds.
- **Rigged models on players.** Four mechanisms for outfits, mechs, transformations and the like. Your mod passes the bone map, the proportions, which bones are covered, which vanilla parts hide and how IK is treated; the library holds no model's bone table. Bones are `BodyBone` (Unity's humanoid names and numbers).
  - *Worn on the first-person body.* `Models.WearFirstPerson(agent, look, options)` spawns `look`, matches its skeleton to the local player's first-person skeleton through both bind poses (shoulders and hips set the common frame; each bone's rest direction is swung onto the game bone's), parents every `WearBone` with `Worn` onto its game bone once, scaled by its `BodyMeasure` (`ShoulderSpan`, or one leg's or arm's two segments; a limb missing a bone falls back to the span), and keeps only the triangles skinned to the worn bones (`FollowParent`: hinged parts whose skin counts as their parent's). `Bones` must list `LeftUpperArm`, `RightUpperArm` and `Hips` (`worn: false` only lines them up). It is drawn once off screen and costs a fraction of a second, so build it while the player cannot act. `FirstPersonWear.Activate()` holds the vanilla parts in `Hide` (`BodyParts`, default head, torso, legs) off with `forceRenderingOff`; `Follow()` every late frame shows the model exactly while the game shows its arms; `Deactivate()`, `SetColor(property, colour)`, `Alive` (false once the game replaced its first-person body: build again), `Destroy()`.
  - *Pose copy.* `Models.ReadPoseTarget(root, skin, links, label)` once per model instance, `Models.CopyPose(animator, target, reach, label)` once per body, then `PoseCopy.Apply()` every frame after the game animated the body and solved its limb IK (a player's hands go on the item's grips in `PlayerSyncIK.UpdateIK`, from a game `LateUpdate` whose order against yours is not fixed). Each `PoseReach(upper, lower, end, anchor)` bends a two-bone limb after the turns so its end joint lands where the body's does, carried over from the anchor link (one anchor for both arms keeps both hands on the item); pass an empty array for turns only. Each `PoseLink` names a model bone, its body bone (with an alternative for an optional one) and its direction (toward a link or a body bone, or from a link), so different rest poses copy to the same pose; link 0 is the root, whose height and sway scale by root height. `Turn`, `Scale`, `Source(link)`, `PoseTarget.Bone(link)`, `PoseTarget.Rest()`, `Release()` (the animator's culling mode back). A caller that found the body's bones itself (an enemy, by the bone paths its content names) uses `Models.CopyPose(body, bones, rest, animator, target, label)` instead: `bones[i]` is the body bone of link i and `rest[i]` its rest pose in the body's frame (read it from the model asset as the game ships it); no reach. `PoseCopy.Follow()` hands the per-frame `Apply` to this library, after the joint clips (`JointPlayer`), until `Release`, the body or the model is gone, or the level ends.
  - *Held item copy.* `Models.MirrorHeld(agent, layer, label)`: `Refresh()` a few times a second, `Place(copy.Turn, copy.Source(hand), target.Bone(hand), copy.Scale)` every frame, `TryMuzzle`, `ShadowOnly`, `Hide`, `Destroy`.
  - *Third-party actions on any humanoid.* `player.CaptureGameClip(name, animator, sourceAnimator, out refusal)` finds a clip the game holds by name and turns it into a `JointClip` for this body by sampling it on the live skeleton, so the engine retargets a humanoid clip and nothing is exported from the game; each skeleton samples it once and the result is kept, so call it as often as you like (`JointClip.FromTurns` builds the clip from those poses). `refusal` is `not-human` or `no-such-clip`. `JointPlayer.FindGameClip(name, controller)` is the lookup it uses: the controller first, then every humanoid clip the game has loaded (an enemy prefab's animator holds only its default controller; the game sets the controller of the enemy's animation set at setup). `JointClip.SeatOnFloor()` (once after reading) seats a clip on the floor in two steps: a clip whose every frame is off the floor (a lying body with a standing hip height) is lowered as a whole by one amount, so a jump inside it keeps its height; then each frame whose lowest body joint is below ankle height (a kneeling or crawling body with the hip too low) has its hip raised by that frame's shortfall only, so standing frames and a flip's apex are untouched; `JointClip.Read(file)` reads a Forge animation file (`.glb`, written only by the site's `Web/src/forge/animation-glb.ts`): the canonical rig (`ClipRig`: 20 body joints and all 30 finger joints or none) as named nodes at its rest pose and one linear animation at a fixed rate, the hip moving and turning, every other joint only turning against its parent; anything else (an extension, a mesh, enemy nodes, a hand layer, another rest pose, uneven or non-zero-based times, a turn that is not a unit quaternion) throws `FormatException` naming the first fault. It reads once at load; `Evaluate` reads nothing and allocates nothing (see "Binding a skeleton"). `Models.BindJoints(playerAgent)`, `Models.BindJoints(animator, label, out refusal)` (a humanoid body that is no agent, such as a copy of a player's model made without a `PlayerAgent`: no IK to pause, nothing reported to `Recording`; refusals as for an enemy), `Models.BindJoints(enemyAgent, out refusal)` (null with `no-humanoid-body` for a body without humanoid limbs, such as the game's squids, or `skeleton` for limbs that do not stand like the rig, such as one side swapped; a body resting turned half round against its root, such as the Birther family, is read turned round and plays facing its root), `Models.BindJoints(root, rigMap, label)` for any other skeleton, once per body; `Models.BindFirstPersonArms(localAgent)` (once `Models.FirstPersonArmsReady(localAgent)` is true: the lobby and the level load have no arm meshes yet, and binding then logs an error), again when `arms.Alive` is false, for arms in front of the first-person camera (the game draws no hands there and re-poses its own first-person skeleton after every late update, so this is a copy of that skeleton holding only the arm meshes): `arms.Play(clip, playback, hideHeld)` plays a clip made for this view: the copy's shoulders sit where the game's rig has them against the eye, so the arms enter from below. Like the game's first-person body and held item it is drawn through the item camera (the game's `FPS_Content` sets `_FPSWeight`, which blends the shader from the world's projection to `_FPS_VP`; `SetFPSRendering` alone only sets the keyword), so the player's field-of-view setting does not change its size. The item camera's field of view belongs to the held item, 32 to 55 degrees, and the arms are squeezed against it each frame so a clip looks as it does at 45 degrees with any item. A third-person gesture stands up the middle of the screen from here, so make a separate clip: in the clip sources mark it `"firstPerson": true` and key each arm with `reach` (`wrist`, metres from the eye, and `elbow`, the way the elbow bends out); an arm no pose places hangs below the view. `Tools/Models/build-joint-clips.ts --preview` renders it from the eye at 45 degrees and prints how much of the screen the hand and wrist take and where the arm leaves the picture. It goes away when the clip ends. `Models.HideHeld(agent)` takes the third-person held item out of the picture until disposed; it does not follow a weapon change, so end the action when the hands change. Every hold on a renderer (this, the arms, `ShowOwnBody`) counts: the value from before the first comes back when the last lets go, whatever the order, `Models.HideRenderers` and `ShowRenderers` meanwhile change that value, and the level ending or a checkpoint reload puts it back for holds still open. A local player's third-person body has no head or arms, so judge body clips on a bot (`Puppets.OpenBotSlots`, `Puppets.Player`) or an enemy. `JointPlayer.Play(clip, new JointPlayback(startTime, loop, mask, weight))` returns a `JointTrack` (`Playing`, `Elapsed`, `Stop()`; a stale handle never touches a reused slot); `JointPlayer.Stop()` ends them all. Up to `JointPlayer.MaxTracks` (4) tracks play at once, and `Play` throws past that; to change clips use `player.CrossFade(oldTrack, clip, playback, fadeSeconds)`, which fades the old track out and, when every track is taken, drops the oldest instead of throwing. **Bone masks** (`JointMask`, built while loading): `Add(BodyPart, weight)` for humanoid parts (`LeftHand`, `RightHand`, `LeftFingers`, `RightFingers`, `LeftForearm`, `RightForearm`, `LeftArm`, `RightArm`, `HeadNeck`, `Torso`, `Pelvis`, `LeftLeg`, `RightLeg`), `AddPath(path, subtree, weight)` for a bone by its path under the body's root with or without everything under it, presets `FullBody` (the default), `UpperBody`, `LowerBody`; a joint takes the highest weight any entry gives it, and a lower edge weight (a forearm at 0.5 under a hand) blends the clip with the game's pose so the joint does not kink. Bones outside every mask are never written: the game's animator and IK keep them. Tracks whose masks do not overlap add up (one hand gestures, the other keeps its grip); on a shared bone the later track wins. A track over the hips writes the clip's pose in the body's axes plus the hip travel; any other track writes each masked bone's turn against its parent onto wherever the parent is now, so a hand gesture rides on the body's own walk and aim. Only the IK that moves a masked bone stops: a masked arm stops that arm's `LimbIK` and sets `PlayerSyncIK`'s weight for that arm to 0, a masked spine or head the `AimIK`/`LookAtIK` and the aim and look weights, and only a mask over the hips also turns `PlayerSyncIK`'s switch off; all come back as they were when the last track ends. When no track covers a bone any more it goes back to the local pose it had just before a track first wrote it, so a bone the animator does not pose every frame (no curve for it, or a culled animator) does not keep the clip's last pose. Masks resolve to per-joint weights when a track starts, so posing looks nothing up. The player poses itself every LateUpdate after the game's animator; the pose is a function of the time since `startTime` (this peer's `Time.time`; every peer's clock is its own), so a mod that wants other peers to show it sends the action id and how far into it the sender is (`Time.time - startTime`) over its own `Net` channel, and the receiver starts it with `Time.time - elapsed`. A player's FinalIK and `PlayerSyncIK` are off while it plays: they sit on the third-person body `PlayerCharacter_rig(Clone)`, outside the agent's own object (six enabled in a level: `PlayerSyncIK`, `AimIK`, two `LimbIK` for the arms, two `LookAtIK`; `BipedIK` and `GrounderBipedIK` are there but off), and `PlayerSyncIK.UpdateIK` solves the left arm onto the item's grip itself while its own switch is on, so the pause also holds that switch (`Disable`/`Enable`). The body and the first-person arms are humanoid `AlwaysAnimate` avatars that map all 30 finger bones (`HumanBodyBones` 24-53), 22 transforms under each hand. `Bone(joint)` and `Root` let a test read the pose back.
  - *Clips on the player's body.* `Models.BodyClipRig(root, animated, "Hip", label)` once for a hidden model with the game's player bone names and your legacy clips; `Models.BindBodyClip(agent, rig, options)` once per player; `BodyClip.Pose(clip, time, position, rotation)` every frame it plays, after the game's animator; `Stop()`. `BodyClipOptions.PauseIk` (default on) turns FinalIK and `PlayerSyncIK` off while it plays and back as they were; `FirstPerson(on, camera)` lets the local player watch from inside (`FirstPersonHead`, `FirstPersonSkip` for renderers that would sit in front of the camera).

- **Glow.** `Glow.For(renderer)` copies its materials into glowing ones; `GlowHandle.Set(hdrColour)` every time it changes, `Dispose()` restores. `GlowSpot` is a soft dot on a transform: `Pulse` swells and fades it, `Show` holds it (`Shown` says whether it is lit), `Place` moves it to a world position, `Hide` and `Destroy` end it. `Glow.Write(material, colour, map)` is the one emission write every mod uses (toggle, keyword, map and colour, written as given); `Glow.Clear(material)` switches that glow off again (toggle and keywords; colour and map stay) and `Glow.SetColour(material, colour)` changes only the colour of a lit glow, allocating nothing, for every frame of an animated glow on the caller's own material.
- **Surface looks.** `SurfaceAppearance` is a surface's colour, glow and invisible switch, with optional `SurfaceSlot`s that override it per material slot (`ForSlot(index)`; `Over(outer, inner)` lays one look over another; `Key()` names it for sharing). Colours are sRGB and become linear once here. `SurfaceLook.Paint(source, look)` returns a new material and keeps nothing: tint on the flat surface shader, glow through `Glow.Write`. A part is shown or invisible, never see-through. Invisible is the game's shadow-enemy draw: `SetShadowOnly(renderer, true)` leaves only the shadow (ShadowsOnly) and the part still takes hits; for single slots `LeaveOutSlots(renderer, materials, invisible)` splits the mesh and draws the invisible slots through a shadow-only twin (`ShadowTwin(renderer, split, materials)`, skinned to the same bones), and `SplitByBones(mesh, groupOfBone, ...)` does the same per bone group (both need a readable mesh, else null with a reason; `PutBack` restores the source mesh and drops the twin, `SurfaceSplit.Destroy()` frees the meshes). A removed or replaced part is `SetDrawn(renderer, false)`: not drawn, no shadow. Hosts that hide a body or a held copy from its own camera (`HeldMirror`, the Frames body) use `SetShadowOnly` too. The caller owns the materials and meshes it gets and destroys them.
- **Effects by name.** `Fx.Play(handle, position, direction[, size, colour])` for one-shots, `Fx.Hold(handle, key, position, direction, size, colour)` for a sustained effect (`key` comes from `Fx.NewKey()`, always above 0, and a key of 0 or less is refused: one per jet, beacon or flying round, and a thing that is pooled or a slot that is used again takes a new key for each new shot, so it never moves the last one's copy; a call with the key of a live copy within its window moves that copy, another key has a copy of its own however close it stands, so nothing is merged by distance, and a hold never takes a copy another key still keeps alive (with every copy kept it answers Unavailable, logged once: raise the effect's Copies); `Fx.Release(handle, key)` ends that copy at once, its particles cleared, when the trigger is let go or the thing turns into something else), `Fx.Line`/`Fx.Tracer` for line effects (a line effect registered with `HoldSeconds` is held and takes the key form `Fx.Line(handle, key, from, to, head, colour)`: calling it again with the same key moves and stretches that live copy; the keyless `Fx.Line` refuses a held line; `Fx.Line(handle, from, to, head, colour)` tints it like a play: a library layer converted with `@tint` takes its hue from the colour), `Fx.Attach` for an effect riding a transform, `Fx.Field(handle, centre, up, radius[, settle])` for a sustained effect over a round area (returns an `FxField`; call its `Hold()` every frame: with `FxOptions.Spacing` it keeps copies that far apart, growing out from the centre (over `FxField.GrowSeconds` when set: gas rolling out, fire catching), without it one copy at the area's diameter; nothing allocates per frame). `Fx.Register(bundle, item, options)` adds your own prefab effect under `Pack:item`. The effects of the bundle Forge ships are registered by the library itself as `Forge:forge_sparks`, `Forge:forge_explosion`, `Forge:forge_energy_beam`, `Forge:forge_flame` and so on (`Forge:forge_<name>`, 11 in all), so any mod plays them through `Fx` too.
- **The shared grenade blast.** `HeavyBlast.Play(position)` draws the heavy grenade launcher's explosion, the one every mod that fires one uses instead of each shipping a copy (Arsenal's launcher and EnergyLab's Blast Gun now do). The prefab, its scale and its light are the `heavy.gl.blast` slot of `forge-visual-fx.bundle` and `fx-slots.forge` beside this library's DLL (the table is in Git, the bundle is local media built with `Tools/Vfx/FxLibrary/fx_slots.py --package ForgeVisual --build`); the library parses the table once at load and plays through `Fx`. A clean clone has the table but not the bundle: the library logs once and the moment draws nothing, as any missing effect slot does.
- **Seating an effect.** `Fx.Seat(handle, point, direction, size, out fit)` returns where a copy stands so what it draws clears the level: lifted from the point until its measured body (the slot's `Body`, `[min x, y, z, max x, y, z]` at scale 1, written by `fx_slots.py` for a slot `fx-adjust.json` marks `seat`) clears the floor below; under a ceiling too low for the whole body it stands between floor and ceiling and plays smaller by `fit`. A slot without `Body` returns the point and fit 1.
- **Effect slots.** `FxSlots.Load(modId, pack, bundleFile, slotsFile)` registers a bundle of prefabs plus a JSON table `{ "Slots": { "pod.land": { "Item": "prefab", "Size": 4, "Line": false, "Hold": 0, "Scale": 1 }, "pod.vent": { "None": true } } }` and returns the set; resolve once with `Find(slot)` (play with `Fx.Play`) or `Model(slot)` (for pool-based players). A slot the table does not list logs its error once and returns the empty handle, and the moment draws nothing: no moment falls back to another effect. A slot listed as `"None": true` returns the same empty handle (`FxHandle.IsNothing`: `Fx.Play`, `Hold` and `Line` draw nothing and report played). A missing or damaged file or bundle logs its error and returns `FxSlots.Empty` (never null), so a mod keeps one `FxSlots` field and calls it without a null check. Which prefab plays for a slot is table data, so a different choice changes the table and the bundle, not code. A mod keeps the handle `Find` returns (never null: the empty handle when the table has no such slot, reported once; the moment then draws nothing) and plays it with `Fx`; nothing looks a slot up by name while playing. `Size` is the extent the prefab is authored at (the caller's size scales it; on a `Line` slot it is the authored length the line stretches from), `Scale` multiplies the caller's scale (on a `Line` slot it is the width), `LaserHead` and `LaserBodies` make a `Line` slot a laser of any length that stays thin: the copy keeps its uniform `Scale`, the head child goes to the end and the body children stretch (a stretched billboard through its renderer's length scale, which changes live particles at once; a flat line along its own +X through its transform; `LaserTile` repeats the bodies' texture every that many metres so a jagged stroke keeps its jags at any length, and `Fx.Line(handle, from, to, head)` (or the key form for a held line) with `head` false leaves the head out for a line that ends in the air; `EndFade` (metres) makes such a line, laser or not, fade out over its last metres instead of stopping square, while a line that hit something keeps its end: the copy's property block gives the Forge particle shaders `_LineEnd` and `_LineFade`), `Linger` is how many seconds a copy may stay after it stopped emitting (default 8; set it short on a sustained effect with long-lived particles so it ends with its hold), `Seconds` is how long a one-shot keeps emitting (a play always ends: a looping prefab stops emitting after it, the particles finish and the copy recycles; default one round of the longest layer, start delay included, at most 8 s), `AxisUp` is for a prefab authored Y-up (its +Y follows the direction, not its +Z), `Centre` (`[x, y, z]`, `FxOptions.Centre`) is where a prefab draws its middle from its root at scale 1 when that is not the root: the requested point is where that middle stands at any size, `Spacing` and `Copies` are for `Fx.Field`, `Light` (`{ "Colour": [r, g, b], "Range": m, "Peak": intensity, "Life": s, "Delay": s, "Flicker": 0..1 }`, `FxOptions.Light` / `LightDelay`) gives the slot a point light that every play brings along: a one-shot flashes it (peak at once, fading over `Life`, which a one-shot slot must give above 0, `Delay` late), a held slot holds it while held (colour and range follow every frame), its colour is its own times the caller's hue (the caller's colour over its luma, as the particle shader takes it, so a dark or HDR colour does not dim or brighten it) and its range grows with the size the effect plays at; it goes through `PointLights`, and at most 8 effect lights are lit at once for every pack together, past which a play draws without its light (no allocation per play), and `"None": true` is a slot that deliberately draws nothing (`IsNone`). Every renderer of a copy takes the caller's colour (kept meshes, line and trail renderers too, not only particles); a trail renderer is cleared when its copy starts again, and trail and line renderer widths follow the size the copy plays at (they are metres, not scaled by the transform); a line renderer in local space stretches with a `Line` slot's transform. How a layer scales and whether it loops are fixed in the prefab, not at run time: the game's build has stripped `MainModule.loop` and `scalingMode`, so `ParticleSystem.loop` and `scalingMode` compile and throw `MissingMethodException` in the game (`Tools/Forge/check-interop-members.py` catches any such call in a released assembly). The converter `Tools/Vfx` puts every library layer on Hierarchy scaling. Everything else a slot needs is written into its prefab there too (`Tools/Vfx/FxLibrary/fx-adjust.json`): a slot drawn from several sources (`layers`: layers of other library effects or of own recipes, each with its own changes, `delay`, `offset`, `scale`, `rotate`, composed under one root), per-layer `@size`, `@speed`, `@count`, `@delay`, `@gravity`, `@life`, `@bright`, `@colour:layer:#rrggbb[:k]` (a fixed hue, independent of the caller), `@tint` (the caller's hue), `@keepmesh:path` (a mesh that stays: a projectile body), the Knife (PRO Effects) shaders on built-in ports (the ports ship only inside the packages' bundles; their source is a local input; a port layer draws its own `_MainColor`, not the caller's colour, and takes no `EndFade`) or the Distort shader (Distortion), Hovl's HS_ShockWave on the Flow shader (a port: it reads the library's vertex streams and custom data), soft particles carried from each library material's own switch with its shader's fade (Master MagicFX depth fade, Hovl, Piloto, Rubfish, Gabriel Aguiar and URP particle soft particles; legacy `_InvFade` shaders, soft only by quality setting, stay hard), `@soft:layer[:metres]` (soft particles added or re-set on the layers it names), an Alpha8 texture drawn as a white shape that takes the tint, and own effects declared as data in `fx-own.json` (layers on library textures, every layer a child that can be placed and left out, no C# per effect). Soft particles fade by the camera depth texture only while the eye's camera has one: ForgeVisual sets the global `_ForgeSoftDepth` from the eye camera, judged again only for another camera object or a new level (on for a deferred camera, which the player camera is, or one asked for depth; off otherwise, where they draw hard edges instead of nothing). `Tools/Vfx/FxLibrary/fx_sheet.py` draws every slot at 0.03, 0.08, 0.3, 0.8 and 3 s and, with `--colour slot=#rrggbb`, in the caller's colour, with the slot's light shown on the floor by an equivalent point light and soft particles on (its camera has a depth texture).
- **Prefab effects you steer yourself.** `new FxInstancePool(name)`, then `pool.Take(model, tint)` gives a pooled copy of a registered prefab (a particle system at its root) that you keep: `Place`/`Stretch` it every frame, `Hold()` it, `Emit(prefix, on)` switches the layers whose name starts with the prefix, `PlayState(child)` plays an inactive state child, `Start()`/`Keep()` play it, `Release()` lets a held copy finish and go back to the pool. `pool.Prepare(model, count)` fills the pool one copy per step. The copy's Unity particle lights are removed; light it with `PointLights`. A bundle built with addressable names (prefabs listed without `.prefab`) registers its prefabs as models too.
- **Effect lights.** `PointLights` is the one pool of temporary lights for every mod: `Flash(position, spec, now)` for a blast or a muzzle, `Hold(ref handle, position, spec, now, strength)` every frame for a light on something burning or glowing (pass your own pulse or fade as `strength`), `Release(ref handle)` when done. They are the game's own `FX_PointLight`s: they cast no shadow, and the game's clustered renderer lights only through them (a Unity `Light` you add lights nothing). The budget is 32 for every mod together: a full pool gives a flash the flash nearest its end and never takes a held or leased light. `Place(position, spec, seconds, now)` leases a steady light (full intensity for `seconds`, no fade, not a flash, so the player's flash setting does not touch it) and returns `PointLightResult.Full` instead of taking another light when every slot is held or leased or the game has no free effect light; it is what an authored "light here for N seconds" step uses. `PointLightSpec` gives colour, range, peak, life, flicker and, with the six-argument constructor, `Blink` (blinks per second) for a warning lamp. The player's `Effects / FlashLights` turns flashes off; held lights stay. The library ticks them every frame; a mod whose effects move later in the frame may call `PointLights.Tick(Time.time)` again after they moved.

  static readonly PointLightSpec Alarm = new(new Color(1f, 0.15f, 0.1f), 6f, 2.5f, 0f, 0f, blink: 2f);
  int _alarm;
  void Update() { if (alarmOn) PointLights.Hold(ref _alarm, lampPosition, Alarm, Time.time); else PointLights.Release(ref _alarm); }

- **Light in a slot.** A slot of the table may carry `"Light": { "Color": [r,g,b], "Range": 8, "Intensity": 3, "Rise": 0.05, "Fall": 0.3 }`: `Fx.Play` then flashes that light with the effect (colour times the caller's hue, range times size over the slot's default size, through the one `PointLights` budget). A slot with a `Light` and no `Item` is a light-only slot and `Fx.Play` just flashes it. Put a mod's effect lights in its table, not in code.
- **Ambient light lease.** `var lease = Ambient.Lease("MyMod", brightness: 0.6f, range: 64f, color: Color.white, seconds: 1.5f)` lights the local player's ambient light and fades to it; `lease.Set(...)` changes the target, `lease.Follow(position)` carries the light to a point (a free camera), `lease.Release(seconds)` fades back. Several mods stack leases (the latest shows, letting go of it shows the one before); if another writer changes a field while you hold it, that field is given up and never overwritten or restored. `Ambient.Native` is the level's own value, `Ambient.Fading` whether any fade runs. `FieldReceipt<T>` is the rule behind it for any one field: it keeps the original value and, once it sees another writer change the field, never takes the field again (the UI part's screen text borrows the game's text fields with it).
- **Effect culling.** A playing copy of a registered effect (`Fx.Play`, `Hold`, `Field`) that is beyond its distance from the eye (default 70 m, measured to the surface of the copy's bounding sphere; the slot's `CullDistance` overrides it) or outside the view (a cone round the eye's forward direction holding the whole frustum, widened 20 %) is paused with its renderers off, and runs on from where it stopped once back in range and in view (its window keeps running while paused: a copy whose window is over ends out of view and is not replayed on a turn; a held copy nobody keeps alive any more ends the same way). Coming back needs 90 % of the distance, so an effect on the edge does not flicker. A pass checks at most 24 playing copies a frame, continuing where the last frame stopped; it allocates nothing and does not walk every copy each frame. A copy whose reach is at least 10 m (blasts, air strikes) is never culled unless its slot says `"AlwaysDraw": false`; `"AlwaysDraw": true` keeps any slot always drawn; line effects are never culled. `FxOptions.AlwaysDraw` and `CullDistance` are the same two fields for code that registers its own options. What is reported to `ForgeCore.Recording` is reported when the effect is requested, so recordings do not depend on what is seen. Not culled: `Game:` effects (the game's pools), copies of `FxInstancePool` (their owners steer them every frame), decals, sprites and lights. Players turn it off or move the default distance in `BepInEx/config/NAinfini.ForgeVisual.cfg` (`Culling / Enabled`, `Culling / Distance`).
- **Decals.** Marks on any surface (holes, scorches, blood, ground marks): flat quads lying on the surface normal, lifted 2 cm off it, each with a life and a fade-out at its end. `Decals.Shared` is one set of 128 for every mod, built during the elevator ride; `SpritePool.CreateDecals(capacity)` makes your own set (at load); keep it across levels (its marks are cleared with the level) and make a new one only when its `Alive` turns false (the pool was rebuilt). A full set recycles its oldest mark. `Decals.Stick(from, direction, reach, out point, out normal)` finds the surface a shot hits. The game's own decal system draws only its own deferred-decal materials registered to its level culling, so it cannot take a mod's texture; these marks use your sheet.
  ```csharp
  var holes = SpriteSheet.Register("MyName.MyMod", "MyMod:holes", holeTexture, 2, 2, FxBlend.Alpha);
  if (Decals.Stick(muzzle, aim, 60f, out var point, out var normal))
      Decals.Shared?.Place(holes!, point, normal, 0.12f, Color.white, life: 30f, fade: 5f);
  ```
- **Game projectiles, look only.** `ProjectileLooks.Copy(type, origin, rotation, needsSpeed, out speed, out reason)` gives a copy of the game's projectile prefab of a `ProjectileType` that keeps only what draws (meshes, particles, trails, lines, lights) and hits nothing; the caller moves and destroys it. Null with a reason when the manager, its prefab table or the prefab is missing. Used by ForgeWeapon's extended bullet flights and ForgeReplay's recorded enemy projectiles.
- **Impacts.** An `ImpactLook` (made once) says what a hit shows: any of an effect by name (`Fx`, at `FxSize` metres when the effect takes a size), a prefab effect (`Model`, from the library's own pool, filled ahead with `Impacts.Prepare(look, copies)`), a light flash (`Light`, `LightLift`), a mark (`Decal`, `DecalSize`, `DecalLife`, `DecalFade`, `DecalColour`) and a camera shake (`Shake`). `Impacts.Play(look, point, normal, scale, strength)` shows it, facing the normal. `Fx.Tracer` is the game's own bullet tracer.
  ```csharp
  var sparks = new ImpactLook { Model = Models.Get("MyMod:sparks"), Light = new PointLightSpec(new Color(1f, 0.7f, 0.4f), 2.5f, 2f, 0.12f, 0.3f), LightLift = 0.1f };
  foreach (var step in Impacts.Prepare(sparks, 8)) yield return step;          // at load
  Impacts.Play(sparks, hit.point, hit.normal);                                  // per hit
  ```
- **Camera shake.** `CameraShake.Shake(at, spec)` shakes the local player's view through the game's own `FPSCamera.Shake`: a `ShakeSpec` (amplitude, range, seconds, frequency, inner radius; make it once) falls off linearly from the inner radius to the range. `CameraShake.Kick(direction, amplitude, seconds)` is a short push of the view one way (a recoil, a blast from one side). Every shake is scaled by the player's `Camera / ShakeStrength` (0 turns them all off), and shakes running together never add up past `CameraShake.Cap`: a new one only fills what is left. Both return the amplitude that reached the camera.
  ```csharp
  static readonly ShakeSpec Blast = new(0.5f, 30f, seconds: 0.6f, frequency: 20f, inner: 4f);
  CameraShake.Shake(blastPosition, Blast);
  ```
- **Particles you built in Unity.** One prefab, world-space looping child systems with emission off. `ParticlePool.Register(bundle, item)`, then `Channel(child, maxParticles)` once per child; `Emit` single particles or `Burst` from the system's own shape. Give the prefab's `maxParticles` as the capacity (the game's interop does not expose it): when full, priority 0 is skipped and counted. `Look(texture, blend)` draws the system with ForgeVisual's particle shader.
- **Sprites configured in code.** `SpriteSheet.Register(modId, "Pack:sheet", texture, columns, rows, blend, sheddable)`, then `SpritePool.Emit(SpriteSpawn.Of(...))`. 256 sprites shared by every mod: a higher priority takes the oldest lower one, attached sprites (`Attach`, driven each frame with `Move`/`Resize`/`Recolour`/`Turn`; they do not age) are never taken, `SpriteSpawn.FlipPhase` starts a flipbook part-way along, and sheddable sprites fade when everything on screen covers more than five screens. Marks on surfaces are decals and light comes from `PointLights` (both above).
- **Outlines.** One line round the outer edge of an enemy or any object, none inside it and none along whatever covers it, laid over the post-processed frame under the game's HUD (colours shown exactly as given); an enemy the game has culled has no line. A skinned mesh that gets an outline has `skinnedMotionVectors` off from then on, so the line draws the pose the frame shows. `Outlines.Add(modId, target, colour, priority = 0, seconds = 0, xRay = false)` (a `GameObject`, or an `EnemyAgent`) returns an `OutlineHandle` (`Active`, `Remove()`; `seconds` 0 holds until removed, else it ends by itself). `Outlines.AddEnemyOutline(modId, name, style)` returns an `EnemyOutline` (`Active`, `Style`, `Remove()`) that outlines the enemies in sight by themselves: ForgeCore's `Enemies.Live` and `Enemies.Alert`, nearest first, coloured `Sleeping`, `Awake`, `Hunting` (`EnemyOutlineStyle`: `Range` 35 m, `FadeDistance` 5 m, `MaxEnemies` 24, `Width` 1.6 px at 1080p, `Priority` 0, `XRay` false). Several sources on one object: the highest priority draws, alone (an equal priority keeps the newer); an enemy given its own `Add` at a priority at or above the automatic outline's takes that outline's place. A limb shot off leaves the outline at once. `Outlines.Enabled` is the player's `Outlines / Enabled`; off, nothing is drawn. While one of the game's own screens is open (map, terminal, menu) nothing is drawn.
  - **X-ray is an opt-in, off by default.** Without it an outline is depth tested: behind a wall nothing shows, behind cover only the visible part. `xRay: true` (or `EnemyOutlineStyle.XRay = true`) draws the whole silhouette through walls; use it only where your mod means to show what is behind a wall. Forge Ordnance's exosuit cockpit does not use it: its enemy outline keeps the default style and outlines only enemies the camera sees.
  ```csharp
  var marked = Outlines.Add("MyName.MyMod", enemy, new OutlineColor(1f, 0.85f, 0.2f, 0.9f), priority: 10, seconds: 8f);  // in sight only
  var scan = Outlines.Add("MyName.MyMod", enemy, new OutlineColor(0.3f, 0.8f, 1f, 0.8f), seconds: 3f, xRay: true);       // through walls, on purpose
  ```- **Text and boards.** `WorldText.Create(parent, name, style)` is a hidden block of text that wraps at a fixed width and grows upward from its lower edge (`WorldTextStyle`: size, colour, alignment, pivot, line spacing, `SceneDepth` to be hidden by scenery); `SetShown`, `SetContent(text, lineWidth)` (returns the preferred size), `FaceCamera`, `Destroy`. `WorldBackdrop.TryCreate(parent, name, colour)` is a flat coloured rectangle behind text or an icon, sized with `Place` and recoloured in place with `SetColor`. `SignBoard.TryCreate(face, backdropName, width, height, backdropColour)` is a sign: a face with an optional backdrop and centred text filling it (`ShowText`). `ImageBoard.TryCreate(parent, name, layer, texture, width, height)` is a picture board, and `ImageTextures.TryGet(key, png, width, height, ...)` decodes and caches the PNG by your content hash (`Dispose` frees them). The `TryCreate` calls return null when the game has no `Sprites/Default` shader; you decide when to show and to whom.
- **Ground markers.** `GroundMarker.Place(centre, radius, colour, style)`, or `GroundMarker.PlaceStrip(centre, forward, halfWidth, halfLength, colour, style, chevrons)` for a rectangle drawn and laid the same way (chevrons walk toward `forward`); set `Remaining`, `Urgency`, `PingRate`, `Opacity`, call `Blink()` on a tick, `Move()` to follow a point, `Remove()` when done.
- **Beams.** `Beams.Create(colour, style)`, `Show(from, to)` every frame it moves, `Release()`. `Opacity`, `Width` and `FlareScale` scale the whole beam; `CoreLevel`, `GlowLevel`, `FlareLevel` and `GlowWidthScale` scale one part for a beam whose parts breathe differently; `BeamStyle.FlareLift` raises the flare above its point.
- **Flight.** `Thrown.Arc(from, to, apex, progress)` is a thrown thing's place on an arc between two points (a line plus a parabola peaking `apex` metres above it; one formula with the throw's own parabola), the same on every peer.
- **Trails.** `Trails.Rent(start, style)`, `Move(position, progress)` every frame, `End()`. A `TrailStyle` is a ribbon, an optional head flame and glow (your sheets) and puffs (your sheets or channels). The ribbon is the thing's last positions in world space (`RibbonPoints` x `RibbonStep` seconds long, at most `Trails.MaxRibbonPoints`), so it stays along the path already run and thins behind the thing (`RibbonTaper`: tail width over head width); for a projectile or a dash use the ribbon and puffs and leave `Flame` and `Glow` unset (those two are head sprites, which read as a ball). `End()` lets the ribbon gather into the last point over its own length and then frees the trail; a rented trail starts with every point at its start, so a pooled one never draws a line from its last journey. A trail only follows the position this peer already shows and sends nothing; `Trails.Max` run or fade at once and a rent past it returns null. Do not hold a particle prefab on a flying thing for its tail: a prefab's particles that simulate in local space move with it and read as a ball.

### Supporting types

Public because they appear in the signatures above or another package uses them: `GunGrip`, `GunFrame` and `GunReach` (a grip point or wrist pose of a gun model, the frame a hand target is given in, and what a target is against the arm's reach: `GunHold`, `GunHoldPreset`); `SightKind` and `GunSightFit` (a sight ForgeVisual ships and which one goes on a gun model: `GunSights`); `ImportedModelFailure`, `ImportedSubmesh`, `ImportedMaterial`, `ImportedTexture` and `ImportedBone` (the parts of an imported model and why one is refused: `ImportedModelDescriptor`); `ZoneShape`, `ZoneStyle` and `ZoneLook` (a drawn zone volume's shape, how it is drawn and its colour and strength: `ZoneVolume`); `SpriteFace` (how a sprite quad is turned: `SpriteSpawn`); `AmbientValues` (what `Ambient.Native` reads) and `AmbientLease` (one user's hold on the ambient light); `FirstPersonArms` (a pair of arms in front of the local player's first-person camera that plays clips: the game's first-person view draws no hands) and `FirstPersonWearOptions` (how a model is put on the first-person body); `GlowMode` (which materials a glow lights), `HeldHiding` (the renderers a hold turns off), `OwnBodyOptions` (what the local player's own body shows), `GunPartPoints` (a package's table of part points by model), `GunHoldResult` (where a gun model and the wrists go at rest, in the game gun's frame), `EnemyOutlineTracker` (what the outline knows of each of ForgeCore's enemy slots). Types nothing outside the package needs are `internal`.

### Observation port

The effect, model, beam, trail and decal calls report what they draw to ForgeCore `Recording` (see Recording above) when someone observes, so a recorder can show it again without the mod that made it. Reported: `ModelHandle.Spawn` (and so `Models.Dress`), `Models.HideRenderers` / `ShowRenderers`, `Fx.Play` / `Line` / `Hold` / `Release`, `AttachedFx.Play`, `Beam.Show` / `Hide` (told every frame while shown; the observer keeps only changes), `Trail.Move` / `Stop`, `DecalRing.Place`, and `JointPlayer.Play` / `Stop` on a body from `Models.BindJoints(player or enemy)` for a clip that has a name (`JointClip.Read(file, name)`, a game clip from `CaptureGameClip` is named `game/clipname`; a clip with no name plays but is not reported). `JointClip.Find(name)` returns a clip read under a name in this process, and `JointTrack.Seek(elapsed)` moves a playing clip to a time so a replay can drive it from its own clock. Not reported, by design: `Models.WearFirstPerson` and the effect pool's own copies (`ModelHandle.Make` skips the report). A beam's or trail's style travels as text: `LookText.Write(look)` and `LookText.Read<T>(text)` carry every public read-write property of the style (numbers, flags, enums, colours, vectors, sprite sheets by name, arrays of looks); a property of another kind stays at its default when read back.
### Binding a skeleton

A clip knows no body: it is the canonical rig's turns. Two steps put a motion on a skeleton: offline, the source's bones onto the canonical rig (one tool); in the game, the canonical rig onto the body's bones (`JointPlayer`). Never turn a source's bones straight onto a model's: that second way is what detached garments and tore wrists.

**A new motion**

1. Look at the source's skeleton: `blender --background --python-expr` with the file imported, print each bone's name, parent and head. Note the way it faces and its rest pose (T, A, arms down), and whether it has real finger data (CMU does not).
2. Add one row to the mod's `sources.json`: `id`, `loop`, `body` (the mask it plays under: `full`, `upper`, `left-arm`, `right-arm`), `file`, `skeleton` (`mixamo`, `cmu`, `cmu-amc` with `asf`, `quaternius`, `animmade`, `rigify`, `kaykit`, or `map` with `map` = {canonical joint: source bone}, every body joint named and one bone allowed under several joints), `action` and `range` (seconds) to cut, `faceAt` (seconds; turns the clip to face forward at that moment; mocap faces any way), `mirror` (the other arm does it), `still` (joints held at rest: an arm this gesture does not use). `handShape` (by side, a name in the list's `handShapes`) holds a hand shape over a source with no finger data or fingers that do not read. A motion nobody has is keyed there: `keyed` with bones by direction or wrist place, hands by aim, knuckle row and `shape`, poses that start `from` another, and each key's `ease` (`out` for a snap, `in` for a drop). A shape folds each finger's three segments toward the palm in degrees from straight and places the thumb in the palm's axes. Motion reads when it gathers before it moves, overshoots and settles, drifts while it holds, and lifts before it drops; a first-person clip must not outlast the body clip it goes with, because the arms stop when the body clip ends.
3. `pnpm ts Tools/Models/build-joint-clips.ts --sources <sources.json> --blender <blender.exe> --only <id> --preview <dir>`. It stops with a named error on too much hip travel, too long a clip or a looping clip that does not close. It prints the readings below and writes `<id>.gif` and `<id>-hand.gif`, replayed with the game's algorithm under the mask on a vanilla pose.
4. Look at the pictures, then in the game. A reading never overrules the picture.

**A new skeleton in the game**

Avatar humanoids need nothing. Anything else: `new RigMap().Bone("hip", "Root/Pelvis")...` with at least `RigMap.Required(RigShape.Body)`, and `Models.BindJoints(root, map, label)`. Do not declare a rest pose or bone lengths: they are read from the skinned meshes' bind poses. Null means it did not fit, and the one logged error names the joints: a missing bone, two joints on one bone, a joint not under its parent, a zero-length bone, a leg or the spine more than 60 degrees from the rig's (wrong map or a root that is not upright), sides swapped. Only a skeleton that can stand as a human takes these clips.

**Reading the symptoms** (`--preview` prints these)

| You see | Reading | Cause | Fix |
| --- | --- | --- | --- |
| Gloves, sleeves or boots off the body | `garmentHeadSpreadMm` above about 5 | Each garment posed through its own armature. In a glb a garment keeps only the bones it has weights on, so it hangs bones from a grandparent or starts at a limb, and its chain goes elsewhere | One skeleton, one world pose per bone, every skin takes the same transforms, as the game does |
| Fingers thin, torn or pointing away | `stretch` above about 4, `worstEdge` on a finger | A finger hung from the wrong parent, or a turn from rest carried between hands that rest differently | Parent is the candidate no other candidate hangs below; carry the palm frame over and line each finger's rest direction up first (`placeHands`) |
| Wrist or forearm wrung | `wristTwistDegrees` above about 60 | The whole forearm roll on the wrist joint; mocap (CMU) stores it in the wrist | `forearmTwistShare` moves half into the forearm |
| Forearm or hand inside the vest | `armInBodyMm` well above `armInBodyBaseMm`, `armInBodyAtSecond` says when | The source's actor is thinner than the character | `retargetExternalAction` pushes the arm out of the measured body; a push shows as `armFromSourceDegrees`. Still in: change `character`, cut the moment with `range`, or use a mask without that arm |
| Arm pointing somewhere else than the source | `armFromSourceDegrees` high with no contact | Wrong map or rest direction | Check the map; the source's rest arm direction comes from its own bones |
| Hands across the body on a masked clip | none: the arm is right against the chest, the vanilla chest is turned | A masked track rides on the game's pose (rifle stance turns the chest) | Expected; pick the arm or a full mask if it reads badly |
| Whole body sinks or floats | hip height in the probe | The hip's travel is scaled by leg length; the source's rest legs are bent | Fix the source's rest with `range` or the clip's mask |

Readings of a probe pass 0.03 degrees of bone direction and still look wrong when the fault is in the skin or the source: judge by the picture.

**A skinned copy on another skeleton** (`SkinRebind.Rebind`)

A copied skinned model (an enemy part placed on another enemy) follows the target's bones instead of its own copy of its skeleton. The caller passes the part root, the root its skeleton was authored under, the target model root and a map from each part bone (by pointer) to a target bone; the map is data the caller resolved from content (ForgeEnemy reads `Web/src/forge/enemy/enemy-skin-families.json` pairs through the compiled assembly), never matched by name here. Every pair is checked before anything is written: the part bone's bind pose in its source root and the target bone's bind pose the caller passes (`SkinRebind.BindRest` of the target model as the game ships it: an enemy whose appearance reshaped its own meshes no longer carries those bind poses) must agree within the caller's tolerance, so a stale mapping returns `deform-pose-mismatch:<bone>` instead of a bent mesh. Other refusals: `deform-mesh-missing`, `deform-bindpose-mismatch:<renderer>`, `deform-bone-unmapped:<bone>`, `deform-target-bind-missing:<bone>`, `deform-no-renderer`. The new bind poses are `targetBind⁻¹ · meshToPart`; the mesh copies come from the caller's `meshFor` (build them with `SkinRebind.WithBindposes`, cache per key and destroy them when the world ends). `SkinRebindResult` gives the renderers and bone slots moved and the largest position and basis difference measured. Nothing runs per frame.

### Drawn ahead of first use

`ShaderWarm` (landing steps queued when the library loads: one per frame once the elevator has stopped, or on the first level frames) registers the Forge effect bundle and the shared grenade blast, then draws the marker, particle (additive, alpha) and dome materials once with a temporary camera into a 16 x 16 texture: a shader's GPU programs are made at its first draw, not when the bundle loads. A new shader of the library belongs in that list. The shared decals (`Decals.Shared`) are built in the same step, so the first hit does not make their quads in its own frame. Decals and impacts draw with the particle shader, which is already in the list. The outline shader is warmed on its own, once a mod first uses outlines and the ride or level has started: it makes the screen-sized mask and draws its three passes (fill, fill through walls, composite) once.

### Logging

Logging goes through ForgeCore's `ModLog` and only real failures are written (`ErrorOnce` with a fixed key per kind of failure, `Error`); the outline code reports a failure once per key. Nothing is written for loads, clears or timing.

### Per-frame work

The library's updates run as ForgeCore `Frame.OnUpdate` and `Frame.OnLateUpdate` callbacks; it adds no component to the scene. `SpritePool` and `PointLights` return at once when nothing of theirs is alive.

### Showing the local player their own body

`Models.ShowOwnBody(player, options)` returns an `OwnBodyView`: the third-person body is drawn in the picture and the first-person arms and held item are hidden, until you dispose it. The game keeps the local body's animator object at scale 1.2 (a bot's is at 1); with `HeadAndArms` on, the view sets it to 1 so the player stands as tall as everyone else, and puts it back. `BodyClip.FirstPerson` uses the same class with the view inside the body.
