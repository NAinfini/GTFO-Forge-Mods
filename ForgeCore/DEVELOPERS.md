# ForgeCore developer notes

The plan is `Docs/forge-core/PLAN.md`. Public types are in namespace `ForgeCore`, one static entry per module; everything else is
internal. Calls are main thread unless a member says otherwise.

## Layering: what this package holds and what it does not

ForgeCore holds the base and the vanilla calls: asset-bundle loading, logging, config, object pools, network messages, input leases, local saves, and enemy queries and slowing, damage, explosions, noise, gear swapping and the special-weapon slot, borrowed-gun switching, data blocks and safe landing spots. It only covers how to call; it holds no gameplay numbers and no content. If another mod may need a vanilla call, add it here. It never depends on a higher package.

## Layout

- `Core/` references no game or Unity assembly and is compiled straight into the offline tests: logging, pools, the local store,
  network channels and lobby values (over an internal transport), the special weapon slot rules, the input lease book, the data block ledger, the module patch table and
  `NativeDataBlockTables`, the JSON data block transaction ForgeEngine and the Forge base packages register their content through.
- `Once/` is a second pure assembly (`ForgeCore.Once`) that any package, test or tool may reference or compile in without the game: `OnceReporter`, `PosixPath`, `Fnv`, `Hash`, `StrictJson` and `Png`.
- `Native/` is the game side: the plugin and its frame driver, the GTFO-API transport, lazy patching, and the modules that call the game.
- `tests/Core/` is the offline check program (`dotnet run --project Mods/ForgeCore/tests/Core/ForgeCoreTests.csproj -c Release`).

## Modules

- **Content folders.** `ContentFolders.Find(folderName, errors)` returns the full paths of every directory named `folderName` (case-insensitive) under BepInEx `Paths.PluginPath`, sorted and distinct. The plugins tree is walked once per process into a name index (`ContentFolderIndex`), so a second mod asking does not scan the disk again; folders that could not be listed are added to `errors` on every call. It does not read MTFO.
- **LandingWork.** `LandingWork.Add(owner, name, step)` queues a warm-up that has to wait for the game's picture (a shader drawn once off screen, a large texture made). Once the elevator has stopped (`StopElevatorRide`) or the level runs, one step runs on each frame in the order added, so the warm-ups of ForgeUI, ForgeVisual and any mod never share a frame. A step that throws is reported once and the rest still run.
- **Seeds, solo drop and fingerprints.** `Level.TryCurrentLevel` returns the active expedition (`RundownManager.GetActiveExpeditionData` and `Global.RundownIdToLoad`) and the three generation seeds: from `Builder.BuildSeed`, `Builder.HostIDSeedRandom.Seed` and `Builder.SessionSeedRandom.Seed` once generation began, before that from `RundownManager.ActiveExpedition.Seeds.BuildSeed` and `GetSeeds`. `SoloDrop.Start(level, seeds)` walks the main menu with the game's own calls (`CM_PageIntro.EXT_PressInject`, `CM_PageStart.EXT_PressStart`, from any other menu page first `MainMenuGuiLayer.ChangePage(CMP_RUNDOWN_NEW)`, `SNet.SessionHub.CreateHub(Private)`, `SNet.Slots.SetSlotPermission(Forbidden)`, or `Bot` for the bots asked for, `RundownManager.MasterSelectActiveExpedition`, `RundownManager.TrySetActiveExpedition` with the seeds, `CM_PageLoadout.OnReadyButtonClicked`, `EXT_StartExpedition`; the same flow ForgeEngine's StartupProbe uses), checks the seeds read back from the game before the drop and again against `Builder` when generation starts, and is driven from ForgeCore's frame update. `Level.FingerprintSteps(done)` is the same fingerprint as an enumeration of one native scan per step (about 80 ms each on a large level), for a caller that runs one `MoveNext` per frame; `Level.Fingerprint()` runs it to the end at once. It hashes `Builder.CombinedCheckSum` and `ExpeditionInTierData.GetChecksum()` (the game's own) plus lines for zones, areas (geomorph name, size, gates, enemy spawn points, position in centimetres), and for every `LG_SecurityDoor` and `LG_WeakDoor`, `LG_ComputerTerminal`, `LG_ResourceContainer_Storage`, `LG_PowerGenerator_Core` and `ItemInLevel` (game object name and position in centimetres), each list sorted. Sleeping enemies are left out on purpose: the game spawns them after build done (the first frames of the level), and on R1A1 two runs with identical seeds gave the same enemy types and counts at different positions. `Level.Expeditions()` lists the enabled expeditions of the active rundowns with their official labels; `Level.TryFindLevel` resolves a label such as `R1A1`. `SoloDrop.Start(level)` without seeds lets the game draw its own. `DataBlockHashes.ByType` finds every `GameDataBlockBase<T>` subclass in the interop assemblies, reads `GetAllBlocks()` and hashes each block's text as the game's own `CellJSON.SerializeNoFormatting` writes it with `JSONSettings_GameData` (`NativeDataBlockTables.Serialize`, the inverse of the table loader's `Deserialize`) less the public state fields the game writes into a block while it plays (`NativeDataBlockTables.WithoutRuntimeState`: in `MusicStateDataBlock` the music machine's timer `active`, `nextTrigger` and `timeIsClockRelative` on every timed entry, set by `MUS_Base.ResetTimedData` and `CheckTimedData`), so only what a data block file can say counts; combined in persistent-ID order. `SoloDrop` asks for the drop only when `PlayerManager.IsBotActionAllowed` holds and every lobby bot has its agent (the game's drop gate refuses silently otherwise, and cannot itself be asked: its yes already starts generation); 30 s of waiting, or 5 s in the lobby after asking, ends in `Failed` with the lobby in the log.
- **PlayerStats and CarrySlot.** `PlayerStats.Walk / CarryUnslowed / Jump / NoStamina / NoFlinch` change the local player's walk velocity, carry slowdown, jump, stamina cost and hit flinch; each hook goes on with its first subscriber and every subscriber is asked. `CarrySlot` moves the object of the in-level carry slot between the local player's hands and back: `Track` every frame, `Toggle` on the key, `GiveBack` and `Settle` when the permission ends, `DropIfFallen` while it may be on the back (the game drops only one in hand), `ShowOnBack` for other players, `SetPickupHold` at spawn. The package lifts `GameHooks.WieldedSlotBlocked` and `LocalItemHeld` for its carrier. The object stays in the slot, so the game's leaving capture and checkpoint capture read it unchanged.
- **Compact and ChunkLog.** `Compact` writes into a caller-owned `byte[]` at a caller-owned position: `WriteVar`/`ReadVar` (7 bits per byte, low group first, at most 10 bytes; a run past the end or a tenth byte above 1 throws `FormatException`), `WriteVarSigned` (zig-zag), `WriteDelta`/`ReadDelta`, `Quantize` (saturates out of range and on NaN) / `Dequantize`, `WriteQuaternion` (6 bytes: 2 bits for the largest component, 15 bits for each of the other three over ±1/√2, largest component kept positive, so q and −q give the same bytes; every component within 6e-5). `ChunkLog.Create(stream, formatVersion)` writes a 12-byte start (`FCLG`, container version 2, owner format version, little-endian), then per `Append(type, startMs, endMs, data)` a 28-byte header (`CHNK`, type, flags 0 stored / 1 Brotli, start, end, raw length, stored length, CRC-32 over the first 24 header bytes and the payload) and the payload; `Finish()` adds the index (24 bytes per chunk) and a 20-byte trailer (`FCIX`, index offset, count, CRC-32). Data is Brotli-compressed (quality 5, window 2^22) only when that is smaller. `ChunkLog.Open(stream, expectedFormatVersion)` reads the index when the trailer holds, otherwise scans headers in order and stops at the first chunk that is cut off or fails its checksum (it never skips ahead); `ChunkReader.IsComplete` tells which. Another container or format version throws `ChunkLogFormatException` naming both numbers. Every `Append` flushes the stream. One writer thread; a failed write throws and the writer is abandoned.
- **Net.** ForgeCore is the only caller of GTFO-API's NetworkAPI (`Tools/Forge/core-owned-entries.json`). Every package sends through a
  channel; there are no raw events. A received message dropped as illegal is counted under its refusal code: `Net.Drop(code)`,
  read with `Net.Dropped(code)`; ForgeCore's own codes are `net-body-oversized`, `net-control-overflow`, `net-reliable-overflow`,
  `net-formats-unreadable`, `net-lobby-malformed`, `net-state-size`, `net-state-invalid`, `net-peer-refused`, `net-manifest-malformed`; the log still reports each kind once.
  `Net.Traffic` is what every package sent since the process started, counted in the game transport: messages and payload bytes (GTFO-API's
  event header not included; a send to every player is one message), and the lossy share. Take two readings for a rate; neither side allocates.
  `Net.Open(modId, capacity)` opens the mod's only channel; there is no protocol number to bump. Message events are named `modId/name`.
  `Net.OpenInline(modId)` opens one whose handshake and handlers run at the moment the game delivers a message, in arrival order against the game's own messages, with no queue and no `Pump()`; a handler's exception is logged, not thrown into the game's callback, and a refused player's message is dropped and counted.
  `OnBytes`/`SendBytes` are messages of any length: the fingerprint covers their name and delivery, so what the bytes mean belongs in `Content`. `HoldContent()` says this side does not know its content yet: no player is judged by it or of it until `Content` is set, which asks every player again. `ContentDetail` is sent once per refusal with the format list; `Refused` then waits for the other side's, read with `ContentDetailOf(player)`, and `FormatDiffers(player)` tells a format difference from a content one.
  Every registered message adds its name, delivery and field layout (field names and types in declaration order, nested structs expanded,
  fixed buffers with their length, plus the byte size; lobby values are layout `bytes`) to the channel's format fingerprint
  (`NetChannel.Format`, FNV-1a over that text, same on every machine). The handshake event `ForgeCore/handshake/<modId>` carries that
  fingerprint and a hash of `NetChannel.Content`, so different builds meet and both sides refuse (`PeerState.Refused`, `Refused` event,
  one error each). When the formats differ the two sides exchange their per-message list (`ForgeCore/formats/<modId>`) and the error and
  the refusal reason name the messages that differ: missing there, only there, different field layout, different delivery. Registering a
  message after players answered asks them again. Nothing is computed outside registration and the handshake. Players are listed once a
  second and greeted every 2 s until they answer (at most 5 greetings, then one error saying the mod is missing there). Messages
  wait in a queue until the mod calls `Pump()`; messages from refused players are dropped and counted. How a message travels is fixed where it is
  registered: `On` takes a `NetDelivery` (default `Reliable`) and every send of that name follows it, so every player that sends a message
  registers it too (sending an unregistered name throws). `Reliable` uses `SNet_ChannelType.GameOrderCritical` and is never dropped by the queue (it does not
  count toward `capacity`): requests, answers, checkpoints, state replays. `Lossy` uses `SNet_ChannelType.GameNonCritical` (unreliable, may be lost or
  reordered) for frequent presentation messages; at most `capacity` lossy messages wait, the excess is dropped on arrival and `Pump()` reports the count
  with `ErrorOnce`. A hostile player cannot grow memory through the channel: a lobby value over 64 KiB or a format list over 512 KiB is dropped on arrival,
  and more than 8192 reliable messages waiting for `Pump()` drops the excess (both reported with `ErrorOnce`); a handler must still check the
  indices, enums and counts inside its own message. Handshakes and lobby values are reliable. `Lobby(name)` is a `NetLobbyValue`: each player `Set`s only its own bytes (null for none),
  sent as `[1]+bytes` or `[0]` on the variable-size event `modId/lobby/name` to every other player, again to each player the
  moment their copy answers the handshake (a later joiner, a reconnect, a content change), and dropped for a player who left, was refused
  or belongs to an earlier host or local player; `Changed` fires inside `Pump()`, `VersionOf` lets a reader cache by version.
  `Manifest(name)` is a `NetManifest` on the lobby value `manifest/name`: each player `Set`s its own (content number, content hash) entries (12 bytes each,
  sorted by number; a number listed twice throws), and per other player `Match(player, id)` says `Shared` (same hash, usable), `Mismatched`,
  `OnlyHere`, `OnlyThere` or `Unknown` (no list yet); `Usable` is `Shared`, `Differences(player)` lists what that player lacks, what this peer lacks and what differs.
  `Changed` fires when a list arrives, changes or goes, and for every held list when this peer's own changes. Content that may differ entry by entry goes here,
  not into `Content`, so a mismatch drops only those entries and the channel stays compatible; a malformed list is dropped as `net-manifest-malformed`.
  World epoch and readiness: `Epoch` is the host's world number (zero: no world). A message that carries one implements `INetEpoch` explicitly over its
  existing field (the wire layout does not change) and is registered with `OnEpoch<T>`, which drops a message of another epoch, or any message while the
  epoch is zero, before the handler runs. `EnableReadiness()` adds the message `ForgeCore/ready` (`Epoch`, `Ready`): the mod sets
  `Live` (the world is up and its definitions are loaded) and `Ready` before each `Pump()` and calls `Announce()` about once a second; the host broadcasts,
  a client tells the host. A client adopts a newer epoch only from the current host (an older one, or one from a world it left with `ResetWorld()`, is refused),
  raises `EpochChanged` and answers with its own state; the host records each compatible member's answer. `HostReady(lifetime)` and `PeerReady(player, lifetime)`
  say whether an answer is fresh (seconds on the clock `Net.Tick` runs on). `TryToHost` sends only while there is a host. Ordnance stamps and drops by epoch
  but keeps its own hello (throw numbering) in its session; Energy Lab uses all of it. `FromHost(sender)` is the check on a host-to-client message's sender (true only on a client, when the sender is the host) and `IsPlayer(lookup)` the check before acting for a player (a human the session knows, not a bot); the network does not authenticate senders, so a handler makes these itself.
  Following the world: channel.FollowWorld(ready) (call it with the registrations; it enables readiness) makes the channel start and drop the world, so no mod mints or resets epochs itself. The world is up once Net.WorldReady (in a level, a host, no migration) and the mod's 
eady() hold, and stays up until GameEvents.MasterChanged / MasterMigrated / CheckpointReloaded / LevelEnded; while up, Live follows 
eady() (the mod still sets Ready). The host mints Epoch at start, always above its previous one (the clock, at least previous + 1), and raises EpochChanged; a client's EpochChanged is its adoption. A host change, migration or checkpoint reload drops the world (ResetWorld(), the queue cleared, WorldReset raised) and a host still in a ready world mints a higher epoch at once, so state sent from the same game event is stamped with it; a client refuses the epoch it held before and everything below it, then asks the host (a readiness message of another epoch is answered with the host's own), so it takes the host's next epoch, and also one it had already adopted before its own reload event came. A level end drops it and the world does not restart until the game has left the level once. A mod's handler on the same GameEvents subscribed after FollowWorld runs after the channel's. The world stays one per channel; Net.WorldReady is public for packages that keep their own session (ForgeEngine's WorldEpochSync still does and can later call FollowWorld on a channel and read Epoch).
  Replaying level state to a player who joins mid-level stays with each mod (Ordnance keeps it per call, `OrdnanceApi.SendState`).
- **InputLease.** A blocked action passes while `FocusStateManager.CurrentState` is `MainMenu`, `Map` or `GlobalPopupMessage`, because the menu cursor (`CM_PageBase.UpdateCursorPosition`) reads the look axes. Wraps the four public `InputMapper` delegates while any lease blocks or steers, and puts them back when none
  does; a wrapper left in place because another mod wrapped over it forwards everything. `Down`/`Held`/`Axis` read the game's own
  answer. Released automatically at `LevelAPI.OnLevelCleanup` and at `GameEvents.LocalPlayerDown` (subscribed with the first lease); nothing is read per frame.
- **Enemies.** `AimPoint(enemy)` is where a shot or blast looks at an enemy (its aim target, else a metre above its feet) and `NearVisible(position, radius)` is `Near` kept to the enemies whose aim point the position can see (`Level.HasSight`, no wall between). `Near` uses `Physics.OverlapSphereNonAlloc` on `MASK_ENEMY_DAMAGABLE` and doubles its buffer until the query is not
  full; collider owners are cached by instance ID and dropped by prefixes on `EnemyAgent.Setup` and `EnemyAgent.OnDead` (patched the
  first time `Near` runs) and at level cleanup. `Nearest` is `Near` sorted by distance and cut to a limit. `Alert` maps `AgentMode.Hibernate` to Sleeping, `Agressive` to Hunting, the rest to Awake; a dead enemy, one without an AI and `AgentMode.Off` are `Off`.
  `Live` is the registry of every living enemy in the level: slot index = position in the span, vacant slots are null, a slot keeps its
  enemy while it lives and `Generation(slot)` goes up each time the slot is vacated. The first read patches `EnemyAgent.Setup` (postfix
  registers) and `OnDead`, `OnDeSpawn` and `OnDestroy` (prefixes unregister: an enemy that leaves without a death is dropped when the game
  removes it, not by a scan on read), and registers the `EnemyAgent`s already in the scene once. `Version` changes whenever a slot is taken
  or left; level cleanup empties the registry.
- **FactoryEvents.** `FactoryEvents.OnBuildStart(handler)`, `OnBuildDone(handler)` and `OnBatchDone(handler)` (`Native/FactoryEvents.cs`) are `LG_Factory`'s own `OnFactoryBuildStart`, `OnFactoryBuildDone` and `OnFactoryBatchDone` delegates for any number of subscribers: the one native delegate goes on with the first subscriber and hands the call on at the same moment, in subscription order, and each subscription returns an `IDisposable`. They are not GTFO-API's `LevelAPI.OnFactoryStart` / `OnFactoryDone`, which are postfixes of `LG_Factory.OnStart` and `FactoryDone`; a subscriber that needs either moment picks it. Packages do not add to the three delegates themselves (`core-owned-entries.json`).
- **GameEvents.** `StateChanged` is raised after the game changed state, from GTFO-API's `EventAPI.OnGameStateChanged` (a postfix of `GameStateManager.DoChangeState`), for a cache a scene owns. The game's discrete state changes as events, so no mod reads them per frame: `MasterChanged` with `Master` (the host's
  lookup, 0 without a session; read once at `SNet_Events.OnMasterChanged`, `OnResetSessionEvent`, `OnPlayerJoin` and `OnPlayerLeave` and
  raised only when it changed), `LanguageChanged` with `LanguageRevision` (raised after `GameDataTextLocalizationService.SetCurrentLanguage`;
  a reader caching text compares the revision), `LevelEnded` (`LevelAPI.OnLevelCleanup`), `CheckpointReloaded`
  (`EventAPI.OnCheckpointReloaded`) `LocalPlayerDown` (`Dam_PlayerDamageLocal.ReceiveSetDead`), `LobbyChanged` with `InLobby` (GTFO-API `EventAPI.OnGameStateChanged`; the state is read once at
  start and kept from the events) and `ExpeditionSelected` (rundown id, tier, index; after `RundownManager.MasterSelectActiveExpedition` on the host and after `RundownManager.SetActiveExpedition` on a client). The language,
  player-down and expedition patches go on the first time something subscribes or reads the revision. A handler that throws is one `ErrorOnce` line and the others still run.
- **Players.** `Players.Motion(agent)` and `MotionChanged` read the players' locomotion states; `Players.Face(agent, point)` turns the local player's view level toward a point (a teammate, for a two-player action) and does nothing for a remote agent.
- **Checkpoint.** The recall barrier. After a checkpoint reload the game puts the backpack, ammunition and players back over several frames, so anything a mod writes earlier is overwritten. `Checkpoint.Recalling` is true while the game is reloading a checkpoint or its capture is recalling replicated state; `Checkpoint.Settled` is true once no reload is in progress and a frame has passed since `CheckpointReloaded`. A mod restoring its own part of the state waits on `Settled` and writes once; a mod that must refuse stale input during a reload reads `Recalling`. Nobody patches `CheckpointManager.OnStateChange` or `SNet_SyncManager.OnRecallDone` for this. Each mod keeps its own state snapshot (what it saves at `CheckpointReached` and puts back at `CheckpointReloaded`): the data and the messages that carry it to the other players differ per mod, so there is no shared snapshot registry. Main thread only.
- **ColliderQuery.** `new ColliderQuery(capacity)` owns one `Il2CppReferenceArray<Collider>`; `Sphere(position, radius, mask, triggers)` runs `Physics.OverlapSphereNonAlloc` into it, returns the count and clears what a longer earlier query left behind. The game cannot tell a buffer filled exactly from one that overflowed, so `Truncated` is true whenever `Count == Capacity`: the colliders are the first ones found and the caller must refuse or query again with a larger capacity (it never reads as complete). `new ColliderQuery(capacity, grow: true)` does that repeat itself: a full buffer is replaced by one twice as large and the query repeated until the result is below the capacity, so the result is always complete and `Truncated` is never true (the capacity stays grown; use it where the count is unbounded and a refusal is not an option). `Clear()` releases the last result. `Count` and the indexer are valid until the next `Sphere` on the same instance; keep one instance per call site so results survive other queries. Layers (`LayerManager.MASK_*`) and `QueryTriggerInteraction` are the caller's; dedupe, ordering and receiver selection stay with the caller. Energy Lab uses it for its contact, flame, gravity, arc and explosion queries. For living enemies use `Enemies.Near`.
- **StaticColliders.** `Node(parent, name, layer, position, rotation, scale)` makes a GameObject on a TagManager layer (`Layer(name)` throws `static-collider-layer-missing` for an unknown name); give it one collider with `Box`, `Sphere`, `Capsule` or `MeshCollider` (all non-trigger). The navigation build takes active, non-trigger box and mesh colliders on `Navigable(layer)` layers (`LayerManager.MASK_UNITY_NAVMESH_GENERATION`) as walkable sources, so nodes parented into a level before its navigation build carry voxel nodes (read back in game; the player build has no static flag to set). `Mesh(name, positions, indices)` builds a collision mesh (UInt32 indices above 65535 vertices; throws `static-collider-mesh-invalid` for incomplete or out-of-range geometry); `ColliderMesh(node, name, vertices)` returns the mesh of a vanilla MeshCollider only when name and vertex count match (a Unity built-in mesh is not handed back by name in the player build, so callers carry it as geometry).
- **Slow.** `Enemies.Slow(agent, factor, owner)` returns a `SlowLease` (dispose to end) and scales `EnemyAgent.Anim.speed` (the game moves enemies by animator root motion; the foam state stops them the same way). The bookkeeping is `SlowBook` (pure): the enemy's own speed is kept, leases on one enemy take the slowest factor and never compound, and when the speed read is not the one applied the game changed it and that value becomes the own speed (`lease.Refresh()` re-applies after that). The last lease ending, or `EnemyAgent.Setup` / `OnDead` (the same prefixes as the registry), puts the own speed back unless the game has set another meanwhile. Every write is read back; a mismatch is an `ErrorOnce` line and `ReadBack` is false. An enemy without a live animator gets an inactive lease and an error line. Callers skip enemies the game holds itself (foam) before asking. `Enemies.SlowZone(centre, radius, factor, seconds, owner[, admit])` is that call made for every enemy inside a sphere (and passing `admit`, for example not behind a wall) and returns a `SlowZoneLease` (`Dispose` ends it; it also ends at `Time.time + seconds` and at level cleanup). It is a list of zones, each with one `Slow` lease per enemy inside, run by `CoreDriver.Update` through `Enemies.TickZones(Time.time)` at most every 0.1 s: a pass takes `Near(centre, radius)`, skips an enemy without a live animator and one the game holds in foam (`Locomotion.CurrentStateEnum == ES_StateEnum.StuckInGlue`, the foam owns its speed until it wears off; the enemy is slowed on the first pass after it is let go), takes a lease for a new enemy, refreshes one it holds, takes a fresh lease for one the game ended (died, reused: `Setup` and `OnDead` already put its speed back) and ends the lease of an enemy that is no longer inside. `Slowed` is the number of different enemies slowed with a write that read back over the zone's life and `Mismatches` the writes that did not read back (the lease's `ReadBack`, one `ErrorOnce` line per kind), so a caller can log what really happened. A radius or time of 0 or less, or a negative factor, is refused with `ArgumentOutOfRangeException`. Zones are per peer: call it on every peer that should see the enemies slowed.
- **Level.** `CourseNodeAt(position, sample, out node, out dimension, preferredDimension)` asks `AIG_CourseNode.TryGetCourseNode` for the
  preferred dimension, then for the level's other dimensions in index order, and takes the first live (not collected) node; false with dimension -1 when none.
  Only dimensions the built level has are asked: they are read once from `Builder.CurrentFloor.m_dimensions` at build done and cleared at cleanup (the game logs an error with a stack trace for each index it lacks).
  Zones as level events name them: `HasDimension(dimension)` (that same list), `TryZone(dimension, layer, localIndex, out zone)`
  (`Builder.CurrentFloor.TryGetZoneByLocalIndex`), `AreaCount(zone)` and `TryAreaCentre(zone, index, out centre)` (the area's course node position, in
  the zone's own `m_areas` order). Main thread, after the level is built.
  `TryActiveExpedition(out rundownId, out tier, out index)` reads the active expedition (`Global.RundownIdToLoad`, `RundownManager.GetActiveExpeditionData`); false when the game cannot say.
  `FindStandSpot(origin, yaw, clearance, preferBehind, out spot, out tried)` tries `StandSpots.Count` (7) places in a fixed order (straight behind, the back diagonals, the sides, further behind, the front; mirrored when `preferBehind` is false), each `clearance` times its factor away: a place passes when `NavMesh.SamplePosition` (0.6 m) finds ground within 1.2 m of the origin's height, the floor ray (`MASK_WORLD`) finds the floor, a 0.3 m capsule from 0.45 to 1.45 m touches no world geometry and no world geometry lies on the line from 1 m above the origin to 1 m above the place. When none passes the result is false, `spot` is the origin and `tried` is the count. The order is pure (`StandSpots.Offset`); nothing is allocated.
  `TrySnap(position, reach, out snapped)` is the nearest walkable ground on the navigation mesh within `reach` (`NavMesh.SamplePosition`, every area; false and the position itself when there is none). It is the only caller of `NavMesh.SamplePosition` in the repository (`core-owned-entries.json`): other packages call `TrySnap`, they never sample the mesh themselves. `TryRoute(from, to, maxLength, corners, out count)` snaps both ends onto the navigation mesh (`NavMesh.SamplePosition`, 2 m, every area), asks `NavMesh.CalculatePath` (the surface the enemies walk on, closed doors included) and accepts only `PathComplete`; it writes every corner after the start into `corners` (a `Span<Vector3>`) and their number to `count`, and refuses, with a count of 0, a path longer than `maxLength` (summed over the corner segments), one with more corners than `corners` holds (never cut short) and one that fills the game's 64-corner buffer (it may be truncated). `HasSight(floorPoint, aim)` is false when `Physics.Linecast` against `LayerManager.MASK_WORLD` (triggers ignored) meets the level between a point 2 m above `floorPoint` (a ray 0.1 m above the floor finds a lower ceiling; the line then starts 0.15 m under it, never below 0.2 m above the floor) and `aim`. `Blocked(from, to)` is that linecast between the two floor points lifted 1 m. The path object and corner buffer are reused: nothing is allocated per call.
- **Il2CppArrays.** `ToManaged` / `ToGame` copy the array memory (after the four-pointer header) in one go; `Upload` writes RGBA32 pixels with
  `Texture2D.LoadRawTextureData` (the caller applies the texture).
- **PlayerHits.** The one patch on the game's player hit path. `Redirect(owner, (receiver, damage, source) => damage)` changes the damage of a hit before anything reads it (0 = none; redirects run in registration order); `GateInfection(owner, (receiver, data) => allow)` skips an infection write; `WriteAuthoredInfection(damage, data, sync, updatePageMap)` writes infection for authored content and a gate reads `AuthoredInfection` to tell that write from the game's own sources (enemies, fog); `Observe` / `ObserveInfection` register the one reader of hits and infection writes (`IPlayerHitObserver.Before/After/Faulted` with a `HitState` value carried between them, `IInfectionObserver.Before/After`); a second owner is refused, null removes a registration. `Watch(owner, (receiver, damage, source) => ...)` only reads a hit, with the damage the game will apply, and any number of owners may. A callback that throws is one `ErrorOnce` line and the game body still runs. ForgePlayer reads, Frames redirects and gates.

One consequence of dividing the distance: the game's inside-1 m instant wake becomes 1 x multiplier m.

Every method takes the object's own path prefix (empty at the root, `"Shield."` inside `Shield`) and names the field as prefix + name in a `StrictJsonException`. `OnlyKnown(value, prefix, known, alsoAllowed, owner)` refuses a non-object, a member in neither list (the message lists `known`) and a member written twice. `Number` and `Integer` (`min`..`max`, bounds included; a whole number for `Integer`), `Bool`, `Enum<T>` (exact member name, no number), `Reference` (a persistentID or a block name) and `Object` read one member; a missing member returns the fallback, or is "required" when there is none; a wrong type or a value outside its range is refused, never clamped. `Canonical` writes members sorted by name with every number in one spelling (coefficient and exponent, no rounding) and strings escaped by the default serializer, so equal content is equal text; ForgeOrdnance hashes it into its definition set hash.
- **Fnv.** `Hash32` and `Hash64` over UTF-8 text or bytes; `Mix32` and `Mix64` feed one byte for callers that hash a record; `Mix32(h, uint | int | ulong)` and `Mix64(h, ulong | long)` feed an integer as its little-endian bytes and `MixUtf8(h, text)` feeds the UTF-8 bytes of a string without allocating (equal to `Hash32` / `Hash64` of the text from the offset basis, a lone surrogate being U+FFFD). The algorithm is part of wire formats and saved keys (`Net` fingerprints, ForgeOrdnance payload and look keys, ForgeAudio network names, EnergyLab gear IDs, the Frames spec key), so its output never changes; the tests lock the published vectors.
- **Session.** `Session.IsHost` is the game's `SNet.IsMaster` read from two numbers ForgeCore keeps current (`GameEvents.Master`, `Session.LocalLookup`, both set from the game's `OnMasterChanged`, session-reset and join/leave events and from `SNet_SyncManager.OnFoundMaster`, `GameHooks.MasterFound`, which is the only one after a lone host's session found its host), so asking costs no game call; at a host migration it flips together with `GameEvents.MasterChanged`, and a `MasterChanged` handler already reads the new value. `HostLookup` and `LocalLookup` give the two lookups; everything is 0 / false with no session. Packages use it instead of reading `SNet.IsMaster`; `SoloDrop` still reads the game's own value because it runs while the session is being created.
- **Players (roster and warp).** `Players.WorldCamera()` is the camera the picture comes from (the game's current camera while active, so a dead player watching a teammate or a scripted shot is followed; else the local first-person camera; else `Camera.main`): effects, sound and HUD placement read the view from it, never from the local player's body. `Players.Local` / `LocalAlive` are the local agent (null when empty, collected, or dead for `LocalAlive`). `Players.Each(visit)` and `Players.Each(state, visit)` walk the level's live player agents as `PlayerInfo { Agent, Lookup, Slot, IsLocal, IsBot, Name }` (`Name` is read from the game only when asked for); with a static lambda nothing is allocated. `Players.Joined` / `Left` raise a `SessionPlayer { Lookup, IsBot, IsLocal }` when the session lists or drops a player (its agent may not exist yet). `Players.Warp(agent, dimension, position, forward, mode)` calls the game's own entry and reads the position back: `WarpMode.Synced` is the host's `RequestWarpToSync` (replicated, any live agent in one of its `m_warpableStates`), `WarpMode.Local` is `TeleportTo` for this machine's own agent (not replicated, same dimension, camera turned to `forward`). A wrong side, a dead or unwarpable agent, a dimension mismatch or no agent is refused by name before the game is called (`WarpRefusal`, rules in `WarpGate.Check`); `WarpResult.Landed` is true only when the agent reads within `WarpTolerance` (0.5 m) of the request, so an accepted warp that did not land is reported as such. The caller brings a landing from `PlayerAgent.SampleWarpPosition`.
- **Store.WriteText.** `Store.WriteText(path, text)` writes any text file atomically (UTF-8 without a byte order mark, a temporary file beside it, then a replace; the folder is created; an `IOException` family exception is the caller's to handle). `Store.Write<T>` uses it.
- **Active expedition.** `Level.TryActiveExpedition` gives the numbers; `Level.ActiveKey` the game's key string (a new string per read, so compare the numbers first and read the key when they change). A package that needs to know when the choice changes subscribes to `GameEvents.ExpeditionSelected` instead of polling.
- **Png.** Pure (`Once/`). `Png.TrySize(bytes, out width, out height)` reads the PNG signature and the IHDR size and is false for anything else. Check it before handing bytes to a decoder, which allocates whatever the header claims; ForgeVisual's `ImageTextures` and ForgeMap's image admission do.
- **Assets.Keep.** `Assets.Keep(asset)` sets `HideFlags.DontUnloadUnusedAsset` on an object a mod holds only in managed code (a texture, mesh, material, pooled root or a loaded bundle asset) and returns it; the game's unused-asset sweep at scene changes cannot see such references. `Assets.Load`, `LoadBytes` and `Get` already keep what they return. `Assets.LoadAsync(modId, path, expectedSha256)` loads a bundle over several frames: it checks the file's hash first, and you poll `BundleLoad.IsDone` then read `Bundle` (null, one error logged, when it failed). The bundle is not shared or kept; the caller owns it and may `Unload` it.
- **Log, Settings, Pool, Store, Assets** as listed in `README.md`. Logging writes errors only: `Error` and `ErrorOnce` (an exact message is written the first time it occurs and never again; a different message from the same place is written too) reach the mod's BepInEx log source, and nothing else is written (`Log.Num(value)` and `Log.Pos(x, y, z)` / `Log.Pos(Vector3)` format a number with at most two decimals and a position with two, always with a dot). A failed feature, or data or configuration that leaves something unusable, is an error; progress, state changes and recoverable conditions are not logged. There is no debug mode or log switch and no `Info` or `Warning`. An error that carries an exception writes the whole exception (`error.ToString()`), not its `Message`. A state a player or the game can legitimately be in (a player without the mod, an enemy that has just left) is not logged.

While an enemy is held, the launches its attack states make on the host (`EAB_ProjectileShooter.FireBurst`, `EAB_MovingEnemeyTentacle.Attack`, `EAB_MovingEnemyTentacleMultiple.Attack`) are skipped (module `Puppets.AttackHold`); the attack's voice and timers still run. `PlayerPuppet` puts a downed player back into `PLOC_Downed` when the game left it (at most twice a second, counted in `Reentered`, not logged). `CameraLease.Look` looks the view's room up itself: `Dimension.TryGetCourseNodeFromPos` at the view, then at the floor under it (a 40 m ray on `LayerManager.MASK_WORLD`), then at the given point, else the last room; again when the view or the point moved 1 m and every 0.25 s; `SetCurrentNode` and the agent's `m_position` and `lastCrossCheckPos` every frame. Not `UpdatePosition` and `RefreshNode`: the first does nothing while the agent has no room and checks portal crossings from its last place, so a view that jumped got a room along that line or kept a far one. `PlayerPuppet.MeleeSwing(charged)` and `MeleeCharge()` are the remote-player entry `MeleeWeaponThirdPerson.ReceiveClassItemSync` (its animation and swing sound). `PlayerPuppet.Say` is `PlayerVoice.SayLine`; `WorldStates.ZoneLights(modes, instant)` is `EnvironmentStateManager.UpdateAllLightModes`. `PlayerPuppet.State` also takes `OnTerminal`, `GrabbedByTank` and `ClimbLadder` (`PlayerSync.IncomingClimbLadder` with the nearest player ladder). `Puppets.Enemy(enemy, owner)` holds an enemy as a puppet (`EnemyPuppet`): `AI.Mode = Off`, `AI.SetNavMeshAgent(false)`, the `NavMeshAgent` component and `Anim.applyRootMotion` off, `Dam_EnemyDamageBase.IsImortal` on (the damage limbs stay, it can still be aimed at), `ForceNoAnimationCulling` on, and `Locomotion.ChangeState(StandStill)` so the animator leaves the hibernation pose. `Attack`, `Hitreact` and `Scream` put the enemy in the game's own state for that action and set `Acting`; the puppet re-asserts its control right after entering the state (root motion stays on while the action plays) and again when the action ends and the enemy is sent back to walking, so these state changes are not counted as the game taking the enemy back. `Drive(position, rotation, velocity, seconds)` (call it in `Frame.OnLateUpdate`) sets the transform and writes the game's own animator inputs `EnemyLocomotion.s_hashMoveOnGround`, `s_hashForward`, `s_hashRight` (the world velocity in the enemy's frame, `PuppetMotion.Local`; smoothed with the locomotion's `MoveAnimDampTime`). ### Recording (observation port: `Core/Observers.cs`, `Native/Recording.cs`)

ForgeVisual and ForgeAudio report every effect, line, held effect, beam, trail, decal, model and sound they put in the world to `Recording`, at the point every call of their kind passes. Any number of observers hear them: `Recording.Observe(IShownObserver)` returns an `IDisposable` that removes it; observers are called in the order added, on the main thread, inside the library call, and must not throw (one that does is logged once and stays) and should not allocate.

- While nobody observes a report site costs one field read (`Recording.Watched`); the library builds no struct, looks nothing up, allocates nothing.
- Names are `RecordingNames.Of(name)` integers, taken once when a library makes its handle and never changing in the process; 0 is no name. An observer turns them into its own table (an array, not a dictionary).
- `ShownEffect` (kind, name, hold key, at, to, size, colour, head, seconds, fade, look object), `ShownSound` (name, place, at, picked variant and pitch, gain, self, loop number), `ShownModel` (spawned, hidden, shown), `ShownPose` (start or stop, anchor, track, clip name number, seconds in, loop, weight, fade in and out, per-joint mask weights valid during the call; `Recording.Pose`), `Recording.Anchor(Transform)` (player agent, enemy agent or world, and the node when it is not the root).
- Poses: ForgeVisual's `JointPlayer` reports every clip that has a name (`JointClip.Parse(json, name)`) on a body bound with `Models.BindJoints(player or enemy)`; a clip without a name, a first-person arms clip and a body that hangs on no player or enemy are not reported. A mod that poses a body some other way calls `Recording.Pose` itself. Only the name, the start and the play options travel, so the observer needs no bones and a replay finds the clip by `JointClip.Find(name)`. A pose copied from the game's body every frame (`PoseCopy`) is derived from what the replay already animates and is not reported.
- Notes: `Recording.Note(modId, kind, payload = "", mark = false)` writes a note of a mod's own into the recording being made, so a mod needs no reference to the recorder (ForgeReplay stores it as event 101 and offers it back as `ReplayEvents.OnNote`, on the replay timeline when `mark` is set, and in the exported statistics `notes`). `modId` and `kind` are required; a recorder cuts them to 200 and the payload to 1024 UTF-8 bytes. `Recording.ObserveNotes(Action<RecordingNote>)` is the recorder's side and returns an `IDisposable`; a listener that throws is logged once and stays. Every machine records what its own mods note, host and client alike; nothing happens while no recorder listens.
- `Observers<T>` is the general many-observer list (copy-on-change array, `Any`); use it for any further report of this kind instead of a single callback field.

## Quick start

Depend on `NAinfini-ForgeCore-1.0.0` in `manifest.json`, reference `ForgeCore.dll`, and add `[BepInDependency("NAinfini.ForgeCore")]`.
Every call takes your plugin GUID as the mod ID.

```csharp
using ForgeCore;

[BepInPlugin(Id, "My Mod", "1.0.0")]
[BepInDependency("NAinfini.ForgeCore")]
internal sealed class Plugin : BasePlugin
{
    internal const string Id = "me.mymod";
    private static NetChannel _net = null!;

    public override void Load()
    {
        _net = Net.Open(Id);                            // a player whose messages differ is refused on both sides, with a log line naming them
        _net.On<Ping>("ping", (sender, ping) => Handle(sender, ping.Value));
    }

    // From your own Update: run the received handlers, then send.
    internal static void Tick() { _net.Pump(); _net.Broadcast("ping", new Ping { Value = 1 }); }
}

[StructLayout(LayoutKind.Sequential, Pack = 1)] internal struct Ping { public int Value; }
```
